## 通用验收标准

1. 每个批次有明确问题、接口/权限/数据契约、迁移边界与验收记录；缺数据使用真实空态，不用静态假数据。
2. 子代理只用 `gpt-6.1-sol`，在独立 worktree/分支开发、测试、提交；主代理审查改动和证据，完成集成检查后合并。
3. 执行 `scripts/go.sh build ./...`、`scripts/go.sh vet ./...`；通过 `scripts/test-all.sh` 强制独立 PG18 `_test` 数据库全量回归。涉及并发、资金或 worker 的改动追加有效的 race/冲突测试；跳过项不计通过。
4. 前端通过 `npm run typecheck --prefix web`、`npm run lint --prefix web`、隔离目录 `npm run build --prefix web`。不覆盖常驻 Next 进程使用的构建，不复制多套依赖或大量历史备份。
5. 相关页面在 1440、1024、390、320 四尺寸验证：真实 API、页面布局、无 JS 异常、预期权限拒绝/409、加载/空/错误恢复、保存/取消、URL 恢复；危险操作验证确认、幂等、版本与审计。业务拒绝是预期结果时单列，不能当作无 API 错误。
6. 外部成功必须有可信商户/供应商/终端证据。未知结果冻结核对，不以本地过期代替关单，不重复发送资金/资源写请求，不把人工转账叫原路退款。
7. 用户现有授权内继续执行；新增真实扣款、真实资源破坏、生产切流或停旧站，先完成可审查材料再按具体动作取得授权。额度不足/缺资源等外部条件标记待验收，独立完成其余可执行工作。
8. 每批提交代码与去敏验收文档，排除 `.env`、密钥、业务库、构建/扫描产物。推送和部署根据用户具体指令执行。全部范围及验收关闭后才将总体目标标记完成。
