# G09 魔方供应商协议接收器增量

本增量提供有限、真实 socket 的供应商测试接收器。不是外部上游验收、真实虚拟机、worker 实测或容量结果；不访问 PG、不构建候选、不部署。

`internal/g09fixture/supplier.go` 的 `NewSupplierSink` 实现当前编译注册表中 `zjmf_finance_v1` 适配器实际使用的登录、商品目录/详情、账户币种、清购物车、添加、结算、账单回读、余额付款、资源详情及兼容资源回读协议。固定一个月付商品7、价格100分、资源到期时间1795000000；不提供升级、续费、动作、删除或真正的虚拟机。生产二进制不得导入此包。

调用方必须预先冻结独立本地服务/上游主机/账单ID，三类各自唯一，最多512个资源；未知资源不能创建或读取。请求预算包含拒绝和登录请求，最大8192次；超过预算、共享journal失效或写盘失败后持续拒绝。配置中的资源切片及逐服务回调token映射都不保留可变引用，凭据不参与JSON序列化。每个本地服务绑定其自己的32字节token；测试对齐生产侧`svc-<id>`默认主机名，不使用共享token或空主机名掩盖实际worker协议。Downstream URL限制为显式IPv4 loopback的HTTP origin，不产生任何回调请求。接收器拒绝非127.0.0.1来源；调用方仍须把HTTP服务绑定127.0.0.1临时端口并配置请求超时，它本身不是namespace隔离器。

所有成功协议响应都先调用已有journal的写入及fsync，再提交内存状态和发送响应。journal只保存固定操作名、序号、时间、本地ID哈希及规范响应事实哈希；登录的证据不包含JWT，只散列认证成功事实。它是协议接纳记录，不是完整请求、客户端收到响应或磁盘恢复后的供应商状态。资源状态仅内存保存，本工具不模拟接收器重启恢复；新run必须创建新journal，不复用旧成功记录。

清购物车对已结算的同一本地身份返回已有主机/账单，适配器在此合同下不再次结算/付款。原始重复settle/pay各自记录一次协议接纳，资源仍为同一个预分配身份；不可将布尔paid状态当成通用上游扣款exactly-once证明。这只覆盖当前适配器支持的existing-ID合同，不意味着任意真实魔方站点支持幂等，也不允许生产worker重发状态未知的开通。

## 实测范围

`scripts/go.sh test -race ./internal/g09fixture -count=1 -timeout=3m -v` 使用真实编译注册表创建适配器，通过本机HTTP socket访问接收器，覆盖：

- 目录、详情、创建、资源同步、两个独立本地身份、全新适配器及登录下的同身份重放；两次实际settle/pay，与两个资源逐实体对应。
- 八个并发原始settle请求得到一个资源；九条协议接纳记录包含一次add及八次settle，不将请求数折叠成一个。
- 错凭据、错token、未知ID、产品或下游token不匹配、重复表单键及请求预算拒绝，拒绝不变成成功journal。
- journal关闭后结算不成功、不创建资源，后续仍拒绝；独立重读0600落盘journal，逐条核对内存快照、序号、时间、去敏及支付响应hash。
- 真实socket在已落盘结算或付款后断开：结算明确返回`settlement_unknown`，只在fixture里以完全相同身份人工重放；付款由生产适配器主动回读账单确认。两例均只有一个settle和一个pay；不测试生产worker未知冻结流程。

最初协议回归日志及退出结果在 `evidence/g09-supplier-sink-20261017/`；逐服务token/默认主机名修正后的最终回归在该目录的`resource-bound/`子目录，两个源码摘要分别保留。专项不包含PG、生产候选API、真实worker或600任务，不替代主线全量或最终G09验收。
