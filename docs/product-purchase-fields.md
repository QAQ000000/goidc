# 原生产品购买字段

schema063 增加普通购买资料，旧 PHP 自定义字段仅作业务参考，不提取旧数据。

管理员在商品详情“购买字段”维护最多20个字段：文本、长文本、下拉、勾选、HTTP/HTTPS网址；支持启停、必填、说明、排序、最大字符数、完整匹配的RE2规则和账单展示开关。字段标识为小写字母开头的40字符以内字母/数字/下划线，下拉需1–50个唯一选项。字符数按Unicode字符计算，服务端最多2048；网址禁止账户信息且不发起网络请求。RE2不支持PHP正则的回溯、反向引用等语法。敏感扩展支持 `scope=purchase|admin|customer`。`encrypted=true` 的值使用 `PURCHASE_FIELD_ENCRYPTION_KEY` AES-GCM 加密后进入购物车/订单快照；未配置密钥时拒绝保存定义。管理员字段不进入客户购买请求，客户资料字段使用 `customer_profile_key` 标识资料项并不允许账单展示。订单、服务和账单接口默认以 `********` 掩码敏感值，原始密文只保留在数据库快照中，接口不返回解密值。

`PUT /api/v1/admin/products/{id}/purchase-fields` 接收 `expected_revision` 和完整 `fields` 数组，复用 `products.manage`，要求同时有读取能力。定义替换、商品版本和审计原子提交；陈旧版本409，读取角色写入403。公开商品 `purchase_field_definitions` 只含启用定义，后台包含全部定义；商品复制携带定义，不复制购买值及历史。

购物车新增/修改接收 `purchase_fields` 字符串映射。例如 `{"hostname":"web-01","region":"上海","accepted":"true"}`。值去除两端空白，勾选以 `"true"` 保存；必填勾选必须选中。省略PATCH字段保留原值，显式 `{}` 清空并重新检查必填。相同商品、账期和配置但资料不同会成为独立购物车行，修改为已有变体409。无购买资料时保留既有变体标识。

加入、编辑、优惠码报价及结算在目录共享锁内重验定义；读取购物车使用单一可重复读快照。无效资料在购物车返回 `fields_valid=false` 与 `fields_error`，不能结算；客户可重新打开编辑器修正。未知或停用字段拒绝提交，必填/正则/选项/长度变化也需重新确认，服务端校验是最终依据。

结算在同一事务保存订单项目 `purchase_fields` 数组，包含购买时的标识、名称、类型、值和账单展示标志。客户和有客户范围权限的管理员订单/服务详情读取此不可变快照；服务配置、账期及跨商品变更仍引用原购买资料。修改/删除商品定义不会修改已购资料。订单账单详情仅返回快照中 `show_invoice=true` 的字段，不从当前定义重算。后续续费/变更账单不复制原购买资料。页面以转义文本展示，网址不自动生成可点击链接。

专项测试覆盖资料校验、变体、幂等、权限、历史快照、账单隐私、商品复制、陈旧版本、并发和审计回滚。浏览器及发布验收证据保存在 `output/purchase-fields-20261006/`；最终部署与测试结论见重构台账。

发布恢复须保留schema062续费权益保护，并在已有字段定义、购物车资料或订单快照时拒绝退回063之前的API，避免旧API忽略必填校验和购买资料。
