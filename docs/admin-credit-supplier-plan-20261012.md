# 信用业务与供应商后台下一批契约

本轮从旧规范第15、90、92、93、94页继续，信用和供应商分别作为完整业务域验收。三个独立分支从1ff3017派生，提交后由主分支审查合入；运行环境保持原版本，新增迁移先在隔离PG18验证。

## 信用支付、还款与冻结

授信金额和预存余额分开。客户用授信支付真实账单后，账单进入已付状态，执行现有订单开通/续费等结算和通知链路，同时新增独立信用消费债务记录、增加占用额度，不扣余额。必须同时满足全局信用开关开启、客户账户未冻结、额度足够、账单版本和归属正确；充值与未接入信用结算的账单类型拒绝，不允许信用支付绕过待核验的真实在线支付。

后台信用页按“消费记录 / 还款记录 / 客户列表”组织，金额使用整数分、元输入和显示；消费记录支持账单/客户/日期/状态检索。还款先实现管理员线下到账确认，需填写真实收款凭证和说明，并在界面说明该动作登记已到账款项；写入独立还款记录，只减少对应消费的未还金额和账户占用，不伪造支付网关回调。线上还款后续通过同一债务与还款模型扩展。

冻结只阻止新增信用消费，允许登记还款。未还款信用消费退款走原账单取消/库存与服务撤销保护，并冲减信用债务，不增加余额。已经发生线下还款的信用消费暂拒绝普通退款，后续接入线下退付对账，不记录“已退款”却没有资金来源的假结果。

消费、还款、冻结和额度调整均需权限、有效会话、客户范围、版本冲突、幂等和事务内审计。请求结果未知时保留请求体与幂等键并锁定修改，离开/刷新后可恢复原请求。

## 供应商订单、续费与任务

订单页独立显示供应商服务对应的真实本地订单和付款状态；用交付快照确定供应商归属，客户范围限定在后端SQL。多供应商订单按订单语义去重，未知成本不填0或推算利润。已有订单创建、取消、核验、删除等操作复用对应业务API和权限，不能把本地记录变更包装为已调用上游。

续费页展示真实本地供应商服务续费记录和可证明的成本信息。当前适配器不支持的上游续费不添加假按钮或生成虚假成功结果；无记录时返回真实空列表。

两个旧任务队列路由继续映射稳定的 `/admin/suppliers/jobs` 和 `/admin/suppliers/tasks`，使用统一真实供应商任务查询。任务内容仅投影安全字段，不返回请求载荷、密码、令牌或供应商凭据。重试只对已确认可安全重试的失败任务开放；结果未知任务必须核验，运行中、租约失效、任务版本变化以及跨客户操作拒绝。页内明确来源和语义，不能生成两套互不一致的假队列。

所有列表返回items/total/limit/offset，筛选和分页可通过URL恢复，详情保留返回上下文。读写权限分开校验，受限管理员不能通过隐藏按钮以外的方式绕过后端。

## 验收范围

隔离PG18验证迁移重跑、权限/范围、并发及幂等、资金方向和事务失败回滚；完成Go全量和专项race、vet、前端typecheck/lint/独立生产构建。浏览器四宽度覆盖信用三标签、客户信用支付、还款登记、冻结拒绝以及供应商四列表的真实数据/空态/筛选和安全重试。外部真实商户、供应商写操作和线下资金到账真实性不属于隔离测试证据。
