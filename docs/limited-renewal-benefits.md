# 固定金额与限次续费优惠

schema064扩展原生循环权益，百分比和固定金额均支持 `recurring:true`；免初装费不支持循环。新增 `recurring_limit` 为每个服务的优惠续费次数，0为不限，最大10000。首次购买不占续费次数。原百分比权益保持不限次数，历史服务不从当前优惠码补发任何新权益。旧PHP仅作为业务参考，不提取旧数据。

首次购买继续沿用优惠码的购物车计算：固定金额对符合范围的所选购物车总额减免一次；循环权益则给每件符合范围的月/季/年服务分别保存固定金额或比例、次数上限与代码。例：购买两件、每件周期价1234分，固定500分码首次对订单减500分；此后每个服务每期续费各减500分，实付734分。一次性商品没有续费权益。规则的范围、状态、有效期、首次使用及新老客户等只在购买时检查。

`services.recurring_price_cents` 是当前周期原价，`renewal_fixed_discount_cents` 是购买时固定减免，`renewal_discount_percent` 是百分比，两者互斥；`renewal_discount_limit` 是上限，`renewal_discounts_used` 是已结算的优惠续费次数。服务列表/详情的 `renewal_amount_cents` 由当前原价与权益计算，固定优惠最多减至零元。次数用完后按原价续费，仍保留历史权益信息。

创建续费账单保存原价、实际减免、固定金额/百分比、代码、上限和 `renewal_discount_ordinal`（第几次优惠），不消耗次数。付款事务锁定服务并重查序号与保存规则，将优惠计数递增、到期延长、余额/网关结算和审计一并提交。余额不足、内部失败或重复付款不多扣次数；零元及百分比取整为零的成功优惠续费仍消耗一次。已有未付续费单继续阻止新单。

手动、自动余额续费及支付回调使用同一结算逻辑。停用、过期、修改优惠码或发码额度耗尽不撤回已购权益。优惠码核销仍只算首次订单，不因续费增加发码次数。配置、商品与账期变更保留原金额/比例、上限和已使用次数；变更差额和降配返还按原价计算，不享受续费减免。

余额退款只返原账单实际付款金额，沿用既有服务到期扣回规则；**已用优惠次数不恢复**，后续账单按剩余次数判断。页面在限次权益中明确说明。原路退款仍受支付渠道契约限制，不能用余额退款替代。

新增字段沿用已有端点和 `promos.view/manage`，没有新增路由/权限。后台创建表单分别说明“发码次数”和“优惠续费次数”；订单显示购入权益，服务显示已用/剩余与优惠后金额，账单显示该次序号和实际优惠。后台只读管理员不能创建，写接口继续403。

升级迁移把旧已付款/已退款百分比续费单计入已用次数，为旧待付款单保存下一序号，不改变其金额和不限次数规则。旧已付款账单没有新序号时保留0作为历史默认值，不篡改已有金融快照。新增SQL价格函数与Go计算在整数极值、零元、固定与限次场景核对一致。

退回063旧API会忽略固定及次数权益。发布恢复须拒绝已有循环固定码/限次码、已发权益或相关续费快照时直接降级。数据库/旧二进制/环境和实际前端构建备份及独立恢复演练结果见 [重构台账](reconstruction.md)，本批证据位于 `output/limited-renewal-20261006/`。真实商户及供应商仍未验收。
