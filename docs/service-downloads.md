新 API 路径：

| 方法/路径 | 行为 |
| --- | --- |
| GET /api/v1/services/{id}/downloads | 本人服务关联文件，q 搜索名称/说明、limit/offset 分页，返回 enabled/items/total/limit/offset |
| GET /api/v1/services/{id}/downloads/{download_id}/file | 验证本人服务与文件产品关联后，复用公共下载的即时鉴权与字节/外部地址响应 |

服务不存在或不属于当前账户均 404；未登录/失效凭据 401。超级管理员走客户路径也只能读取本人服务，不能借管理员身份扩大客户下载权限。后台服务详情没有客户产品资料面板，管理员仍按独立 downloads.view/manage 维护文件。

列表仅返回公开目录字段、can_download，不返回存储字节、远程地址、作者或后台版本。隐藏文件/分类不列出，直接下载同样 404。关闭下载设置返回 enabled=false、空列表和总数0，但先检查服务归属，不能通过关闭状态绕过客户隔离；下载为403。站点维护继续保护客户路径。

访问条件完全沿用 [下载中心](download-center.md)：公开文件不要求服务状态；登录文件需有效身份；指定产品文件须当前账户拥有任意一个关联产品的 active 且非待迁移复核服务。上下文服务可以暂停或待支付，但用户另一个关联有效服务仍满足中央规则。无资格的资料显示锁定提示，点击时服务端再次拒绝，与公共中心一致；这是对旧列表直接移除受限文件的明确调整。关联只控制出现位置，公开文件取消关联后仍可在公共中心下载。

下载目录锁将隐藏、替换、删除、设置和文件关联变更排序。获取本人服务的共享行锁后再次核对会话/密钥，以覆盖目录锁和服务行锁等待期间的撤销或所有权变更。成功 GET 计数、HEAD 不计数且无字节、替换使用响应实际名称，外部链接只返回地址、不发服务端抓取请求；这与原公共下载端点共享实现。
