# 支付单过期与商户轮换验收

本批修复放弃支付导致商户配置长期无法修改的问题，并关闭模拟支付默认值。新交易保存不可变、绑定付款号的 AES-GCM 原商户快照，历史交易在轮换前补齐；迟到回调和查单使用原凭据。新交易的流水身份包含网关摘要，旧交易保留既有身份。

## 业务边界

- 仅未过期的 pending 易支付单、活动查单租约阻止地址、PID、密钥变更。
- worker 将超时单标记 expired 并安排再次查单；查到已付款才结算。
- status=0 不能证明上游关单，因此 expired 仍阻止账单再次付款、余额支付、编辑、作废、合并及订单取消。
- 凭据快照只在服务端解密，不进入 API、日志或前端；主加密密钥必须保留。
- 未结算旧单快照不存在且原商户凭据丢失时轮换拒绝；成功/失败终态历史单写入加密不可用标记，允许新商户配置而不误用新凭据。
- schema086 只关闭未配置记录的模拟默认值，已主动保存的选择保留。

## 验证

隔离 PG18 测试覆盖有效期内拒绝轮换、超时后在 worker 运行前允许轮换、过期任务幂等、未付款不结算、过期账单资金及编辑/合并/作废保护、新旧商户分离、迟到查询/回调只结算一次、伪造签名拒绝、旧单快照补齐、活动租约保护、密文不可替换、旧流水重复回放、不同网关相同 PID/流水均能结算。加密单测验证付款号 AAD、跨加密域与密文篡改拒绝。

账单详情使用当前事务读取配置与快照；MaxConns=1 的客户和管理员完整 HTTP 请求可完成，防止详情请求耗尽连接池后互相等待。额外测试验证旧成功/失败单原凭据遗失可配置新商户、不可用标记不被后续轮换复活、未结算旧单遗失凭据仍拒绝轮换。

Playwright 浏览器隔离夹具完成管理员登录、查看过期付款、主动查单、未付款提示和注销；核对 API 的账单 unpaid、支付 expired 及 real_payment_pending。桌面及390px截图位于 `output/playwright/payment-expiry-desktop.png`、`payment-expiry-390.png`，付款表格局部滚动。本次仅使用本地协议夹具，没有真实付款、邮件投递或供应商写操作。
