## API 与权限

后台商品详情 `/admin/products/{id}` 的“可配置选项”页签提供组/选项创建、编辑、启停、排序和删除。读取通过现有商品详情，要求 products.view；修改同时要求 products.view/manage，等待目录锁后重新检查当前账号/角色权限。只读管理员可打开禁用表单，无提交或删除按钮。

| API | 行为 |
| --- | --- |
| `POST /api/v1/admin/products/{id}/option-groups` | 创建，兼容原带 options 数组接口；也可先创建可选空组 |
| `PUT/DELETE /api/v1/admin/products/{id}/option-groups/{group_id}` | 编辑组元数据或删除 |
| `POST /api/v1/admin/products/{id}/option-groups/{group_id}/options` | 添加选项 |
| `PUT/DELETE /api/v1/admin/products/{id}/option-groups/{group_id}/options/{option_id}` | 编辑或删除选项 |
| `PUT /api/v1/admin/products/{id}/option-groups/{group_id}/options/{option_id}/price-tiers` | 单账期替换阶梯，兼容原接口 |

选项创建/编辑可附带 `price_tier_changes`，键为账期，值为该账期的完整阶梯数组。只替换明确提交的账期，空数组清除此账期；未提交的账期保持原值。元数据、所有账期、商品版本和审计在同一事务提交，版本只推进一次；任何无效区间或审计失败均整体回滚。最多九个账期，每账期 100 段，选项请求体上限 256 KiB。组创建时内联 options 不接受阶梯变更，应先创建组再维护选项。

后台阶梯使用字符串草稿，保存时才将金额转为整数分。切换账期保留输入与未保存状态，单次“保存选项”提交所有变更账期；关闭和重新加载会确认放弃修改，接受重新加载时即使商品版本未变也重置草稿。只读管理员可切换账期查看，不能修改或保存。目录和购物车配置编辑器共用 `productOptionAmounts`，按当前账期的启用阶梯逐段累计，区间未覆盖时不允许提交；价格矩阵停用时不参与预览。下单金额仍由 Go 在事务中重新计算。

组字段 name/slug/required/active/sort_order/option_type/qty_minimum/qty_maximum/qty_stage/unit/expected_revision，选项 label/value/price_delta_cents/setup_delta_cents/qty_minimum/qty_maximum/active/sort_order/expected_revision。数量型 option_type 使用旧系统 4、7、9、11、14–19；加购和结算要求 option_quantities 映射，校验范围和步长并按数量乘算价格。所有编辑/删除和新增选项要求最新商品 expected_revision；原新增组兼容不传版本，界面始终传版本。新建组 options 数组最多 100，编辑组不接受非空 options；单独接口维护稳定选项 ID。每商品最多 100 组，每组最多 100 项，名称和值最长 120 字符，控制字符拒绝，排序 0–1000000，组标识以小写字母开头。增减价格为整数分，范围 ±100000000；所有当前账期使用同一增减额，配置后的周期价和初装费分别不得为负数。

类型 1 用下拉框，类型 2 用单选按钮；两者每组最多提交一个真实选项 ID，必选组须选择，可选组可不选择。类型 3 是单个可选勾选附加项：未勾选不提交该组 ID，勾选提交唯一启用选项的 ID。活跃类型 3 组必须为可选且恰好有一个启用选项；后台可先创建停用的空组，添加选项后启用。编辑和删除也执行该规则；旧数据若出现多个启用选项，购物车、报价和结算返回 `unsupported_product_configuration`，不会代选第一个。目录、购物车编辑、服务配置变更及商品升级共用这套选择语义，价格矩阵和历史快照沿用原选项 ID。

修改在 CatalogTx 中获得管理员共享锁、目录互斥锁及商品行锁，再检查版本/归属。变更推进商品 revision，与审计原子提交。启用的必选组必须有启用选项；不允许停用/删除最后一个启用项，可先停用组。购物车或任何历史订单引用选项时禁止物理删除（含删除整组的级联），返回 409 configuration_in_use，允许停用。过时版本返回 409 version_conflict。商品下架并不限制管理员维护配置。

公开商品仅返回启用组及启用选项，包括空的必选组以阻止无有效配置购买；后台仍返回全部。数据库验证检查必选、重复、同组多选、跨商品和停用项。购物车/结算持有目录共享锁，管理修改不会穿过其事务中间。购物车的 current/active/options_valid 标记旧版本和失效选项；数量型配置显示范围/步长输入并随 option_quantities 保存，删除保留，配置编辑按商品 ID 加载最新公共详情并允许重新确认或改选。隐藏/下架商品的详情不可读取时仍可删除购物车项。

## 金额与历史快照

结算原代码在逐项计算时修改了 Go range 的副本，订单总额含增价但写入项目的周期/初装金额丢失增价。本批保留逐项计算结果并统一 OptionAmounts 校验；购物车单价、小计、优惠码、订单项和续费依据均包含对应配置增减。初装费免除优惠使用含配置的初装金额。修改配置后旧购物车需重新确认，已成功订单幂等重放保持原结果。

迁移 038 新增 order_items.config_snapshot，迁移 050 新增 cart_items/order_items.option_quantities：新订单保存配置/组 ID、当时名称/组标识/值、周期、数量及初装增减额。原 config_options ID 数组保留，后台详情显示历史快照，商品配置改名、改值、改价不会更改订单。旧订单无法从当前配置反推下单时名称/增价，因此迁移保留空快照，不编造或修正历史金额；后台对只有 ID 的旧记录显示历史编号提示。已有部署库零带配置的订单，不存在需修复的该类金额记录。

schema 048 增加旧配置迁移层：旧配置容器和商品关联进入 `legacy_product_config_groups` / `legacy_product_config_links`，旧配置类型成为商品配置组，子选项成为选项；数量范围、步长、单位、隐藏、升级、原始值和服务历史选择均保留。`product_option_prices` 保存九种旧账期价格及初装费，购物车、促销和结算按选择的当前账期取矩阵价格，没有矩阵时回退到管理员配置的增减价。schema 049 另将旧 `shd_product_config_options_links` 保存到 `legacy_product_config_option_links`，包括关系类型、条件/结果引用、上游 ID 和原始字段。当前结算链对可映射的离散子项等于/不等于条件和数量组闭区间条件执行服务端求值；同一条件的所有结果都必须满足，区间多个条目按并集匹配，条件/结果来源或旧子项引用不一致、数量非整数、区间无效返回 `unsupported_product_configuration`，结果不满足返回 `configuration_dependency`。schema 050 接入数量输入、计价和历史快照；schema 052 将旧数量组的多个区间子项折叠为一个 Go 数量选项，以 `legacy_product_config_option_aliases` 保留每个旧子项映射，并将各子项九种账期价格写入 `product_option_price_tiers`。共享配置、升级折扣和上游同步仍属于后续业务批次，旧商品导入后继续下架等待复核。

## 数量请求

`POST /api/v1/cart/items` 和 `PATCH /api/v1/cart/items/{id}` 使用选项 ID 作为 `option_quantities` 的 JSON 键，例如：

```json
{
  "version": 3,
  "product_id": 1,
  "quantity": 1,
  "billing_cycle": "monthly",
  "option_ids": [12],
  "option_quantities": {"12": 4}
}
```

项目 `quantity` 是购买服务件数；`option_quantities` 是每件服务的配置数量，两者独立。数量型选项必须显式提供整数数量，范围为 1–1000000。选项范围非零时覆盖组范围；选项范围为零时继承组范围，最大值都为零时使用全局上限。正步长按有效最小值为起点校验，步长为零时不额外限制整数；最小值为零且步长为 2 时，首个有效正数为 2。旧联动区间是闭区间，多个旧子项区间按并集判断；区间条件只读取当前配置组数量，不读取某个旧子项 ID 的价格段。当前不支持零单位配置；旧数量阶梯价格通过独立阶梯表按账期保存，并在购物车、优惠码报价和结算中按闭区间逐段累计，后台可批量替换阶梯。

固定价选项可省略数量，或显式提供 1；其他倍数返回 `invalid_product_option_quantity`，防止负增价被任意放大。数量映射中出现未选中的选项也会拒绝。PATCH 省略 `option_ids` 时保留已有选择和数量；显式传入空数组和空映射可清空可选配置。前端重新打开编辑器会从当前购物车初始化数量，改选后只提交当前选项的数量。

## 多级选择

旧 `option_type=20` 的层级读取 schema048 已保存的 `legacy_metadata.linkage_pid`：配置组字段引用旧父配置组，选项字段引用旧父选项。引用只在同商品、同旧来源内解析；`linkage_level` 和 `linkage_top_pid` 是旧缓存，不作为购买规则。普通和数量类型的残留层级缓存不参与多级求值，数量阶梯别名也不会成为父选项。

公开和管理目录增加组字段 `parent_group_id`、选项字段 `parent_option_id`，两者为新系统 ID，无父级时为 0。目录与购物车编辑器先解析父级再显示可选分支，支持组排序与层级顺序不一致；父选择改变后清除全部旧下级选择，必选组默认选择当前分支的首个启用选项。当可选根未选、父级停用或所选父选项没有启用下级时，后续分支不要求选择。

购物车读写、优惠码报价和结算复用后端校验。选中下级但未选父选项或选中其他分支返回 `configuration_dependency`；遗漏当前分支可选的必选组返回 `required_product_options`。全图校验不依赖当前是否选择选项，缺失/跨商品/跨来源父引用、父选项归属错误、循环及非整数引用返回 `unsupported_product_configuration`。已有购物车在关系变化后标记 `options_valid=false`，不能通过优惠码或结算绕过。

schema053 新增组 `parent_group_id` 和选项 `parent_option_id` 的自引用外键及 `hierarchy_native` 标记。升级后的既有记录保持旧解析器，后续新建配置默认使用原生 ID。原生标记为 true 时，NULL/0 表示明确清除父级，旧归档中的 `linkage_pid` 不会重新生效。

组写入支持 `parent_group_id`，选项写入支持 `parent_option_id`；省略或传 null 保留已有关系，0 清除。组编辑可同时提交 `option_parents` 映射，将当前组的每个选项 ID 对应到新父组选项 ID；先创建可选空子组再逐个添加选项也可行。组重新挂接、选项映射、全图验证、版本推进及审计在同一事务提交，部分映射无法形成有效图时整体回滚。父子组必须同商品且为 type20，父选项必须属于声明的父组；循环、跨商品、错组、缺父拒绝。仍被下级引用的组/选项不能删除。

后台“多级选择”类型提供父组和父选项选择，自身与下级不能作为候选父组；变更父组后清空原归属，要求重新指定。只读账号控件禁用且无保存/删除入口。商品复制解析当前整图，将组与选项父 ID 映射到新副本，并移除旧身份，副本不再引用源商品。含高级条件/结果联动表记录的商品暂返回 `unsupported_product_duplicate`，防止复制时丢弃业务规则；这与已支持的多级父子选择不同。
