# 商品升级优惠

schema065 已部署到当前开发实例，为跨商品升级提供专用优惠码，Go API、客户商品升级表单、后台优惠码页面和账单详情使用同一合同。旧 PHP 仅作为业务参考，本批不提取旧数据。

## 规则

- `upgrade_only=true` 的码只能用于 `POST /api/v1/services/{id}/product-quotes` 的正数本期差额；普通购物车拒绝该码。配置变更、账期变更、续费、降级返还不应用升级优惠。
- 支持百分比与固定金额（分），百分比向下取整，固定金额以差额为上限，可得到零元账单。升级后周期原价不变，升级优惠不形成续费权益，也不收取目标商品初装费。
- 复用启用状态、生效/结束时间、目标商品、原服务账期、最大次数、全局一次、每客户一次、新老客户和必需商品限制。新老客户沿用已有订单数判断，因此已有购买订单的服务所有者属于老客户。
- 只报价、生成未付账单、取消或支付失败均不核销。成功余额/网关结算进入升级队列时，在同一数据库事务中锁定优惠码、重新校验、增加次数并写唯一核销记录。并发限次仅允许符合剩余次数的付款成功；幂等重放不重复核销。
- 提交和付款重新检查折扣。规则、状态、有效期或次数已变化时拒绝结算，客户需要取消未付变更后重新报价。账单中原差额、实际优惠和优惠码保持不可变。
- 付款后交付失败保留核销，可重试交付；退款不恢复次数。只读管理员无法创建或停用优惠码，客户只能访问本人的服务及账单。

## API 与存储

后台 `POST /api/v1/admin/promo-codes` 接受 `upgrade_only`，复用 `promos.manage`；列表返回该标志。`recurring=true` 或免初装费与升级专用标志冲突，返回409。停用/启用沿用 `PATCH /admin/promo-codes/{id}`。

商品报价在既有请求中增加可选 `promo_code`，响应与变更详情返回 `upgrade_base_cents`、`upgrade_discount_cents`、`upgrade_promo_code`。无优惠码时三个值分别为0、0和空字符串。生成账单与付款沿用既有配置变更、余额和支付渠道 API。

`service_configuration_changes` 保存报价快照，`invoice_items` 保存账单快照；数据库约束限定带优惠的变更必须是商品变更，账单应付必须等于原差额减优惠。`promo_upgrade_redemptions.change_id` 唯一，引用优惠码、客户、变更和实际优惠。购物车购买核销与商品升级核销分别存储。
