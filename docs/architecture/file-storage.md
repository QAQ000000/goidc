# 应用文件存储契约

状态：当前实现契约；部署与真实对象服务单独验收。适用下载中心上传文件、客户文件、工单附件、文章图片和电子发票；NOKVM 磁盘、快照、备份仍属于远端资源领域。通用装配规则见[编译模块架构](../compiled-module-architecture.md)。

## 业务与存储边界

业务表保留文件名称、类型、大小、归属、权限、版本、下载次数和审计。文件内容使用旧 `content bytea` 或新的 `storage_object_id`，两者互斥。下载中心 `source_type=local` 仍表示系统内上传文件，可以位于数据库、目录或 S3；`remote` 仍表示外部 URL，授权后返回既有 JSON `{url}`，不能作为私有对象存储标记。

`internal/filestorage` 提供编译注册的 `local` 和 `s3` 实现。数据库字节是兼容路径，不通过外部适配器读取。适配器只负责不可变对象的 Put、Open、Delete；不能判断客户是否有权下载，也不能修改业务记录。新增实现必须提供声明、纯本地配置校验、位置指纹和协议回归，不从数据库加载可执行代码。

## 部署配置与固定位置

API 和 worker 使用相同的 `FILE_STORAGE_DEFAULT` 与 `FILE_STORAGE_PROFILES`。未配置时默认 `database`，保留既有写入行为；切换默认只影响新上传或明确替换的文件，不搬迁历史内容。

本地目录示例（目录由部署人员预先创建并仅授权应用账户）：

```text
FILE_STORAGE_DEFAULT=primary
FILE_STORAGE_PROFILES=[{"id":"primary","implementation":"local","config":{"root":"/srv/goidc-files"}}]
```

S3 兼容协议示例：

```text
FILE_STORAGE_DEFAULT=objects
FILE_STORAGE_PROFILES=[{"id":"objects","implementation":"s3","config":{"endpoint":"https://storage.example.com","region":"auto","bucket":"goidc-private","prefix":"files"},"secrets":{"access_key":"REPLACE_ME","secret_key":"REPLACE_ME"}}]
```

示例是配置格式，不是已存在的部署资源或可用凭据。配置仅存在于服务环境或受控密钥存储；不在上传请求或后台表单接收服务器目录。构造和模块清单不联网、不创建目录。应用目录展示部署管理状态，不把存储模块配置按钮指向商品管理。

每个对象固定 profile ID、实现位置指纹、随机对象键、业务类型、大小和 SHA-256。路径、endpoint、bucket、prefix 等位置变化会导致指纹不匹配并拒绝读取或清理，不能通过复用 ID 重定向历史文件；新位置必须使用新 profile ID。凭据可轮换，但需继续访问原位置。切换默认后保留所有仍有对象的旧 profile，API 和 worker 必须一致。

本地对象键由宿主产生，不使用用户文件名构造路径；目录隔离、符号链接与普通文件检查阻止路径逃逸。S3 bucket 保持私有，使用 path-style、SigV4、固定超时、禁用环境代理与重定向，不自动重发 Put。公开下载地址和预签名链接不属于本批范围。

## 写入、提交与回收

外部对象 Put 前，独立 journal 连接池持久登记唯一意图，再持久确认 `uncertain` 围栏，只有确认成功才发送 Put；业务事务的连接占满时不能阻塞 journal 自身。对象键不复用、不覆盖。上传成功后才能在业务事务中绑定文件，绑定与原有审计一起提交。写入失败、进程退出、审计回滚或提交结果未知时，记录持续可追踪，不能在请求结束时直接删除对象。

数据库触发器保护五类业务引用与对象的类型、大小、SHA 和生命周期一致性。文件替换、下载改外链、显式删除以及工单/回复/内部备注、文章、发票申请的级联删除，在同一事务登记旧对象释放。只改元信息、转移客户归属、合并工单不释放仍被引用的对象；正文不再引用某张图，也不擅自删除其图片记录。

worker 在独立循环中执行延迟回收，不阻塞通知或账单扫描。清理前锁定对象、核对全部业务引用并进入不可再绑定的删除状态；删除失败保留可重试记录。已解除引用的对象至少保留一小时，未绑定的正常意图至少保留一天。Put 结果未知或上传中进程退出单独保留 `uncertain` 待核验状态，自动回收不领取，也不重放写入。此状态目前需人工检查原存储与 journal，尚无后台一键修复入口。对象配置缺失或位置不匹配时停止清理，不使用当前默认后端猜测原位置。

数据库提交错误不证明业务未提交。回收依据持久引用，不依据 HTTP 成功状态或请求内变量。删除操作幂等；进程崩溃后的删除租约和完成 CAS 必须围栏旧执行者。

## 读取与权限

文件下载沿用原有业务 URL、身份、角色、客户范围、产品服务资格、发布状态和审计检查。每次按文件自身绑定读取；有对象引用但配置不可用时明确失败，不能回退到其他文件或旧字节。

首批保持现有大小上限：附件 10 MiB、下载与客户文件 50 MiB、文章图片 5 MiB、电子发票 20 MiB。外部内容在事务中的对象共享锁保护下按大小上限读取，并完整校验长度与 SHA；等待存储后重新验证凭据或业务可见性。校验、授权、计数和审计提交完成后才发送字节。

底层接口支持可 seek 的读取句柄，但当前 HTTP 路径仍使用有界整文件缓冲。下载中心、客户文件、电子发票保留 ETag、HEAD、条件请求、If-Range 和受限多段 Range；工单附件和文章图片保留原状态码与 attachment/inline 行为。S3 ETag 不替代应用 SHA。直接流式响应、超大文件和高并发容量需独立设计与验收。

## 升级、备份与验证

迁移 167 仅增加对象引用、journal 和一致性规则，不改写历史字节。旧下载/客户/工单导入继续直接写数据库，并保留原指纹与重放检查。全量迁移历史文件需单独工具、逐文件核验、可恢复切换和备份演练，本批不自动执行。

数据库备份只包含元数据和旧 inline 文件；启用外部存储后必须同时备份对应目录或对象桶，并记录数据库与对象的一致恢复窗口。恢复不能只换默认存储配置。新增外部引用后，旧运行程序不识别该格式，回退须使用兼容程序或经过验证的数据库与对象备份。

验证必须覆盖本地原子写/逃逸、S3 签名与私有协议、未知写结果、五类真实上传下载、权限撤销、Range、审计失败、级联删除、回收并发围栏、独立 journal 池和真实 schema166 升级。模拟对象服务及隔离 PG18 属于 E1；浏览器为 E2，真实 S3/MinIO/R2 为 E3，生产切换为 E4，分别记录。

执行入口：`node scripts/test-file-storage.mjs --unit` 与 `--integration`。集成 runner 要求独立回环 PG18 `_test` 数据库，逐入口核对 Go JSON 的 run/pass，缺失、失败或任何 skip 均阻断。结果、源文件哈希和日志放在忽略目录 `output/file-storage/`；这些本地证据不替代远端 CI。
