# 请求追踪与 worker 运行诊断

状态：当前生效。此契约定义诊断来源、真实执行进展与就绪边界；诊断读取不执行恢复、重试、支付或供应商操作。

## 请求关联编号

- API 最外层为每次请求生成 128 位随机编号，以 `X-Request-ID` 响应头返回。客户端传入的同名头不会成为权威编号；CSRF、鉴权、维护模式、404 和 panic 同样经过此入口。
- 错误 JSON 的 `error.correlation_id` 与响应头一致。前端 API、上传及业务文件下载保留编号；服务端错误消息显示错误编号，其余统一错误区域另行显示，便于工单定位。无编号的旧响应仍兼容。
- `correlation_id` 与业务 `request_id`、幂等键及资源 ID 分开。它不授予权限，不参与收费、去重或退款决策，也不是完整的分布式追踪协议。
- 请求完成、通用错误和异常日志附带编号、方法及匹配后的路由模板，不记录 query、body、cookie、授权头、实际回调密钥路径和 panic 原文。已写响应后出现异常时中断响应流，不能再伪装成完整 JSON 错误。
- 管理 API 日志保存该字段，原管理员日志权限和数据范围不变；页面可按完整编号筛选，`q` 也支持检索。未认证/鉴权拒绝仍有进程日志，不产生冒充管理员的业务日志。

## 持久化与异步处理

迁移 177 为业务审计、API 日志、调度记录、服务任务、邮件/短信 outbox、通知事件/投递及认证任务增加独立可空字段。先增空列再设置默认表达式，不回填历史来源，不更改原 payload 中的业务字段。

`Store.Open` 安装连接池租借钩子：每次租借显式设置当前上下文编号，缺失时置空；归还时使用独立有界上下文清空，失败则销毁连接。事务保留取得连接时的来源，直接 Pool 调用及现存 HTTP 事务也受覆盖。自建 Pool 的测试/工具须调用 `store.ConfigurePoolCorrelation`，或使用 `Store.Open`；该配置只安装一次，复制配置会继承。

这会增加每次连接租借的设置、清理 SQL 往返；本机小查询测试只作开销观察，不能替代部署网络的容量验证。租借期间不得将同一事务换成另一个请求的来源。诊断设置失败时不能把带旧来源的连接交给新请求。

连接须直连 PostgreSQL 或经过保持会话归属的代理；事务模式的连接代理无法保证设置语句与业务语句落到同一服务端会话，不能直接沿用此实现。

通知投递从其事件继承来源，晚执行、重启和人工重试均不覆盖原编号。worker 领取任务后恢复持久来源，再执行后续审计和入队。每次尝试另以队列、任务 ID、尝试次数或尝试编号区分；历史空来源仅为当前执行生成编号，不能据此声称历史请求已恢复。定时执行使用新的本轮编号，七类循环之间、相邻任务之间不共享来源。

## 就绪与运行状态

| 入口 | 含义 | 权限与响应 |
| --- | --- | --- |
| `/healthz` | API 进程可响应 | 公共，最小状态 |
| `/readyz` | API 已通过启动配置/schema 检查，当前数据库可达 | 公共，不依赖 worker |
| `/api/v1/admin/runtime` | worker 执行进展和队列只读快照 | 仅超级管理员，读取成功返回 200，`status` 为 `ok` 或 `degraded`；读取失败为错误响应 |

发布控制器先等待 API ready，再启动 worker；将 worker 状态塞进 `/readyz` 会形成冷启动互等。运行状态在后台“任务状态概览”独立加载、刷新及报错，监控调用方须检查业务 `status`，不能只看 HTTP 200。

迁移 178 记录随机进程实例及七类循环：服务/邮件/短信串行处理、支付查单、文件回收、分钟通知调度、自动续费、统一通知、实名认证。每个真实循环记录轮询/开始/完成，长批次只从实际执行线程在处理工作单元之间更新进展；没有另起保活协程掩盖卡死。进程所有循环退出后才记录停止。诊断写入有界，失败记录日志，不重跑或授权业务操作。

- 新实例有 120 秒启动宽限。闲置循环超过 `max(3 × 轮询间隔, 30 秒)` 没有进展视为 stale；执行中的无进展阈值由目录声明，为 120–600 秒，响应同时公开具体值。这些是运维阈值，不是外部操作的业务期限。
- 每类循环至少一个实例仍有有效进展即可；其他实例的停止、过期或卡住证据继续展示。全部停止、缺少循环或超过阈值会降级。
- 队列分列可执行待办与未来待办、最久可执行等待、运行数及过期租约；最久等待超过 300 秒告警。这里的可执行指到达领取候选阶段，实际资格仍在领取/派发时检查。
- 最近 1 小时的失败、未知及邮件/短信死信引起降级；长期历史死信不永久阻断运行状态。计数是窗口内仍处于对应状态的记录数，不是完整事件速率。
- 诊断使用数据库时间和只读一致快照，不探测外部渠道，不把未知结果改回待执行。实例证据保留七天，新进程登记时清理过期记录；仍在报告真实进展的长驻实例继续保留。

## 验证与发布

```bash
node scripts/test-runtime-observability.mjs --unit
node scripts/test-runtime-observability.mjs --integration
node --test scripts/runtime-observability-components.test.mjs scripts/proxy-headers.test.mjs
```

严格集成入口要求回环 PG18 `_test` 数据库，逐个核对指定测试 run/pass，缺失、失败或 skip 均阻断。覆盖并发及取消后连接复用、异步重启/重试来源、历史迁移、只读队列窗口、启动宽限、卡住循环、多个实例和权限，以及 worker 不存在时 API 仍 ready。组件/fetch 和代理夹具与真实浏览器、外部渠道、生产告警联动分别验收。

发布前按既有[迁移与切换](../migration/README.md)停旧 writer、备份，在隔离副本演练 177/178 后成套更新 API/worker。诊断字段可空兼容历史，不重写 checksum 或恢复未知外部动作；回退遵循已验证的数据库/二进制组合。本轮实现不代表已部署或已验证生产网络开销。
