# 客户登录、每日续费与认证审核调整

本次按旧系统的客户账号语义调整登录和实名同步，续费参考旧系统每日完整遍历的方式，认证审核增加归属和权限变更的并发保护。

## 客户登录

- 客户中心默认使用邮箱或已验证手机号加密码登录；后台管理员继续使用管理员账号。
- `POST /api/v1/auth/login` 使用 `identifier` 提交邮箱或手机号。兼容原 `username` JSON 字段提交邮箱、带区号的手机号及管理员账号，客户用户名登录始终被拒绝。
- 邮箱去除两端空白并转小写。国内 11 位手机号自动补 `+86`，国际号码使用 `+` 或 `00` 国家区号；允许空格、括号和连字符。原 `username` 字段中的普通账号继续按后台账号解释，避免把数字管理员账号识别成手机号。
- 手机号必须属于已验证绑定，未验证号码不能登录；邮箱、手机号仍受各自登录开关和 MFA 校验约束。旧的用户名 MFA 挑战不能恢复客户用户名登录。
- 客户注册页面只填写姓名、邮箱、密码及按配置要求的验证码，服务端自动生成内部账号标识。旧 API 可继续提供内部 `username`，它不再作为客户登录凭据。
- `users.username` 保留为内部账号标识；旧系统 `clients.username` 对应 `users.display_name`。认证通过后的姓名同步只更新 `display_name`，同时递增客户资料版本，同名客户互不冲突。
- 后台移除客户用户名登录开关，API 拒绝重新开启该方式。

迁移 `141_customer_login_identifiers.sql` 关闭已有客户用户名登录配置并递增设置版本；原配置仅允许用户名时恢复邮箱通道，避免所有客户登录方式均被关闭。管理员账号不受客户登录开关影响。迁移不会猜测或批量恢复此前被错误修改的内部用户名。

## 每日自动续费

- worker 启动时检查当日执行情况，此后每分钟检查；按数据库会话时区的日历日执行完整扫描。
- 每轮固定服务 ID 上界和到期窗口，按服务 ID 分页遍历全部候选。`ProcessAutoRenewals` 的第二个参数现在表示查询页大小，不限制整轮尝试总数。
- 单项建单或付款业务失败会记录原因并继续后续服务；每项尝试有 30 秒超时。余额不足后保留未付账单，后续扫描跳过已有未付续费账单的服务。
- 既有手工未付账单也保留，避免删除客户已经取得的账单与报价。只将账单实际为 `paid` 的续费计入成功，保留现有服务、到期周期和付款幂等键。
- 使用事务级数据库咨询锁协调多个 worker。中断释放锁后，其他 worker 可重新扫描；重复建单和扣款由原有财务事务及幂等键保护。
- 完整扫描在独立 goroutine 执行，避免延迟开通、邮件和短信任务。
- 迁移 `142_auto_renew_daily_index.sql` 为执行记录增加 `is_full_pass` 标记和查询索引。旧版本的批次成功记录不阻止首次完整扫描；完成扫描必须成功保存执行记录。
- “扫描完成”表示已遍历候选，不表示每个服务均续费成功；逐项结果由账单及 `auto_renew_error` 判断。

## 认证审核

审核和幂等结果重放都按以下顺序执行授权：

1. 取得人员和角色管理的共享咨询锁，复核管理员状态及 `certifications.manage` 权限。
2. 锁定认证主记录，再以独立 SQL 获取当前申请资料，避免使用等待之前的语句快照。
3. 取得客户归属共享咨询锁，重新检查当前客户范围，持有至事务结束。
4. 在等待结束后复核并锁定当前会话或 API 凭据，再读取幂等回执。
5. 新决定检查认证版本和待审核状态，将决定、申请、姓名同步、客户资料版本、审计和回执一起提交。

销售归属修改使用同一客户锁的排他形式，人员和角色修改使用同一全局锁的排他形式。先完成归属撤销的审核被拒绝；已取得归属共享锁的合法审核提交后，归属修改才继续。Store 内部入口执行同样的授权。

姓名更新沿用客户管理的 `users`、`customer_profiles` 行锁顺序；缺少资料行时保留联系人提供的公司和电话默认值。姓名未变化时不递增资料版本。无法解密的历史认证资料或超出姓名字段长度时记录跳过原因，认证决定仍可完成。
