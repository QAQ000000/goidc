## 2. 权限、身份与读取契约（待实现）

配置列表、详情和全部写操作统一保持 `customers.manage`；仅有 `customers.view` 的员工不能进入配置页或调用其GET。已有 `/admin/customer-field-definitions` 的 `customers.view` 或 `customers.manage` 读取策略及数字目录版本不变，不将该只读定义接口扩为字段配置接口。不新增客户销售范围或租户筛选，字段定义仍是全局设置。

新增 `GET /api/v1/admin/customer-fields/{id}`：有效管理权限返回单条类型化字段对象，字段白名单为：

- `id,field_key,label,field_type,description,validation_pattern,choices,sort_order,admin_only,required,show_on_register,active,version,created_at,updated_at`。
- id/version为正整数，choices始终数组，六类型沿用现有枚举；无客户资料值、员工密钥或操作账本字段。
- 匿名401、无配置管理权限403；不存在的正整数ID返回404，非法ID返回400。
- 返回标准API `data` 包装内的上述对象；成功响应 `Cache-Control: no-store`。编辑或冲突重读按ID读取，不从某页列表或模糊搜索猜测目标字段。

列表及详情使用显式DTO，避免未来表字段被通用Map意外公开。前端缓存/草稿/原请求按当前员工身份隔离；员工改变或权限周期变化后不可复用旧快照。焦点及可见性恢复重新核实身份后读取，核实失败先隐藏旧配置内容。401/403显示登录或权限说明及可用重读入口，不以空列表替代失败。

## 3. 列表筛选、分页与URL（待实现）

`GET /api/v1/admin/customer-fields` 保持 `{items,total,limit,offset}` 包装，items使用上述字段DTO，空集合为 `[]`。

| 参数 | 固定语义 |
| --- | --- |
| q | 去首尾空白后最多100个Unicode码点，超长400；对field_key/label/description做不区分大小写的字面子串搜索，`%`、`_`及反斜杠均按普通字符匹配，不作为通配符或转义输入 |
| field_type | 空或text/textarea/number/date/select/boolean，其他400 |
| active | 空/true/false，其他400 |
| limit/offset | 沿用项目pagination：limit合法1–100，缺省或非法回落25；offset缺省、非法或负值归0。前端提供25/50/100 |

只接受上述列表参数，其他参数400；前端只投影API认可参数，不把页面page等状态直接透传。类型/启用字段继续严格校验，不默默以“全部”替代非法API筛选。

列表排序固定 `sort_order ASC,id ASC`。同次响应的total及items必须取自同一只读一致性快照；不承诺整个跨页会话冻结，定义被新增/删除后后续页可以变化。

页面URL保存 `q,field_type,active,page,limit`，page为从1开始的正整数。刷新、直接打开、浏览器前进/后退及离开返回均恢复同一筛选上下文。更改筛选/条数或重置回第一页；搜索提交时使用规范化q。无结果与越界页分别展示：total=0显示筛选空态；total>0但当前页items为空显示越界说明和显式“回到第一页”，不自动跳页或掩盖真实total。删除最后一行也沿用越界恢复，不编造本页仍有记录。

## 4. 字段语义、不可重命名及历史保留

保持现有长度、正则、选项、排序与类型校验。正则使用服务端Go regexp语义，不把JavaScript正则通过当成服务端校验结果。非下拉字段提交空choices；下拉至少一个非空且不重复的选项。前端提供具体可理解提示，服务端仍是最终校验者。

仅 `active && show_on_register && !admin_only` 表示实际公开注册可见。管理列表应区分原始“注册时显示”标志和实际生效结果，说明停用/仅管理员可见的优先级。允许保留历史冲突标志，不自动改写配置，也不把内部required强加给注册用户。

字段标识创建后不可重命名：前端继续禁改，后端新增原值比较，新PATCH修改field_key返回409 `field_key_immutable`，无定义、目录版本或审计写入。基线后端目前仍会UPDATE field_key，故这一保护尚待实现。已提交历史操作的同键重放仍返回其固定回执，不为重放再次执行重命名。

删除仅删除字段定义，停用仅改变启用标志；不得迁移、清空或重写客户profile中已有custom_fields JSON。相关历史值保留，不承诺删除定义后仍在活动表单中显示。删除确认明确影响及历史保留边界。本批不增加客户历史值清理、批量迁移、字段重命名、标识回收账本或新资料域。

## 5. 新增、修改、删除的草稿与原请求恢复（待实现）

保留既有方法和请求体：新增POST为字段白名单；修改PATCH为同组字段加expected_version；删除DELETE仅expected_version。不得把GET返回的id、version、timestamps等只读元数据直接回传。沿用服务端员工+操作范围+幂等键及版本/审计机制，不重写注册幂等策略。

### 未提交草稿

新增和编辑保存表单及原始快照，按员工、操作类型及字段ID隔离；恢复需要用户显式选择，不自动覆盖最新服务端数据。取消按钮、遮罩、Escape及离页对脏草稿提示确认；确认放弃只清相应未提交草稿，不清原请求。干净关闭不多余确认。草稿存储损坏不显示解析原文或配置内容，提供可理解提示。

编辑打开和再次操作前按ID读取最新对象；读取失败保留安全输入但阻止提交。删除有独立确认及目标名称/标识/版本提示。同步互斥锁覆盖三类写操作，防止双击、列表删除与编辑保存并发；未知结果未核实前禁止其他新写入。

### 发送与未知结果

发送前实时读取 `/me`，核对原员工ID和 `customers.manage`；身份读取失败、员工改变、权限不足或组件已卸载均零写POST/PATCH/DELETE，原员工空间的资料不删除、不迁移到新员工。

在实际发送之前，把原 `path,method,key,body` 写入身份隔离sessionStorage并保存在内存；之后恢复必须逐字使用原body、原key、原方法、原路径和ID。新请求无法持久保存则不发送，清楚提示阻断原因；已有原请求可按安全内存状态核实，不自动换键。操作资料不含密码、会话token，URL仅放列表状态。

网络中断、408、429、5xx或不完整成功响应均保持待核实；401/403及权限/身份失败不删除原责任。404不能单靠“字段已不存在”推断删除原请求未提交或已成功；保留恢复入口按原DELETE核验回执。刷新、关闭弹窗、字段改为停用、目标被删除或当前列表无该行，都不能隐藏或丢失原请求；恢复入口独立于编辑目标及列表存在性。后台重放继续在当前身份/权限复核之后执行，不能借历史成功绕过撤权。

明确成功回执才清理对应原请求及已完成草稿，并刷新相关资源；新增/修改确认 `{id,version}`，删除确认 `{id,deleted:true}`，ID须与目标相符（新增取得新ID）。清理storage失败不得开放新操作，应保留原请求用于再次核验。恢复队列从不自动发送。

### 409与明确拒绝

版本冲突、标识冲突、不可重命名或幂等异参409均保留草稿和原请求，明确区分原因，禁止自动换键/更新expected_version重发。用户必须显式重读字段最新事实；目标已删除显示404事实并保留原请求恢复区。重读失败仍锁定新写入。

原请求可继续用原键核验。用户确认已理解明确拒绝后，可显式结束该被拒请求；再次编辑时由用户决定保留输入或用最新对象替换草稿，再次确认才产生新请求。不能把重读或关闭弹窗当作自动提交、自动放弃原请求或默默覆盖草稿。新增标识冲突不依赖尚不存在的字段ID；显示冲突原因，显式结束被拒请求后由用户重新选择标识。其他明确输入400也需明确纠正，不无限重放无效body。
