# 信用额管理首批

新增独立 customer_credit_accounts 与 customer_credit_events；初始额度为零，必须管理员明确设置授信额度，不从预存余额、余额消费或全局设置推导客户债务。GET /admin/credit 返回真实额度、已用和可用金额，提供客户范围、状态/关键词筛选和分页。PUT /admin/credit/{id}/limit 只调整授权额度，不修改 users.balance_cents 或 balance_ledger。

写入需 credit.manage、有效浏览器会话；事务锁定管理员、角色、会话及客户范围，复核版本及幂等请求，记录授信事件与审计。额度不能低于已用额。迁移为已有客户初始化零额度账户，并为新客户创建账户。

本批未接入信用消费/账单债务、还款、冻结/解冻、按客户授信审批和旧信用额数据导入。used_cents 为真实账户占用字段，新建账户为零；本批没有消费或还款写入口。旧版消费记录/还款记录标签不能以余额流水冒充，后续需独立业务闭环。全局信用额设置不会批量覆盖客户授信。

验证：隔离 PostgreSQL 18 HTTP 测试验证迁移、真实列表、额度写入/重放、版本冲突、低于已用拒绝、权限/客户范围和预存余额不变；前端 typecheck。尚未浏览器验收。
