## 当前供应商生命周期边界

供应商宿主已接通按编译能力入队、运行能力复查及暂停/恢复/终止目标确认。不支持的动作生成可处理的人工待办，先在原供应商完成操作，再回读原资源与原商品，权限、会话、版本和审计贯穿核验；已发送但未知的写操作继续持有账户租约，禁止自动重发。默认魔方提供方仍不声明这三类写能力，不能把宿主流程完成解释为真实魔方动作已自动化。

邮件、短信继续使用原模板与 outbox，统一付款记录只关联旧队列，不重复发送；工单三种公开事件及其邮件/短信偏好仍走独立链路。真实 Telegram 已核验 `getMe`、`getWebhookInfo`，但当前没有公网 HTTPS 地址，未配置真实 webhook，未验收真实消息收发。模拟平台接受不代表真实平台收件。

首批运行增量补齐严格 CI 与本地等价门禁：31 项单元 race、42 项 PG18 串行 race 均通过，集成零跳过；实际 API/worker 清单均为 9 模块且无网络尝试。160→161/162 旧密文/待发队列升级、历史付款回放不补发、当前候选拒绝 160/161，以及通知生产循环子进程 SIGKILL 后 unknown 不重发均通过。`c25d3bf` 独立 v2 候选同包迁移两次、3 页/21 资源、API/Web/worker 启停及 TERM/重启通过；控制器依赖闭包缺失已修复并保留失败及重跑证据。详见[通知验证边界](notification-architecture.md#当前验收状态)与 `output/notification-runtime/summary.json`。这是有限旧夹具升级和隔离准备，未验证旧二进制降级、生产快照恢复、真实渠道或正式切流；G04/G09 保持开放。

第三批生命周期扩展的 57 项 PG18 串行 race 门禁零跳过通过，覆盖真实业务接线、仅 Telegram 的提醒候选、显式扩展订阅、UTC 会话日期、提醒失效和旧邮件短信兼容；实际 160/162 起点升级到 163，并验证同一 API/worker 拒绝 160/161/162 启动。真实隔离 API 的桌面/手机浏览器、独立前端生产构建及实际 9 模块清单检查通过。浏览器列表使用合成投递记录，实际业务事件由数据库集成验证；这不等于真实 Telegram 收件或新版本已部署。证据见 `output/notification-lifecycle/summary.json`。

## 按业务范围补齐的 P1/P2

这些项目不是所有部署共同的 P0，应依据实际启用产品逐项立项：

- 客户信用门户仍缺线上还款、账期合账、授信审批和已还款现金退付；联系人资料有权限标签，但没有联系人独立登录身份与真实授权执行。
- 供应商客户自助运维、上游升级及暂停/恢复仍未形成完整客户授权契约；旧下游分销/供应商协议、远程部门映射和回调签名不能由采购侧 catalog/import API 代替。
- 实名认证已有实例绑定、加密申请快照和持久提交/查询运行链路，见[实名认证契约](domain/certification.md)；生产仅装配人工 provider，真实厂商及回调验签仍未接入。OAuth 仍为分类预留，启用时需真实渠道、state/nonce、绑定解绑和 MFA 会话关系；敏感文件安全及审批留痕须独立验收。
- 合同强制签订、商品绑定、电子签署证据、税务开票服务仍缺；HTML 打印和发票申请记录不等于电子签章或税务开票。
- 优惠码开始/失效时间、过期状态和深度搜索分页，以及商品编辑旧十区的逐项映射仍部分；流量包资源交付、多币定价/结算也未形成完整策略。
- 工单部门自定义字段、上游工单同步、供应商工单 ID 映射/签名/去重及附件安全仍缺；旧 `/v1`/OpenAPI 消费者兼容须另做 wire contract。
- 旧版完整报表恢复口径已确认，实施和验收见[业绩、处理人评分、年度账户收支和产品分类/数量](report-restoration-contract.md)。已有汇总接口或历史截图不构成全量旧功能验收。
- 独立 DCIM、资源池/IPMI、NOKVM 真实母机、应用市场/插件、低频 CRM/营销能力按现网消费者决定，不能由同名页面或统一渠道目录推定覆盖。

## 审查结论

当前 Go/Next 已具备核心交易、异常保护、通知、易支付和魔方供应商操作框架，并具备可复核的完整运行包；“可停用旧 PHP”剩余阻断主要是正式 HTTPS/维护/回调及生产切流切回、支付退款到账与查单能力边界的正式证据、实际供应商资源扩展动作、目标容量/其余故障点恢复和（若接管存量）业务快照迁移。隔离双Web、代表性网络窗口强杀恢复及有限600任务来源/双worker/独立对账子项已通过；相同源码/迁移集合的成功不能替代历史 schema 升级。建议下一份发布评审只使用本记录的当前证据和各专项验收链接，逐项将外部条件标记为 PASS / FAIL / N/A / 未验证；不要把已实现并测试过的功能重复列为未实现。
