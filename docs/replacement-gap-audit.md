## 按业务范围补齐的 P1/P2

这些项目不是所有部署共同的 P0，应依据实际启用产品逐项立项：

- 客户信用门户仍缺线上还款、账期合账、授信审批和已还款现金退付；联系人资料有权限标签，但没有联系人独立登录身份与真实授权执行。
- 供应商客户自助运维、上游升级及暂停/恢复仍未形成完整客户授权契约；旧下游分销/供应商协议、远程部门映射和回调签名不能由采购侧 catalog/import API 代替。
- 实名认证已有实例绑定、加密申请快照和持久提交/查询运行链路，见[实名认证契约](domain/certification.md)；生产仅装配人工 provider，真实厂商及回调验签仍未接入。OAuth 仍为分类预留，启用时需真实渠道、state/nonce、绑定解绑和 MFA 会话关系；敏感文件安全及审批留痕须独立验收。
- 合同强制签订、商品绑定、电子签署证据、税务开票服务仍缺；HTML 打印和发票申请记录不等于电子签章或税务开票。
- 优惠码开始/失效时间、过期状态和深度搜索分页，以及商品编辑旧十区的逐项映射仍部分；流量包资源交付、多币定价/结算也未形成完整策略。
- 工单部门自定义字段、上游工单同步、供应商工单 ID 映射/签名/去重及附件安全仍缺；旧 `/v1`/OpenAPI 消费者兼容须另做 wire contract。
- 旧版完整报表恢复口径已确认，实施和验收见[业绩、处理人评分、年度账户收支和产品分类/数量](report-restoration-contract.md)。已有汇总接口、CSV或历史截图不构成全量旧功能验收。
- 独立 DCIM、资源池/IPMI、NOKVM 真实母机、应用市场/插件、低频 CRM/营销能力按现网消费者决定，不能由同名页面或统一渠道目录推定覆盖。

## 审查结论

当前 Go/Next 已具备核心交易、异常保护、通知、易支付和魔方供应商操作框架，并具备可复核的完整运行包；“可停用旧 PHP”剩余阻断主要是正式 HTTPS/维护/回调及生产切流切回、支付退款到账与查单能力边界的正式证据、实际供应商资源扩展动作、目标容量/其余故障点恢复和（若接管存量）业务快照迁移。隔离双Web、代表性网络窗口强杀恢复及有限600任务来源/双worker/独立对账子项已通过；相同源码/迁移集合的成功不能替代历史 schema 升级。建议下一份发布评审只使用本记录的当前证据和各专项验收链接，逐项将外部条件标记为 PASS / FAIL / N/A / 未验证；不要把已实现并测试过的功能重复列为未实现。
