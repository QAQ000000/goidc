配置页面必须连接实际API、数据库与运行进程。保存成功不等于外部付款或邮件投递成功。真实密钥不得进入Git、截图或文档。

## 支付契约

`GET/PUT /api/v1/admin/payment-settings` 限定超级管理员Cookie会话，写请求校验来源。PUT使用`expected_version`；冲突保留草稿，重新加载确认放弃修改。GET只返回`key_configured`，空密钥保留，清除前关闭支付。

schema084用AES-256-GCM和支付专用AAD保存密钥，主密钥为部署环境的`PROVISION_ENCRYPTION_KEY`。首次保存前使用环境配置；首次保存后数据库为准，首次空密钥保存加密保留已有环境密钥。审计不保存秘密。

API按每次请求读取配置，worker每10秒处理过期和查单，无需重启。总开关关闭阻止所有新在线支付，停用渠道不阻止已有单的回调和查单。仅尚未超过本地有效期的待支付易支付单或活动查单租约阻止更换地址/PID/密钥。清钥后可仅启用模拟支付；启用任一易支付渠道必须有完整凭据。支持HTTPS网关或回环HTTP测试地址，PID为1至20位数字。

schema087 为新易支付单保存不可变 AES-GCM 商户快照，密文绑定付款号；查单和回调始终使用该单原商户。轮换前将无快照的历史单按当前原凭据补齐，未结算单的原凭据不可用则拒绝轮换，不能猜测已经丢失的历史密钥。已成功/失败的历史单若无原凭据，写入加密“不可用”标记，不阻止新商户配置，也不使用新密钥替旧单验签。新单流水加入网关身份摘要，兼容旧单 `PID:trade_no`，不同网关重复 PID/流水不互相冲突。主加密密钥必须保留，不能直接轮换或丢弃。

worker 将超时易支付单标为 `expired`，记录本地过期审计并安排再次查单。上游 `status=0` 不代表关闭支付链接，因此旧单仍接受迟到成功通知，仍阻止该账单重复付款、余额支付、编辑、作废、合并及订单取消。可信关单和原路退款尚未接入。schema086 和环境兜底均默认关闭模拟支付；后台明确开启或 `PAYMENT_MOCK_ENABLED=true` 才启用，迁移保留已主动保存的配置。

## 邮件契约

`GET/PUT /api/v1/admin/smtp-settings` 使用相同会话、来源和版本保护。schema085加密密码，AAD与支付/服务密码隔离。空密码保留，清除前关闭邮件发送；GET仅返回`password_configured`。首次保存前读取环境配置，首次保存加密保留环境密码。

worker每2秒及每次领取任务前重新读取，停用或解密失败停止领取，已发出的网络请求无法撤回。发送器为`net/smtp.SendMail`，服务器提供STARTTLS时升级，认证使用PlainAuth；不支持465隐式TLS，启用时拒绝该端口。未认证邮件遇到不提供STARTTLS的服务器可能明文发送，尚无强制TLS开关。发件地址必须为单纯邮箱。后台试发与真实收件验收未完成。

## 浏览器链路

每条链路记录前置配置、操作、终态、异常恢复及手工环节。默认使用独立PG18库/schema，真实验收单独记录外部证据。

| 链路 | 顺序 | 必须核对 |
| --- | --- | --- |
| 支付 | 后台配置/启用 → 客户下单 → 创建支付 → 访问网关 → 手动补单或付款 → 回调 → 刷新账单/服务 | 金额、渠道、一次入账、重复回调、停用后的旧单回调；支付宝和微信分别执行 |
| 供应商交付 | 配置账号 → 拉取目录 → 导入商品/定价 → 下单付款 → worker开通 → 定时同步 | 本地/上游ID、主机名、实际状态、库存、超时待核验和重复任务 |
| 服务操作 | 已开通服务 → VNC/电源/重装/重置密码/救援 → 任务 → 同步/核验 | 实际资源状态、权限、密码更新时机、未知结果不盲目重发；破坏动作按指定资源范围执行 |
| 邮件找回 | 配置SMTP/模板 → 忘记密码 → outbox → worker → 收件链接 → 新密码登录 | 真实收件、令牌单次使用/过期、会话失效、失败重试 |
| 工单 | 部门/权限/预设 → 客户提交 → 接单/分派 → 插入预设/回复附件 → 客户查看 | 部门隔离、内部备注、附件归属、停用预设 |
| 财务续费 | 定价/优惠 → 下单付款 → 续费 → 付款 → 到期更新 | 分单位金额、优惠核销、流水、一次更新；人工退款与原路退款分开验收 |
