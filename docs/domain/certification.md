# 实名认证与提供方实例

实名认证采用编译期提供方、运行时实例配置和持久任务。核心保存身份资料、申请历史、审核状态、购买及 API 密钥资格；提供方只负责协议映射、提交与查询。当前生产装配仍只包含 `manual`，测试适配器不进入发布清单。

## 实例选择与申请绑定

`certification_settings.default_provider_id` 保留实现 ID，新增 `default_instance_id` 指向实际渠道实例。设置写入必须验证实例类别、实现、启用状态、配置 schema、必填值和凭据，保留 `certifications.manage`、会话、来源、版本、幂等与审计边界。旧客户端仅为 `manual` 省略实例时兼容到 `manual-default`；其他实现必须明确选择实例，不能随机选择同实现的一个账户。

迁移 164 创建人工兼容实例。历史申请的资料密文、状态、时间、人工审核记录保持原值，不为历史申请补发外部请求。

新申请及个人转企业在同一事务中保存资料、实例 ID、实例版本、配置 schema、申请对应的档案版本、稳定请求 ID 和处理任务。配置与命名凭据使用独立密文快照，AAD 绑定具体申请；后续修改默认实例或轮换密钥不改变该申请的提供方身份。被设置或申请引用的实例禁止删除。

资料仍按现有认证专用 AAD 加密，申请配置快照另有 AAD。公开响应只增加安全的 `processing_state`，不返回资料、快照、凭据、提供方原始消息或交易主体标识。管理员查看资料仍须通过客户范围和访问控制。

## 提供方接口

`internal/certification` 提供 `RegisterFactory` 和 `New(id, module.Config)`。工厂只构造实例和验证本地参数，不联网；不得用全局共享凭据替代实例配置。`Register`、`RegisterDescriptor` 和 `Lookup` 保留旧代码兼容，实例运行路径使用 `New`。

`Submit` 接收认证类型、必要身份资料和稳定的 `RequestID`；`Query` 接收原请求 ID 和已知的 `ProviderSubject`。适配器必须把上游业务状态规范化为 `processing`、`approved`、`rejected` 或 `failed`。网络错误、超时、畸形响应和未知状态不能当作认证拒绝。

提供方声明 `submit`、`query` 及可选 `query_by_request_id` 能力；无法确定外部主体时，只有支持原请求 ID 查询的实现可以自动核验。已知主体的查询结果不能更换为另一个主体。人工实现声明 `review`，申请直接进入待人工审核任务，不发出网络请求。

新增真实适配器时，须只发送必要资料，定义 HTTPS、请求签名、超时、上游身份与状态校验及敏感日志边界。本批没有厂商回调入口；需要回调的厂商须另外实现验签、防重放、具体申请/实例绑定及相同结果围栏，不能把未验证的回调 JSON 直接作为认证结论。

## 任务与不确定结果

worker 的认证循环独立于开通、通知和支付循环，每轮最多处理 10 个任务。外部调用发生在数据库事务之外，提供方调用有 15 秒超时；调用超时后仍用父上下文持久化不确定状态。

| 情况 | 核心行为 |
| --- | --- |
| 尚未开始提交 | 原子领取并记录已开始发送，提交最多尝试一次 |
| 接受且处理中 | 保存加密结果，至少间隔 30 秒查询 |
| 超时、断连、崩溃或提交结果未知 | 不再次提交；按原主体或稳定请求 ID 查询，能力不足则待人工核验 |
| 查询失败或继续处理中 | 最多查询 5 次，之后待人工核验，不无限消耗提供方额度 |
| 明确通过/拒绝 | 同事务更新当前档案和具体申请、完成时间及审计 |
| 配置不可用、解密失败、无效响应或技术失败 | 保持业务待审核，显示待进一步核验，不伪造拒绝结论 |
| 总开关/实例停用 | 阻止尚未发送的提交；在途核验仍使用原申请快照 |

租约令牌阻止失效进程提交结果。进程在发送标记之后退出时，恢复只进入查询；标记已写但请求尚未到达上游也不能假定安全重发。需要重新申请时由客户或管理员根据已核实的业务情况处理，不能自动清除发送标记。

结果存入 `certification_provider_results`，原始消息仅在加密结果中保留；任务错误码、公开驳回提示与审计使用安全的通用描述，不保存原始身份资料或提供方错误正文。

## 状态、人工审核与业务资格

档案的业务状态继续为 `unverified`、`pending`、`approved`、`rejected`。提供方的 processing/failed 不直接写进档案枚举；公开处理状态分别为 `queued`、`processing`、`needs_review`、`finished`。

结果只有在具体申请仍为最新申请、档案仍待审核且档案版本匹配时才可生效。客户重新申请、个人转企业和管理员人工审核都会使旧结果失效；迟到结果不能覆盖新申请或人工终态。

提供方通过须同时写入申请 `approved` 和 `reviewed_at`，并保留加密资料有效性检查，从而满足原下单和 API 密钥资格规则。自动更新姓名继续在同一事务执行并更新客户资料版本；登录名及其他客户字段不变，审计只保留变更字段和对象标识。

姓名写回使用不等待的客户行锁，避免与并发下单/API 密钥资格查询形成死锁。发生锁冲突返回 `certification_busy`，决定、姓名及审计全部回滚；人工审核可重试，外部任务保留已发送标记，租约恢复后只查询，缺少查询能力时转人工核验。

现有人工审核权限、客户范围、等待锁后的撤权复核、审核回执、姓名更新事务和历史记录继续生效。个人手机号匹配沿用现有宽松规则，企业申请及个人转企业不新增手机匹配限制。高级开关、自动通知、未实名暂停和认证文件上传仍未因本次模块化而启用。

普通提交新增可选 `Idempotency-Key`，新客户端对相同表单的网络重试复用键，旧客户端无键仍可提交。回执与资料、任务、审计共同提交；返回回执前重新检查凭据与认证总开关。该键只合并同一次请求，不能把两次独立申请当成同一业务请求。

## 验证、发布与边界

测试入口见[测试说明](../testing.md)，领域门禁见[验收矩阵](../architecture/contract-verification-matrix.md)。必须覆盖两实例配置隔离、密钥轮换、未知结果只查、租约恢复与旧结果围栏、人工覆盖、审核事务、身份数据加密、下单/API 密钥资格及 163 升级。

隔离测试提供方和浏览器夹具只证明对应代码链路，不能视为真实厂商验证。发布时迁移 164 与 API/worker 同包升级；旧二进制不处理新任务，不能直接作为回退手段。停止有问题的认证 worker 后保留资料与任务，按已验证的数据库恢复和发布手册处理，禁止删除发送标记或改写既有迁移来强行重试。
