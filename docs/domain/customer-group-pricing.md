# 客户分组定价

状态：当前实现。规则适用于迁移 180 后新建的购买，不重算既有订单、服务或退款证据。

## 计价顺序

1. 读取当前客户分组。未分组的客户使用目录价格；客户组 `discount_percent=20` 表示减免 20%，支付八折。
2. 配置项计价后，对每件服务的周期价与初装费应用分组规则。命中商品组规则时覆盖客户组默认，即使商品组减免更少。商品同时命中多条规则时，按本次单件总价计算实际减免，取最大；相同金额取规则 ID 最小的一条，不累加。
3. 百分比减免按单件总价向下取整到分，再乘数量；续费周期价的减免独立向下取整，剩余减免归初装费。固定减免按每件计算，先减周期价再减初装费，金额最低为零。配置项、配置数量和配置初装费计入相应部分。
4. 管理员显式指定首次或续费覆盖价的项目跳过分组减免。首次覆盖价仍替代该次整件价格；仅覆盖首次时，默认续费价保持原目录及配置价。既有“覆盖价订单不能用优惠码”限制继续生效。
5. 优惠码在组折后金额上计算。按商品、账期筛选后，百分比/固定减免按符合条件行的组折后金额累计分摊；免初装费按组折后初装费分摊。采用稳定行序的累计整数分摊，所有行优惠之和精确等于订单优惠。

“无商品组折扣”沿用原设置含义：删除规则，随后回退客户组默认折扣。客户等级、销售提成组与此客户分组相互独立。

## 优惠码的客户组范围

`applies_customer_group_ids` 是客户组 ID 数组，不是商品组。管理列表、编辑和代下单快速建券均显示这一范围，选项接口仅返回组 ID/名称，使用 `promos.view` 权限。

| 配置 | 使用资格 | 与分组减免组合 |
| --- | --- | --- |
| 留空（包含历史券） | 所有客户，包括未分组客户 | 订单存在正的分组减免时拒绝该券，保留分组优惠；界面允许移除券并重新报价 |
| 显式选择客户组 | 只有当前属于所选组的客户 | 分组优惠后继续使用优惠码，即折上折 |

范围在报价、应用到购物车、实际结账和升级用券时重新校验。升级不重新计算既有服务的客户组减免；升级专用券沿既有模式在付款时再次核对资格，循环续费券则使用冻结权益。编辑范围要求当前优惠码版本；同键重放保持原范围，改 body 必须换键。删除被券引用的客户组被外键拒绝，避免删除最后一个组后意外扩大为全客户。券的核销金额仅保存券的优惠，不含组减免。

## 报价、历史与续费

- `POST /api/v1/cart/quote` 接受 `cart_version` 和所选 `item_ids`，返回服务端价格、分组/券减免、每行来源和 `quote_hash`。购物车部分选中也重新报价，不按全购物车比例猜测优惠。
- 前端只允许匹配当前选中项与版本的报价结账，并原样携带 hash。规则、归组或券条款变化时要求重新确认；不覆盖结果未知请求原有的 body、hash 或幂等键。旧 API 的不带 hash 请求兼容保留，仍按事务中的当前规则计价。
- 后台报价与结账共用 Store 计价，报价 hash 包含规则来源/版本、价格及购买配置。管理员改变客户、配置或价格后重新报价。
- `order_items.total_cents` 继续保存原价；订单 `discount_cents` 为组减免加券减免，订单/发票总额为净额。
- 独立不可变 `order_item_pricing` 保存每行原价、两种减免、净额、来源和每件续费基价；订单/发票详情读取这一快照。没有快照的历史订单只展示原优惠合计，不从当前分组补算或回填。
- 新服务保存组折后的周期价为 `recurring_price_cents`；一次性商品保存零。以后修改客户分组/规则不改变这个合同价。循环优惠码另存原有权益，按这个合同价执行，不把当前组优惠重复应用到续费。
- 产品收入、销售明细和新购计佣使用确切行净额；调整后的发票按净额权重分摊实际金额。信用授权本身不计现金收入，新购信用回款直接关联订单行，不依赖只用于服务/续费账单的 `invoice_items`。新信用回款先对全部历史收款累计，再按本期累计差额分摊，防止多次或跨月还款产生尾差；期间、商品和分类筛选不重新分配已收金额。同一期间按订单行去重件数、按订单去重单数，跨期间件数不能相加当成全年件数。旧单保留原 gross 权重及逐笔分摊口径。

## 客户成员分配

客户成员分配使用独立成员版本，GET/PUT协议见[后台API](../admin/api.md#客户分组的版本与结果恢复)。必须显式提交group_id、当前成员版本和稳定幂等键；null仅主动移出分组，漏传不清空。同组保存不递增版本，但新意图单次审计；换组或清空按真实成员变化递增，历史成功重放不重算。分组规则version、sales_version和客户profile_version均不能代替成员版本。

迁移183以独立元数据表为既有客户初始化成员版本1，此后数据库触发器覆盖API、创建和导入等成员写入，不追溯历史次数或改写购买快照。版本锁不使用users行，避免管理员代下单先持客户共享行锁、再等定价锁时与分组写入形成环。新API先取得RBAC/客户范围及管理员权限锁，再取定价写锁，最后复核实际凭据；新旧成员writer不能混跑。

## 事务、迁移与发布

定价读持有共享事务锁，分组/规则/券范围写持有独占锁，覆盖首次成员和首次规则插入；应用写入口在行锁前取得独占锁，数据库语句触发器提供补充保护。购物车先锁自身，再取定价和目录锁；价格和优惠的读取、快照、订单、服务、库存、发票、核销、审计及通知原子提交。失败不消耗库存或优惠次数，已成功同键重放不重新定价。

迁移 180 新增关系、快照与独立出生标记，不向旧 `orders` / `order_items` 增列：外部退款证据保存整行 JSON，增列会使旧证据失配。出生标记由新订单 INSERT 触发生成，不从旧订单推断；定价必须在原创建事务、库存预留之前落库。快照不能更新/删除，出生总额用延迟约束核对，旧单不可事后补快照。原订单行的历史检查及退款围栏保持原契约，不新增一套全局订单冻结状态机。

先停止旧 API、worker 和其他 writer，升级迁移后成套启用新 API/worker；旧 writer 不具备此计价契约，不能混跑或直接回退旧二进制。生产快照升级、正式域名浏览器及外部资金/供应商渠道需要单独验收。

## 验证入口

`node scripts/test-customer-group-pricing.mjs --integration` 使用独立回环 PostgreSQL 18 `_test` 库，串行 race，逐项核对 run/pass、拒绝 skip。覆盖规则/整数分、购物车与后台、部分选择、券范围、报价失效、幂等回放、续费冻结、财务分摊、真实 schema179 升级、退款证据及并发锁序。前端组件由 `node --test scripts/purchase-discount-components.test.mjs scripts/promo-customer-groups-components.test.mjs` 验证。

本地 Next 生产构建配合真实 Go API 与随机 PostgreSQL schema 的浏览器验收已覆盖：客户登录、普通券拒绝叠加、指定组券叠加、部分购物车结账、订单与账单快照、未选商品保留，以及后台客户组搜索/选择/保存。夹具 `TestCustomerGroupPricingBrowserFixture` 在结束时断言只创建一单，原价 2666 分、组减免 532 分、券减免 213 分、净额 1921 分；390px 视口的账单页面无横向溢出。该入口需显式启用浏览器夹具，不纳入必跑集成 runner。

本地验收不代表真实渠道、线上升级或远端 CI 已通过；原始证据写在被忽略的 `output/`。
