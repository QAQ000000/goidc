# 2026-10-16 续费并发与代理来源修复

本次修复以 `ae271c7` 为基线，覆盖最近审查确认的两项 P1 问题。无新增数据库迁移，不调用真实供应商、支付或短信服务。

## 供应商续费

原流程在持有服务行锁和事务连接时，通过连接池读取供应商绑定、账号并请求上游报价。默认池大小为 10；10 个并发请求占满连接后，持锁请求等待第二个连接，其余请求等待服务锁，全部超时。

现在事务内的配置读取复用 `tx`。生成供应商续费账单分为两段短事务，中间的上游报价不持有数据库连接或行锁。写入前重新校验所有权、服务状态/版本/到期时间、供应商启用状态/版本、绑定与成本上限、已有待支付账单和进行中任务。自动续费的开关与到期候选在写入账单的同一事务里校验。

幂等键重放优先返回已有账单；同一服务不同键并发只生成一张账单，其余返回 `renewal_invoice_pending`。报价期间配置变化返回冲突，不写入过期报价。

回归测试：`internal/httpapi/supplier_renewal_concurrency_test.go`。

- 单连接池可开启自动续费并生成续费账单。
- 10 个请求占满连接池、等待同一服务锁后均可完成；不同键只生成一张账单，相同键返回同一笔结果，审计仅一条。
- 上游报价阻塞期间无数据库连接占用，本地服务和账号更新可完成。
- 服务版本、到期时间、账号版本变化，停用账号或关闭自动续费后，不生成过期账单。
- 创建后即使停用供应商，同键重放仍返回已保存的账单。

## 代理来源

Next.js 默认保留请求方提供的 `X-Forwarded-For`。Go 信任回环地址且 Next 端口可直连时，攻击者可伪造登录限流、黑名单和审计所用的 IP。

`web/src/proxy.ts` 现在覆盖 `/api/*` 并移除 `X-Forwarded-For`、`X-Real-IP` 和 `Forwarded`。NextRequest 无权证明客户端来源，因此经 Next 本地转发的请求由 Go 按连接对端归属。Cookie、Origin、请求正文、幂等键和回调查询参数正常转发。

开发/生产 npm 命令及 systemd 模板默认监听 `127.0.0.1`。生产 Nginx 的 `/api/` 必须直接转发至 Go，并由 Nginx 追加真实连接地址。`TRUSTED_PROXY_CIDRS` 仅配置受控反代。已有安装需更新 unit 并重启后才改变监听；详见 `docs/cutover-runbook.md`。

回归命令：`npm run test:proxy --prefix web`。测试启动一次性 Next 应用和本地回显后端，使用项目当前 proxy/config，检查开发及生产模式的伪造单 IP、IP 链、备用 IP 头和 middleware 子请求头，同时覆盖 `/api/`、`/API/`、`/aPi/` 大小写路径，验证业务请求和支付回调透传。
