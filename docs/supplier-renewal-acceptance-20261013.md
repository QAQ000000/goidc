# 2026-10-13 旧魔方续费接入与真实验收

用户提供旧系统接口文档并要求补接续费。本批实现旧魔方 `/host/renewpage → /host/renew → /apply_credit → 账单和资源查询`，共用本站手动与自动续费入口。取消、商品/规格/账期升级继续明确拒绝。本批没有接入 V10 续费，也没有发送取消、升级或真实退款。

## 实现边界

生成本站账单前只读查询已有资源的续费价，核对资源/商品、状态、周期、CNY 和绑定成本上限；不拿新购目录价格代替已有资源续费价。报价写入不可修改的账单快照。本站付款只按账单幂等排入 renew 任务、消费一次本地优惠次数，尚不延长到期时间。未完成的已付款续费阻止再次建单收费。

worker 使用供应商账户锁，检查本地账单仍 paid、账户版本和资源身份，再确认报价未变。上游生成账单后立即持久化账单号，随后核验唯一 renew 项、所有明细归属、成本与币种。只调用一次余额支付（use_credit=1/enough=1），不使用授信，不自动重发已经发送的写请求。响应不完整时只读查询同一账单。必须确认 Paid，并查询到至少延长一个完整购买周期，才同步到期日期并完成任务；迟到的旧同步不能缩短已确认期限。

已知拒绝、未付款账单成本/归属不符明确失败并释放账户；支付后的异常、扣款结果不明、账单已付但期限尚未生效保持 waiting_verification 和账户锁。人工“已生效”登记也必须核实原账单已付和上游新期限，不能只凭资源原本 active 结案。

## 验证

- supplier/store race 单元测试：身份错误、创建账单冒充续费、超成本、持久化失败、支付响应丢失、假成功但未支付、已付但旧期限等；失败路径不重复扣款。
- 隔离 PG18 UTF8 强制数据库回归：供应商、续费、自动续费和退款专项 race 通过（65.689 秒）。新增用例覆盖权限、建单/支付回放、本地收款不改期限、一次上游付款、未知结果保留锁、人工核验期限、自动续费重复扫描、退款前后边界。最后追加的迟到旧同步不缩短期限、报价和任务快照不可修改由续费专项再次验证（6.965 秒）。
- go vet、API/worker 构建、前端 typecheck、改动组件 ESLint 通过。
- Playwright 390px 临时预览：客户有“生成续费账单”和“启用自动续费”，任务显示“上游续费 / 已完成”；管理列表显示关联账单 36、上游任务已完成和成本 ¥0.01。两页整体宽度均为 390px，表格内部允许滚动。未通过浏览器再次点击建单或支付。

真实环境没有故意断网、制造错误资源/高价账单或做真实退款；这些边界由隔离测试证明。真实自动续费定时触发未运行；它与手动续费共用的收款和 worker 路径已由真实手动续费与隔离自动扫描测试分别验证。

## 续费异常 runbook

1. pending 尚未 dispatch 的余额续费可退本站余额，事务同时取消该任务；到期时间不扣减。external_started 后、结果未知或上游续费已完成时禁止只退本地款并回退期限。外部支付的退款继续遵循支付人工 runbook。
2. failed 表示已知拒绝或未付款账单检查失败，先查看原任务的账单号、资源和成本；不重复向客户收费。确认未生效后，可退原本地余额账单再重新报价。不要把 failed 任务原地改 pending 来重发。
3. waiting_verification 优先只读查询原 invoice_id、资源 4061 类似的绑定 ID 和原报价期限。已付且期限延长后用管理服务页面登记“上游账单已支付且续费已生效”；系统再次验证原账单和期限后结案。不能只清账户锁。
4. 若原响应丢失且没有可信账单号，保持冻结，联系供应商核对本次续费账单和执行时间。不要拿任意历史 Paid 账单替代本次账单，不手改任务 JSON 来绕过核验。只有确认本次没有已付、待付或处理中的账单/续费结果后，才登记“未产生结果”并处理原本地财务。
5. 取消、升级由管理员在上游处理并核验；取消受理不等于删除，原路退款与资源删除、本站财务退款各自核对。本站 API/页面继续拒绝这些尚未接入的写操作。
