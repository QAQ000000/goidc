# 注册登录与 MFA 设置首批

`/admin/auth-settings` 使用 `GET/PUT /api/v1/admin/auth-settings`；`/admin/security/mfa` 使用 `GET/PUT /api/v1/admin/security/mfa`。读取需要 `settings.view`，写入需要 `settings.manage`、浏览器会话、`expected_version` 和 `Idempotency-Key`。版本冲突返回 409，重复请求返回原结果，变更与审计在同一事务。

迁移 `127_auth_security_settings.sql` 建立独立认证与 MFA 策略表。原有 `site_settings` 的注册、邮箱验证、图形验证码字段保持公共接口兼容；任一后台页面修改这些共享字段都会推进另一设置页的版本。MFA 页面仅返回两个策略开关及版本和更新时间，不读取个人密钥或恢复码。关闭策略仅阻止新的个人 MFA 开通，已开通者登录仍强制验证。

客户登录总开关和邮箱、已验证手机号登录方式在真实登录路径生效；迁移 141 关闭客户用户名登录，后台移除该开关，API 拒绝重新开启。客户注册不再要求填写用户名，内部标识由服务端生成；管理员继续使用管理员账号，不受客户登录开关约束。具体兼容规则见[客户登录与每日续费调整](legacy-login-renewal-certification-20261016.md)。邮件/短信验证码渠道开关在真实签发与渠道发现路径生效，渠道实际投递仍要求配置并启用 `channel_instances`。连续管理员登录失败阈值与封禁分钟数在登录阻断路径生效。邮箱注册仍为当前可用流程，手机独立注册、注册手机号强制验证和图形验证码自动启动没有完整流程，API 明确拒绝将这些开关设为开启，页面不展示无效控件。旧版“注册时选填字段”由客户自定义字段模块维护，不复制到此页。

迁移128记录MFA登录挑战所用方式，旧挑战安全失效；完成挑战复核该方式当前策略，确认个人MFA时也复核当前开通策略。后台保存只发送可写字段；按管理员ID在sessionStorage保留未知请求体与幂等键，允许重新进入页面后原请求确认，确定响应后清理。409自动读取最新版本、保留草稿并提示服务端差异。四尺寸和真实保存验收见[集成记录](admin-parallel-acceptance-20261012.md)。
