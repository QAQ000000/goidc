# 外部退款 store 验收（2026-10-16）

新增迁移143，事实表 `external_refunds`；仅 `status='confirmed'` 是独立出款事实。`received_at` 为实际到账时间，`confirmed_at` 为复核时间；原支付成功、账单 paid_at 均保留，不产生余额流水。幂等表 `external_refund_operations`；权限独立注册，未给已有角色自动授权。

在隔离 PG18 的随机 schema 上运行 `scripts/go.sh test ./internal/store -run TestExternalRefund -count=1` 通过，迁移由测试实际执行并清理 schema。覆盖：无会话拒绝、创建/同键重放/异参、申请人自审、并发同键确认、会话撤销后的幂等重放拒绝、已确认事实数据库不可覆写、数据库重复退款约束；确认后的账单版本/状态、原成功收款、零余额及零余额流水有实际断言。另覆盖混合外部收款、信用关联、有效发票申请、导入审核、金额/支付状态不符、未来/早于支付的到账时间、账单版本冲突与失败不留下退款事实。

业务支持严格限于完整合法人工账单项目且无订单/资源、信用/流量/配置变更/佣金与有效发票申请。复杂订单/资源/流量/佣金完整 fixture、发票申请并发竞争及签名通知重放不由此 store 测试证明，需结合 HTTP 集成测试单列。未连接业务库、未调用真实退款或真实资金接口；真实到账与商户闭环仍未验收。

补充审查收尾：登记与复核说明统一最长1000字符，登记说明trim后必填；退款流水/证据引用trim并拒绝控制字符，SHA256正则全局复用。原 `payment_transactions.external_transaction_id` 保存为不可变 `original_transaction_id`，迁移143直接包含该列。

补充隔离PG18通过：真实订单/商品/订单项目/服务fixture，拒绝人工账单项目挂载service及订单关联账单；持有真实invoice-customer锁并插入发票申请时，并发确认等待该事务提交后拒绝，确认出款数仍为零。跨不同账单/原支付重用商户退款流水的数据库唯一保护、原商户流水快照及空说明/控制字符拒绝都有断言。流量/佣金完整fixture仍未单独构造，源码保护存在但不表述为完整端到端证明。

驳回收尾：驳回不出款、不更新账单，因此仅重验会话/权限/客户范围、同账单退款身份、pending版本及非本人审核；维持客户→payment→invoice→refund固定锁序。到账/账单/关联/发票资格仅约束创建与确认。隔离PG18测试证明：登记后并发产生有效发票申请，确认等待并拒绝，但独立驳回成功、同键重放，账单paid/version1与支付succeeded保持不变，出款为零且驳回审计仅一次。

商户唯一性补强：原先 `(provider,channel_instance_id,provider_refund_id)` 仅保证实例内唯一，不能称为商户唯一；现改为 `(merchant_scope,provider_refund_id)`。易支付scope从原支付AES-GCM快照解析APIURL/PID，以scheme/host小写、默认端口省略、路径尾斜杠省略、PID trim规范化后计算SHA256；不包含密钥、不使用当前配置替代历史商户、不按alipay/wxpay或实例拆分。mock使用明确的测试专用稳定scope，未知渠道、缺失/损坏快照拒绝登记及确认，驳回继续可用。不同URL域名实际指向同一商户的身份合并仍需显式商户映射，本次不推断网络别名。

隔离PG18新增实际断言：跨alipay/wxpay、复制渠道实例、大小写/默认443端口/尾斜杠别名均不能复用同退款流水；不同PID或host可使用同流水。缺快照/损坏快照/未知provider登记拒绝；原加密密钥不可用时确认拒绝但独立驳回成功。全部 `TestExternalRefund` 于独立隔离PG18通过（18.734s），未调用任何真实渠道接口。迁移143尚未部署，因此直接修订其表结构。

驳回后补正：商户退款流水唯一索引改为仅约束 `status<>'rejected'` 的pending/confirmed事实；已驳回记录保持不可变历史，允许同真实退款流水以新幂等键提交修正证据。账单/原支付各一条live索引继续保护。测试覆盖原流水登记→独立驳回→同流水新证据重新登记→独立确认一次、旧驳回幂等重放不变、历史两条不覆盖、同账单live重复拒绝与跨账单数据库唯一拒绝。创建幂等键仍重放原创建时快照，补正必须使用新键。

快速流程复核：申请状态不改账单；确认失败回滚不冻结pending；资格变化仍可驳回；驳回记录不可编辑但可新登记补正；确认记录不可覆写，不允许再次产生同商户流水出款。确认后的资金修正仍属专门流程，不在本增量放宽。
