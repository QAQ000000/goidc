# 合同生命周期还原批次

来源：旧规范第18页 `#/contracts_audit`、第38页 `#/contracts_setting`，并核对旧后台/客户 `ContractController.php`。现有合同设置只有总开关；本批补真实合同模板、服务合同实体及客户申请、后台审核、邮寄、作废链路。保留 `/admin/*` 路由，不加载 PHP 插件。

## 页面及关联

`/admin/contract-settings` 保留总开关，新增合同模板管理页签，模板创建/编辑包含名称、正文、启用和版本。正文采用纯文本和有限占位符，不执行用户模板代码或 HTML。

`/admin/contracts` 对齐 ID、客户、产品信息、付款时间、产品状态、合同状态、操作七列。提供关键词、产品/合同状态、日期筛选、分页、真实空态、生成合同、详情/历史、审核、邮寄及批量作废。客户和服务链接保留原后台上下文。

`/console/contracts` 提供客户自己的合同、可申请的已付款服务、模板选择、合同详情、姓名确认提交审核及文档下载。后台不代替客户确认合同。姓名确认不是第三方电子签章服务；PDF/电子签章集成另行列缺口，当前下载转义静态 HTML 可供打印。

## 业务边界

合同关联一个真实已付款且有效的服务；生成时冻结模板正文、客户和服务信息，后续改模板或客户资料不改历史合同。状态为待签订 draft、待审核 pending、已通过 approved、已驳回 rejected、已邮寄 shipped、已作废 void。驳回可重新提交；审核需当前 pending，邮寄需 approved/shipped；作废是终态，批量最多50条，全事务校验。

总开关关闭后禁止新生成/申请及客户提交，历史合同仍能查看并由管理员处理。服务归属、付款资格、管理员客户范围在服务器校验，客户端只能提交引用和确认字段。快递管理记录地址、联系人、电话、承运商和单号，不代表调用第三方物流。

## 安全与一致性

后台合同读取/写入使用 `contracts.view` / `contracts.manage`，模板管理使用 `settings.view` / `settings.manage`。所有写入必须有效会话、事务内复核角色与客户范围；客户接口验证归属。写入带持久幂等键，编辑和状态操作带 `expected_version`，版本冲突409；业务变更、状态历史、审计和幂等回执原子提交。批量作废按稳定ID锁序，冲突不得部分成功。

未知写入响应保留原路径、请求体、幂等键，刷新后重试确认，确认前禁改字段和取消；草稿按账号隔离，只读账号不恢复写入草稿。正文用安全文本渲染，下载 HTML 转义字段并限制为无脚本、无外链内容。
