# 订单与账单详情

原生交易页面初版于2026-10-06部署于schema055；后续schema060/061接入原生支付与查单，schema062增加循环续费权益快照，schema063保存[购买资料](product-purchase-fields.md)，schema064扩展[固定与限次续费](limited-renewal-benefits.md)。订单/服务读取完整资料快照，订单账单仅返回购买时允许账单展示的字段。旧 PHP 与旧数据仅作业务参考。

## 页面与接口

| 页面 | API | 访问范围 |
| --- | --- | --- |
| `/console/orders` | `GET /api/v1/orders/page` | 当前账户订单 |
| `/console/orders/{id}` | `GET /api/v1/orders/{id}` | 当前账户订单 |
| `/console/invoices` | `GET /api/v1/invoices/page` | 当前账户账单 |
| `/console/invoices/{id}` | `GET /api/v1/invoices/{id}` | 当前账户账单 |
| `/admin/invoices` | `GET /api/v1/admin/invoices/page` | `invoices.view` 及客户销售范围 |
| `/admin/invoices/{id}` | `GET /api/v1/admin/invoices/{id}` | `invoices.view` 及客户销售范围 |

原有订单、账单数组列表接口保留。新 `/page` 接口在 `data` 下返回 `{items,total,limit,offset}`；空的末尾页也返回真实总数。计数和项目使用同一只读 Repeatable Read 快照。API 默认 25 条，`limit` 有效范围 1–100，负 `offset` 归零；页面每页 20 条，按 ID 倒序。

订单状态支持 `pending/paid/active/cancelled/refunded`；账单状态支持 `unpaid/paid/cancelled/refunded`。`q` 去除两侧空白，最长 120 字节，非法状态或超长搜索返回 400。订单搜索订单号、历史产品名称，管理员额外搜索客户名称/邮箱；账单搜索账单号、关联订单号、账单项目描述和历史产品名称，管理员额外搜索客户名称/邮箱。

## 交易快照与权限

客户订单详情返回订单金额、优惠码/优惠金额快照、同一客户的关联账单、订单项目及服务。项目使用下单时的产品名称、账期、周期价、初装费、数量、配置和数量快照，修改当前商品或选项不改写历史订单。

客户订单列表和详情均不返回管理员备注、上游资源凭据、请求哈希或旧来源归档。未登录返回 401；访问其他账户详情返回 404。管理员订单备注继续由既有后台接口提供。

账单详情返回保存的 `invoice_items`、同一客户关联订单的 `order_items`、支付意图与余额付款/退款流水。原生购买账单没有独立账单项目时，前端展示订单项目快照，不创建虚构历史；续费和升级账单展示已有账单项目。服务链接只关联同一账单客户的服务。

订单项目保存购买时的续费比例/固定金额、次数上限和代码；续费账单项目额外保存周期原价 `renewal_base_cents`、优惠 `renewal_discount_cents`、权益与该次序号，实付等于原价减优惠。成功付款后消耗一次，退款只返实付且不恢复优惠次数。详情汇总展示实际优惠，不从当前优惠码重算历史。没有购买权益或次数用完的服务保持原价，详见 [循环续费优惠](recurring-promotions.md)。

支付意图和余额流水各最多返回最近 50 条。不返回支付渠道原始结果、幂等键或上游凭据。schema060 新增易支付协议适配、独立渠道流水和客户本人付款链接；后台详情隐藏付款链接。schema061 新增主动查单补结算及最近查询状态/时间，后台操作要求独立 `payments.reconcile` 权限和客户范围。真实商户验收、可信关单/原路退款、自动对账及完整历史分页仍待完成，见 [在线支付](payments.md)。

管理员账单详情使用 Read Committed，取得客户销售范围共享事务锁后重新检查当前归属，并锁定账单头供本次读取。销售转交持有排他锁；等待转交的读取在转交提交后重新校验范围，失去授权返回 404。管理员账单、订单及服务链接分别检查读取权限，仅有 `invoices.view` 的账户不展示退款和无权限资源链接。

## 支付与流程入口

客户余额付款继续使用 `POST /api/v1/invoices/{id}/pay`；模拟支付使用 `/payments` 的 `provider=mock`，页面明确标注模拟支付。配置真实商户后可使用原生易支付跳转；部署实例尚未配置真实商户。已存在模拟待处理意图时禁止再次创建模拟支付单，余额支付仍可用；真实待处理意图按下文限制。数据库账单状态和锁防止重复结算，余额付款后的成功渠道回调拒绝再次付款。

`payment_pending` 仅在账单未付款且存在 `pending` 意图时为真；`real_payment_pending` 进一步要求渠道不是 `mock`，页面据此禁用余额支付。在线意图阻止换渠道、余额支付和取消操作，详情可继续原付款。过期意图仍保留 `pending` 状态及渠道唯一约束，详情单独标记 `expired`；当前没有可信网关关单或安全重新开单流程。详情在未付款待处理时每 3 秒刷新，付款后停止。支付和退款按钮使用稳定幂等键重试。

取消待付款订单和管理员退款均有确认弹窗，操作后重新读取真实状态。管理员退款还需要 `invoices.refund`，继续遵循现有交付/复核约束。

购物车结算成功直接进入返回的订单详情；订单详情可进入账单和服务；服务续费生成账单后直接链接该账单详情；未付款配置/商品升级账单也直接链接详情。
