## 浏览器证据

Playwright 独立 Linux Chrome 检查 10 条路由：`invoice-applications`、`promo-codes`、`reports`、`content`、`downloads`、`customer-files`、`ticket-departments`、`ticket-presets`、`notifications`、`access`，在 1440/1024/390/320 宽度均无全页横向溢出、可见页面异常或 API 失败。报表四个页签、发票 URL 状态/分页、内容取消恢复、管理员取消恢复均已检查。

浏览器路由夹具拦截管理写请求并返回 409：文章和下载保存期间按 Escape 不关闭弹窗；失败后草稿保留。下载文件选择保留在失败状态，取消更改同时清空 React 状态和 DOM file input。客户文件与部门新增表单取消后恢复空初值，未产生写请求。

通知模板夹具验证保存期间返回按钮禁用、409 后保留主题、取消恢复和模拟成功后返回列表。预设回复夹具验证取消恢复以及编辑停用分类中的现有回复时 PATCH 不携带未改变的 `category_id`。首次预设夹具路由未覆盖详情路径，对不存在测试 ID 的请求返回 404，未修改记录；扩大拦截范围后重跑成功，失败尝试不计通过。其余上述写请求均未到达业务 API，不能视为真实保存成功。开票审核和权限修改没有提交真实写入，标记为未验证。

文章弹窗最初在 320px 存在内部横向溢出，修正底部按钮组换行后，在四种宽度重跑通过；最终 320px `scrollWidth=clientWidth=286`。最终手机文章操作区与桌面通知列表截图已目视检查，无文字遮挡。截图：`output/playwright/mf-batch3-article-actions-mobile.png`、`mf-batch3-notifications-desktop.png`。
