# 循环续费优惠

Go 原生权益模型，schema062引入百分比权益，schema064增加[固定金额与限次续费](limited-renewal-benefits.md)。旧PHP的循环字段仅作业务参考，不推断历史购买的权益，不读取旧数据或密钥。以下百分比基础契约继续适用，限次计数、固定减免和升级行为见上述扩展。

## 购买与权益

管理员创建百分比或固定金额优惠码时可设置 `recurring: true`，百分比是减免比例，例如 `value: 10` 表示减免10%，不是一折；固定金额以分计。免初装费的循环请求明确拒绝。`recurring_limit`可限定每件服务优惠续费次数，0为不限。后台仍使用 `promos.view/manage`，客户不能创建或修改优惠码。

购物车显示本次优惠及循环提示；结算根据实际所选项目重新检查优惠码有效期、状态、商品/账期范围、前置商品、客户类型、使用次数和商品版本。每个符合范围的月/季/年购买项目保存比例或固定金额、次数上限和代码，同一项目购买多件时，每件服务独立获得相同权益；一次性商品只享受首次购买优惠。不符合范围和未选中的项目不会获得权益。

核销、订单项目、服务权益、库存和审计在同一事务内提交；同一结算幂等请求不重复核销。历史订单及已有服务默认为0%，事后修改优惠码不会追溯发放。停用、过期、使用次数耗尽以及发码规则变化只阻止新购买，已经购买的服务保留权益。

## 续费与变更

`services.recurring_price_cents` 仍表示当前有效服务合同的周期原价，权益单独保存。API额外返回 `renewal_amount_cents`，页面同时显示优惠后金额、原价、代码、减免规则和次数状态。

手动与余额自动续费共用 `CreateRenewalInvoice`。百分比按当前周期原价乘比例向下取整到分，公式采用除法/余数分解避免 bigint 乘法溢出；固定优惠最多减至零元。没有权益或次数用完的服务按原价续费；零元账单通过正常付款状态机延长到期时间并消耗一次优惠，不扣余额。

续费不重新核销、不增加优惠码使用次数、不重新执行新客户或首次使用条件。账单项目保存 `renewal_base_cents`、`renewal_discount_cents`、`renewal_discount_percent` 和 `renewal_promo_code`，账单实付金额等于原价减优惠。数据库检查约束保护计算一致性；账单创建和审计原子提交。已有未付续费单阻止新单，幂等重放返回原单。

权益绑定实际购入的服务，配置、账期、跨商品变更交付后仍保留，并按变更后的周期原价计算下一次续费。变更应付差价及降配余额返还继续按周期原价计算，不使用续费优惠。页面明确说明此规则；这是原生产品契约，不承诺与旧 PHP 所有循环/升级规则完全相同。

余额续费退款返还原账单实际支付金额，权益快照和历史计算保留，已用优惠次数不恢复；不会按未优惠原价返还。外部付款仍遵循在线支付契约，未实现可靠原路退款。

## 接口与页面

沿用现有端点，不增加权限或后台路由：

- `POST /api/v1/admin/promo-codes`：支持百分比/固定金额循环开关和 `recurring_limit`。
- `GET /api/v1/cart`：优惠报价包含 `recurring/recurring_limit`。
- 订单详情：项目增加购买时的续费权益。
- 客户/管理员服务列表、详情：增加权益代码、比例和优惠后续费金额。
- 客户/管理员账单详情：返回续费原价、优惠及权益快照，账单优惠汇总展示代码和金额。
- `POST /api/v1/services/{id}/renew`：按保存的权益创建续费账单。

后台 `/admin/promo-codes` 可创建、查看和停用；客户 `/cart`、订单详情、服务详情、账单详情显示对应权益和计算。只读管理员保留查看能力，管理按钮继续受权限保护。

## 验证与未完成范围

隔离PG18专项覆盖范围/账期/一次性/部分结算、多件服务、历史不追溯、规则变化后的手动与自动续费、实付退款、零元付款、审计失败回滚、并发幂等、整数边界及配置/商品/账期交付后保留。

最终部署和浏览器验收记录见 [重构台账](reconstruction.md)。不配置真实商户，不把模拟资源交付和隔离余额付款视为真实资金/供应商验收。循环权益人工撤销或编辑、升级专用优惠、客户分组叠加、多币种及真实外部支付退款仍待实现。

## 部署恢复边界

迁移添加带默认值的权益字段，不补发历史权益；schema064统计已结算百分比续费次数，金额及不限次数规则保持不变。各批备份包含对应升级前数据库、实际旧二进制、环境配置及旧前端构建；在独立 `_test` 库恢复旧结构/旧API，再升级检查新API和既有业务摘要。

数据库结构允许旧二进制启动，但旧二进制不认识循环权益，会按原价续费。因此发放任何新权益后禁止只降级API/worker。发布失败的自动恢复先检查是否已有权益：只有仍无权益时恢复旧二进制；有权益则保留新版并报告恢复拒绝。后续整库恢复需停止业务写入并处理备份之后的真实交易，不应直接覆盖。
