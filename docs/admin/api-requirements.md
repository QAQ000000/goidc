# 后台 API 需求取舍

本文维护后台全域的需求范围和实施顺序；[API 契约](api.md)说明协议及已经落地的新接口。受控声明源是 [`audit/admin-api-requirements.json`](../../audit/admin-api-requirements.json)。声明不是运行证据，也不是把旧系统接口逐个复制到 Go 的任务表。

## 判定方法

逐领域核对旧规范章节、旧路由/控制器、当前注册路由和当前页面消费者，再区分业务缺口、接口缺口、前端接线与验证缺口。声明记录代表性的旧路由、handler 和源码行，以及现有 API 入口；完整当前/旧路由和页面消费候选由脚本生成，不在活动文档重复展开。

声明中的 `required` 表示当前批准范围内是否必需；`disposition` 独立表示复用、优化、新增、排除、待决策。另分别维护 API、UI 和验证状态：有 API 不等于页面接入，页面显示不等于权限/并发/外部链路验收通过。

当前声明按 **30 个领域、54 个需求组**组织。它们是功能范围分组，不是 54 个已逐动作验证的操作。扫描发现的 **105 个实际后台页面**均归属需求组；旧台账同样有 105 条，但其中含共享页面和 query 子视图，两者不能按数量视为一一对应。旧 `/admin/logs/system` 可由当前 `/admin/logs/[kind]` 提供，不能因为缺少同名目录判定 API 缺失。

| 需求处置 | 功能组数 | 实施含义 |
| --- | ---: | --- |
| 复用 | 22 | 使用既有领域接口，按页面动作核对接线与证据 |
| 优化 | 14 | 改进查询、上下文、并发恢复或验收，具体剩余工作见下表 |
| 新增 | 3 | 客户摘要、客户通知/活动历史、管理员自动续费设置；本轮后端已实现，UI待接 |
| 待决策 | 9 | 业务范围或协议未冻结，不允许前端自行补写 |
| 排除 | 6 | 维持已确认的产品与安全边界 |

上述处置分类不等于完成状态；例如“优化”可能是后端已具备、前端未接线，也可能仍需进一步核实具体动作。

生成器的页面依赖是**文件级候选可达**：递归本地 import、reexport、字面量 dynamic import，提取 `api`、`useResource`、`upload` 和 `download`。共享组件文件里的其他 export、客户端逻辑或未渲染分支也可能被关联到页面，不能把候选请求当成该页确定执行的操作。变量路径、动态方法和无法解析的依赖保留表达式与未知状态；动态路径命中的是候选，不会自动标为已覆盖。

## 全领域取舍

表中 API 为代表入口，路径省略 `/api/v1`；完整注册、权限与源码位置以生成 inventory 为准。页面接入、API 实现和运行证据继续独立判断。

| 领域 | 复用入口及当前能力 | 需实现或优化 | 排除或待决策 |
| --- | --- | --- | --- |
| 控制台 | `GET /admin/dashboard`、已有经营卡片 | 商品/人员销售排名当前占位；先确定期间、退款、件数/订单数和销售归属 | 排名口径未定前不提供假统计 |
| 客户档案与列表 | 客户列表、创建、详情、状态、联系人、销售归属 | 真实摘要、固定客户的关联列表与创建上下文、版本冲突、稳定充值重试 | 不物理删除客户及财务历史 |
| 客户分组与等级 | 分组、等级、组折扣、优惠券分组适用规则 | 客户详情接入已有分组修改 | 不新建第二套等级/折扣引擎 |

| 商品与分类 | 商品、分类、配置项、多账期、规格、服务导航 | 旧十页签逐项映射，明确已有独立领域的复用 | 试用及其余旧配置先确认需求 |

| 账单与支付 | 人工账单、收款、退款、对账与关单核验 | 创建读取预选客户；版本/幂等及历史分页一致性 | 无可信渠道协议时不自动宣称退款到账或关单 |
| 发票申请 | 审核、调整、业务文件上传与下载 | 核对所属客户、审核状态和冲突恢复 | 不因移除导出删除发票文件 |

| 营销与优惠券 | 活动受众预览、投递及客户组优惠券 | 过滤/分页和分组叠加规则一致性 | 未选客户组的旧券不自动叠加分组折扣 |
| 推广 | 资格、链接、佣金、提现审核、打款证据 | 客户详情按固定客户复用 | 不新建第二套佣金台账 |
| 销售 | 设置、预计佣金、历史确认结算 | 人员/期间/条件和历史明细核对 | 预计与确认不相加，不称为已发放；正式确认沿用现有范围 |
| 报表 | 收入/业绩/工单/新客户/排名/商品报表、费用台账 | 已恢复明细、评分、分类及分页的真实 Go/浏览器/旧数据对账证据 | 通用数据导出排除；未记录全部成本不称利润 |
| 合同 | 模板、提交、审核、寄送、作废和 HTML 打印 | 按当前状态机与权限复核 | PDF/e-sign、产品绑定、强制签约、逾期政策和取消寄送待定 |
| 实名认证 | 人工及编译提供方、资格与转企业流程 | UI 真实状态及未知结果语义一致性 | 真实外部提供方结果另验 |
| 员工与安全 | 角色/权限/资源范围、MFA、分入口账号和 API key | 员工详情及撤权边界复核 | 手机独立注册、动作级二次认证、员工签名/通知偏好待定 |
| 内容与文件导航 | 内容、下载、文件分类、产品绑定、导航、友情链接 | 私有下载和编辑权限一致性 | 保留业务下载，不恢复 CSV 等数据导出 |
| 站点与主题 | 站点设置、公开主题、自定义字段 | 对照当前代码消除旧配置差距说明 | 不恢复运行时任意写配置 |
| 调度与队列 | jobs、queue、scheduler-settings、执行日志和 `/admin/logs/jobs/trend` | 按租约、执行事实、审计和安全重试验收 | 趋势 API 已存在，不重复列为缺失 |
| 审计与日志 | audit、登录/API/通知/任务日志、动态日志页；本轮补精确客户 subject 筛选 | UI 待接；客户 subject 与管理员 actor 分离 | 时间戳近似关联不充当精确客户筛选 |
| 运行状态与模块 | runtime/database/about/upgrade、编译模块目录 | 按 API/worker/数据库及实际构建清单核对 | 运行时插件上传安装排除；PHP 环境页不原样迁移 |
| 迁移 | runs/reviews、映射、冻结和回退 | 来源、冲突及旧业务对账逐项验收 | 外部库可读和静态路由不等于真实切换通过 |

上述各领域的旧规范章节和代表旧路由证据都登记在声明源的 `legacy` 中。旧控制器路由归属只用于定位旧行为，不自动认定新旧接口语义相同；例如旧 `user_manage` 同时包含客户列表、分组与资源操作，必须继续按具体业务动作核实。

## 本轮落地与下一批边界

### 已落地的代码与盘点

- 真实注册路由采集：Go AST 扫描生产 HTTP 注册源码，保留包装器、handler、权限来源及行号；旧版路由保留 `ANY/RULE`、动态目标及未解析 include，不猜测展开。
- 后台消费者采集：发现实际页面，递归源码依赖，识别导入别名、reexport、namespace、字面量动态导入、模板路径和方法备选，未知情况显式保留。
- 需求声明：30 个领域及 54 个功能组分别记录当前代表 API、旧规范/路由来源、复用/优化/新增/排除/待定、UI/API/验证轴。新增稳定证据路径和声明端点均与当前仓库校验。
- 客户真实摘要 `GET /api/v1/admin/customers/{id}/summary` 已实现；各 section 根据调用者权限及客户范围返回真实数据或明确的不可用状态。精确协议与测试入口见 [API 契约](api.md)。**客户详情 UI 尚未接入**，新增 API 不能消除当前页面假零值。
- 信用消费与还款已纳入现有交易事件分页和汇总；信用消费属于非现金，信用还款按 `received_at` 计真实到账，并排除同账单的 fallback 重复记录。新来源和现金字段的 UI 展示待接。
- 通知/审计日志已增加精确 `customer_id`；统一通知新增 `GET /admin/notification-deliveries/page`，覆盖目录11类业务事件的 email/sms/inbox/Telegram/Web Push，支持客户、事件、渠道、投影状态、上海期间及分页。工单/营销仍走独立日志；无法证明归属的旧消息不猜测匹配。管理员自动续费设置新增专属 `PATCH /admin/services/{id}/auto-renew`。这些 UI 均待接，不通过普通客户身份完成后台管理。
- 关联列表及订单/账单/工单创建客户选项已统一精确 `customer_id`，非法不回退全局，范围外404，最终数据查询保留范围约束；包括续费/供应商读取。资源服务视图增加精确客户/商品筛选及商品名称/到期时间；商品分组新增分页并保留数组兼容，配置备注仅管理端读写。涉及的HTTP持久化移入Store，架构豁免仅删除，不重建基线。
- 工单带key附件上传新增持久业务意图、原子成功回执及授权结果查询；已有意图未确认禁止再次Put，底层存储journal继续围栏。原UI尚未接入新上传恢复协议，无key兼容不等于幂等；不能把这项API完成写成附件交互已闭环。详细字段、错误和前端接线要求见[API契约](api.md)。

### 优先接线和闭环

| 顺序 | 任务 | 当前边界与完成判据 |
| --- | --- | --- |
| 1 | 客户摘要真实展示 | 接入 summary；认证、邮箱、末次登录、推荐人、服务组、工单/财务/到期指标均有真实来源。无权 section 明示无权限，空事实与不可用分开 |
| 2 | 客户修改与充值恢复 | 状态提交携带 `expected_version`；同一充值意图保持原 key，未知结果先核验；刷新不丢草稿，不从新 key 推断重试安全 |
| 3 | 客户上下文关联与创建 | 后端精确筛选与预选客户已补齐；UI接入时固定客户与返回路径，分组/销售归属/重置密码复用现有API，不以姓名检索代替归属 |
| 4 | 客户通知与活动历史 | 后端精确 `customer_id` 已落实，UI 接入分页及既有筛选；审计管理员 actor 和客户 subject 分开；不得返回秘密或原始外部响应 |
| 5 | 服务设置和信用流水 UI | 接入管理员自动续费专属 API；呈现信用消费/还款来源及现金汇总，不能把消费与还款相加当收入 |
| 6 | 其余优化与业务决策 | 按上表核对具体动作和证据；排名、信用扩展、合同 PDF/e-sign、自动流量交付等先确认业务口径，再设计状态机和接口 |

附件UI接线另需：首次上传前保存稳定key和文件意图；断网或未知结果先调用结果查询，工单/回复成功与附件未确认分开展示，不生成新key绕过未确认围栏。资源/分组新筛选及配置备注也只完成本批API与测试，现有页面未自动接入。

当前 [客户详情组件](../../web/src/components/admin-customer-detail.tsx) 仍有认证/邮箱固定状态、工单/财务占位计数、硬编码服务分组、缺少固定客户的跳转以及禁用的分组/销售入口。这些属于明确的前端工作，不能因为后端有列表或汇总接口就标记完成。

## 明确不恢复

1. 报表和通用数据导出；工单附件、合同和发票等业务下载保留。
2. 客户退款/停用申请状态机；客户走工单，管理员经原账单或服务处置。
3. 管理员普通购物身份、URL 传会话/密钥；只允许显式、受控、可审计的代登录。
4. 客户与财务历史物理删除；运行时插件上传安装。
5. 忽略未知外部结果的通用重试；无可信渠道能力时自动退款/关单及假成功按钮。

这些是范围决策，不能在旧版差距数量中反复统计为待补 API。

旧服务 `ClientsServices::postInfo/postTransfer/hostRenew/postBatchRenew` 另登记为 `services.legacy-manual-management`（待决策，`required=false`）。管理员自动续费 API 只改变开关，不执行立即收款或续期，也未实现任意改价、改期限、改状态及转移客户。未来若恢复，须先冻结版本、资金与权益、未决外部任务、审计、幂等和失败恢复；不能采用旧转移流程删除未付账单后直接改归属。

## 复现与证据限制

```bash
node --test scripts/admin-api-inventory.test.mjs scripts/admin-api-consumers.test.mjs
node scripts/admin-api-inventory.mjs --legacy-root "$GOIDC_LEGACY_ROOT"
node scripts/admin-api-consumers.mjs
node scripts/check-doc-governance.mjs
node scripts/check-doc-links.mjs
```

运行前将 `GOIDC_LEGACY_ROOT` 设置为实际可读的旧源码目录，并通过 `--legacy-root` 显式传给 inventory；脚本本身不读取该环境变量，也不猜测默认旧目录。消费者扫描仅需当前仓库。生成结果仅写入被忽略的 `output/audit/admin-api-inventory.{json,md}` 和 `output/audit/admin-api-consumers.{json,md}`。共享文件导致的候选关联、未解析路径/方法、未解析依赖分别保留，不作为缺失接口计数或完成率。

声明 `verification` 记录该声明维护流程的证据边界，不保存 PASS 运行快照；测试函数和命令可作为入口登记。扫描器及其夹具只能证明静态采集/匹配行为。本批精确客户上下文、创建选项、资源/分组分页、配置备注和附件上传恢复已完成隔离PG18 race验证，逐入口和分组证据边界见[API契约](api.md#契约验证与前端交付)。API实现、页面接线和验证仍分轴维护；未执行的新UI浏览器、真实通知/对象存储/其他外部渠道、部署和旧全量迁移均不得宣称通过。旧105条台账与浏览器截图只保留其原有历史范围。
