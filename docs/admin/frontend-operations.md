# 后台财务、支持与运营页面设计

状态：前端实施设计，规定需要的页面、排版、组件和交互；不表示页面已按本文改造、浏览器验收或上线。业务事实以代码、迁移和测试为准，字段与写入协议以[后台 API](api.md)及各领域契约为准。

本文承接[后台公共设计规范](../admin-frontend-design.md)。公共壳、字号、间距、状态色、抽屉焦点、加载/空/错误状态和响应式断点直接复用，不再创建一套视觉系统。所有路径为后台页面；下文 API 省略 `/api/v1` 前缀。

## 页面范围与公共交互

| 分区 | 必需页面及页内视图 |
| --- | --- |
| 账务 | 账单列表、新建、详情、编辑；交易流水；发票申请列表与详情 |
| 营销财务 | 销售结算及预览/详情；优惠码及新增/编辑；推广账户/归因/提现与推广设置 |
| 客服 | 工单列表、新建、详情；部门、状态、传递规则、预设回复 |
| 通知 | 统一通知中心、邮件/短信模板与队列、新增模板；渠道配置；营销活动及编辑/查看 |
| 报表 | 收入、客户、产品、每日运营、我的业绩、工单统计六类，附各自子视图 |

范围排除信用额度、合同及其页签；不恢复数据导出、经营建议生成、自动网关退款。电子发票、工单附件等业务文件继续授权下载。新增机器人不是新增一套通知业务，按统一通知目录和渠道能力呈现。

- 页头统一为面包屑、标题/口径、次要刷新、主要动作；筛选置于表格前，主动作不得藏入行菜单。
- 搜索草稿与已应用条件分开，查询/重置/页大小变化回第一页；筛选、页签、页码写 URL，详情返回恢复来源。只编码已冻结的 API 参数，不能给前端筛选制造不存在的服务端总数。
- 列表、汇总、选项目录和详情分区独立加载与重试；无权限、尚未加载、未知、`null` 与真实零分开。旧对象的迟到响应不能覆盖新对象或新身份。
- 所有金融展示用整数分来源，百分比明确单位；日期注明北京时间或对应领域时区。历史快照与当前资料分别标记，不拿现价重算历史。
- 写入发送 API 明确要求的版本/幂等字段；同一意图保留原 body/key。未知结果显示待确认，按本动作协议恢复，不换 key、不自动重新提交。
- 409 保留草稿并显示冲突原因；有原回执的先恢复结果，再决定是否加载最新版本。无回执的旧接口只能读取并人工核对，不能承诺安全重放。
- 写入成功清理该动作草稿，刷新受影响的详情、列表与汇总；排队成功只显示已排队，待核验不显示完成。401/403/404 不证明旧请求没有执行。
- 手机按 390/320px 验收：筛选折叠、表单单列、操作栏换行；表格在自己的容器滚动，不让整页横向溢出。金融明细不能因小屏隐藏金额或状态。

## 账单与资金

### `/admin/invoices`：账单列表

- 目标：定位应收、付款及异常账单；入口为财务导航或客户详情，进入详情后返回原列表。
- 桌面：页头右侧“创建账单”；第二行状态标签，第三行搜索/精确客户筛选；主体表格与底部分页。不把列表做成大型付款表单。
- 主列：账单号、客户、来源/项目摘要、应收金额、状态、到期时间、付款时间、操作；导入待复核和支付未决独立徽标，不混成账单状态。
- 组件：`AdminStatusTabs`、搜索框、客户选择器、金额文本、状态徽标、`AdminPagination`、局部 `Failure`。
- API：`GET /admin/invoices/page`；读取 `invoices.view`，客户范围按后端；新建还需 `invoices.manage`。只有实际可见的关联对象提供链接。
- 交互：账单号进入详情；创建进入 `/new`。列表不提供跨客户“一键退款”；筛选无结果与全库无记录给不同说明。
- 手机：账单号/金额/状态优先显示，其他信息可在行内展开；保留表格容器滚动和可访问的详情按钮。

### `/admin/invoices/new`：人工账单创建

- 目标：创建独立应收，入口为账单列表或固定客户上下文，成功进入新账单详情；取消回来源。
- 桌面：最大内容宽度内上方客户/到期信息，中部项目明细编辑器，下方备注与金额合计，页尾保存/取消。右侧可放只读应收摘要，不常驻营销统计。
- 表单：授权客户搜索选择、到期时间、项目描述及整数分金额、增加/移除项目；允许负优惠行，总额合法范围遵循[人工账单](../manual-invoices.md)。固定客户入口锁定归属。
- 组件：异步客户 Combobox、日期输入、行编辑器、金额输入、校验摘要、草稿离开确认、提交按钮。
- API：`GET /admin/invoice-customers` → `POST /admin/invoices`；`invoices.view` + `invoices.manage`，稳定 `Idempotency-Key`。
- 交互：取消不写入；失败保留项目。超时保留原请求重试确认；成功显示应收单创建，不宣称收款、开通或服务创建。
- 手机：每个项目变成描述/金额纵向组，合计紧邻保存区；删除按钮有项目名称，无小型裸图标。

### `/admin/invoices/[id]`：账单详情与受控财务操作

- 目标：查看不可变应收与资金事实并处理允许的动作；入口来自账单、订单、服务、客户，返回保持原上下文。
- 桌面：页头账单号/状态/金额；正文左 2/3 为项目快照、关联订单/服务、付款与余额流水，右 1/3 为到期/客户/来源与允许动作。支付异常、外退及人工收款各自独立分区。
- 组件：定义列表、明细表、支付意图卡、资金来源徽标、版本化确认 Dialog、证据表单、状态时间线、可下载业务文件行。
- API：`GET /admin/invoices/{id}`；`invoices.view`。人工编辑/作废需 `invoices.manage`，钱包退款需 `invoices.refund`，主动查单需 `payments.reconcile`；外退读取/登记/复核分别用 `external_refunds.view/create/review`。
- 动作：只有符合来源和状态的账单显示编辑、作废、退款；退款明确是钱包退款还是外部退款证据，不用含糊“原路退回”。未决支付与导入复核显示阻断原因。
- 支付区：后台隐藏客户付款 URL；未知关单与异常到账按[关单契约](../payment-close-unlock-contract.md)、[异常处置](../payment-exception-resolution-contract.md)展开，只有渠道声明支持时才显示关单。
- 外退区：登记实际发生的凭据、金额、时间及原因，独立确认/拒绝；按[外退冲正](../external-refund-reversal-contract.md)及各账单来源契约处理，不能用按钮伪造网关请求或税务服务。
- 交互：确认弹窗列出账单/客户/金额/影响与版本；成功刷新详情、资金和关联业务状态。外部未知结果持续提示待核验，不自动解锁付款或重复退款。
- 手机：摘要→异常提示→项目→资金→操作单列；高风险确认显示完整金额和对象，底部按钮避开遮挡。

### `/admin/invoices/[id]/edit`：人工账单编辑

- 目标：修改符合条件的人工应收；从详情进入，保存或取消返回同一详情。
- 桌面：复用新建项目编辑器，客户/来源只读，标题明确编辑对象；到期、项目、备注分区，页尾新总额/保存/取消。
- API：`GET /admin/invoices/{id}` → `PUT /admin/invoices/{id}`，`invoices.view/manage`；发送该账单 `expected_version` 与稳定 key。
- 交互：未付、无待处理支付、无需导入复核才开放；不满足时解释原因并链接详情。409 显示最新状态入口，保留旧草稿供比对，不自动覆盖。
- 未知：用原 body/key 恢复；页面重载不能直接采用新版本提交旧草稿。成功刷新详情及列表，不虚构金额更新历史。
- 手机：与新建共用单列表单、可读金额和离开确认；不开放客户改归属。

### `/admin/transactions`：统一交易流水

- 目标：追溯现金与钱包事件；入口为财务或固定客户，相关账单链接返回本筛选。
- 桌面：类型标签与搜索；高级筛选含客户、上海起止日、方向、渠道、金额区间；中部现金汇总，底部流水表与分页。汇总不受当前页限制。
- 主列：客户、发生时间、渠道、描述/账单、金额/方向、当前销售、外部流水号、类型/来源、账单入口；余额变化与外部现金用不同标签。
- API：`GET /admin/transactions/page` + `/summary`，`invoices.view`；字段与期间见[统一交易](api.md#统一交易分页)。客户链接另需 `customers.view`。
- 组件：高级筛选折叠、整数分范围输入、来源徽标、独立汇总状态、可复制脱敏流水号、分页。
- 交互：现金、人工线下、退款和钱包内转分别展示；summary失败不遮表格，列表失败不把卡片清零。人工加余额不能显示外部到账。
- 手机：筛选抽屉与单列汇总；每条保留时间、金额、渠道/来源及账单入口，不加导出。

### `/admin/invoice-applications`：税务发票申请列表

- 目标：找到待审核及已处理申请，入口为财务；与应收账单独立命名。
- 桌面：页头和状态筛选、申请表格、分页；主列为申请编号、客户、抬头、金额、状态、提交时间、详情。当前列表API未提供文件状态，电子文件在详情展示，不逐行追加详情请求。
- API：`GET /admin/invoice-applications`，`invoice_applications.view` + 客户范围；分页与状态按[发票契约](../invoice-applications.md)。
- 组件：状态标签、金额、分页与空态；列表不直接弹出可无确认批准的快捷按钮。
- 交互：详情处理后返回保留筛选；筛选变更回到第一页，当前筛选为空时可切回全部状态，不伪造零元申请。
- 手机：编号/抬头/金额/状态为首屏信息，详情按钮带对象名；其余列允许容器滚动。

### `/admin/invoice-applications/[id]`：审核、电子文件与调整

- 目标：核对提交快照、人工登记开具/驳回及已开具调整；返回申请列表原条件。
- 桌面：页头申请状态与总额；左侧抬头/地址快照、关联已付账单和审核/调整时间线；右侧显示摘要与审核/调整操作；电子文件上传及授权下载位于文件卡。
- 表单：驳回原因，实际发票编号、快递信息与备注；已开具后可按协议登记作废或红冲，红冲需真实红字号码。文件为 PDF/XML、20 MiB 内。
- API：`GET .../{id}`、`POST .../{id}/review`、`/adjust`、`/document` 与 `/adjustments/{adjustment_id}/document`；写需 `invoice_applications.manage`，版本和稳定 key 按契约。
- 组件：快照 DefinitionList、关联账单表、审核 RadioGroup、证据表单、业务文件上传/下载、确认 Dialog。
- 交互：明确“人工登记，未接税务服务”；终态不可重复审核。上传成功刷新文件元数据，下载走授权接口；上传未知先核对文件事实，不重复新增。
- 手机：快照→账单→历史→操作，表单单列；不因小屏隐藏驳回理由或调整记录。

## 销售、优惠与推广

### `/admin/sales-settlements`：销售佣金正式确认

- 目标：预览并确认已结束月份的新购佣金、追踪冲正；入口为销售/财务，详情作为页内 `detail` 状态返回列表。
- 桌面：顶部结算表单（月、最多100个订单 ID）；预览区三卡确认/冲正/净佣金及订单明细；下方分页结算记录，选中记录展示独立只读详情。
- 主列：结算编号、月份、确认佣金、冲正、净额、状态、确认时间；明细列订单/客户、历史销售、基数、费率/阶梯、佣金、到账、冲正状态。
- API：`POST /admin/sales-settlements/preview`、`POST /admin/sales-settlements`、`GET /admin/sales-settlements[/{id}]`；读/预览 `sales.view`，确认 `sales.manage` 且全部客户范围。
- 组件：月份输入、订单清单输入、预览表、金额摘要、确认弹窗、历史快照标签、分页。
- 交互：修改清单废弃预览；确认绑定 `preview_digest` 与原 key，409重新预览；未知冻结原意图并恢复确认。成功刷新详情和记录，不显示“已发工资”。
- 边界：正式确认保持新购范围；预计续费/升级不在这里确认，历史快照不随规则改写；详见[报表恢复](../report-restoration-contract.md#金额提成与归属)。
- 手机：表单单列、摘要卡换行、订单明细容器滚动，确认弹窗完整展示月份/条数/金额。

### `/admin/promo-codes`：优惠码

- 目标：搜索优惠、管理期限与适用客户组；新增/编辑为本页抽屉或 Dialog，取消返回原列表。
- 桌面：状态标签+搜索+新增；九列为 ID、优惠码、类型、价值、循环优惠、已用/上限、开始、失效、操作；服务器状态徽标附于代码区。
- 表单：新增包含经济条款、次数、日期、适用条件与客户组；编辑仅开放当前 API 可改字段，其余只读。客户组规则见[分组定价](../domain/customer-group-pricing.md)，不沿用旧快照的字段位置。
- API：`GET /admin/promo-codes/page`、`POST /admin/promo-codes`、`PATCH /admin/promo-codes/{id}`；`promos.view/manage`，版本和稳定 key。
- 组件：状态筛选、日期时间控件、百分比/金额切换、客户组多选、循环说明、抽屉与校验摘要。
- 交互：状态由服务端判定；日期清空显式 null。留空客户组为所有客户但不叠加分组优惠；明确指定组仅这些组可用并折上折，提交前可读解释。
- 恢复：409保留草稿，读取最新记录后人工核对；未知使用原请求，不自动换日期/版本。成功关闭编辑并刷新当前筛选，丢弃草稿需确认。
- 手机：九列表格局部滚动，抽屉改全宽单列；循环不限、最大次数0和无期限用文字说明，遵循[优惠码契约](../promo-code-restoration-contract.md)。

### `/admin/affiliate`：推广账户、归因与提现

- 目标：审核推广账户、核对归因和提现；三个页内标签共享来源 URL，不混成客户钱包。
- 桌面：账户/归因/提现标签及搜索状态栏；账户表显示客户、状态、佣金分桶及时间；归因表显示推广人/被推荐人/状态；提现表显示申请、金额/费用、状态、申请/处理时间。
- 页内详情：提现审核和打款分开 Dialog；左侧申请与资金分桶、右侧审核原因或实际打款证据。完整收款目标仅授权人员说明原因后临时读取。
- API：`GET /admin/affiliate/accounts/page`、`/attributions/page`、`/withdrawals/page`、`/withdrawals/{id}`；读取 `affiliates.view`。账户状态 `affiliates.manage`，提现审核 `affiliates.withdrawals.review`，打款及敏感目标 `affiliates.payout`。
- 写入：`POST .../accounts/{id}/status`、`.../withdrawals/{id}/review`、`/payout`；版本、稳定key与状态按[推广契约](../affiliate-core.md)及实际接口。
- 交互：仅加载当前页签必要数据；pending_count为后端口径，不能拿当前页计算。审核通过不等于打款；打款登记不伪造银行回执，成功刷新列表、详情及分桶。
- 范围：客户上下文传精确 `customer_id`，归因另用 `customer_role`；越界推荐人字段 null显示“不可见”，不补全姓名；推荐人变更在客户详情专属动作完成。
- 未知/手机：原请求恢复仅适用于该端点协议；未知不得再打一笔。手机详情单列，目标凭据不进入持久草稿/URL/日志，离开即清除。

### `/admin/affiliate/settings`：计划与返佣规则

- 目标：维护未来计佣规则，不重算既有佣金；由推广页设置入口进入并返回推广工作台。
- 桌面：默认计划与商品/阶梯两个标签；默认计划分基本开关/归因期/冻结期、提现阈值/费用、四事件默认规则；规则页是商品覆盖表与月营业额区间编辑器。
- API：`GET/PUT /admin/affiliate/policy`；`GET/PUT /admin/affiliate/rules` 与 `GET .../schema`；规则读 `affiliates.view`，计划读取及写入按实际 `affiliates.manage` 门禁，不能仅因页面可读显示默认计划。
- 组件：FormSection、四事件规则行、商品选择、继承/禁用/比例/固定 Select、区间表、版本标识、保存/取消。
- 交互：基点与百分比转换明确；阶梯下闭上开，重叠预校验；规则完整数组提交，空数组确实清空，须确认。金额单位和最大值依[规则 API](../affiliate-rules-api.md)。
- 版本：计划与规则共享版本，保存成功刷新另一分区；任一分区未知锁定关联写入，重放原请求。409保留草稿，显示新版本差异，不静默整组替换。
- 手机：商品/事件一条卡片、区间上下限纵向排列；保存区同时显示影响未来业务及未保存状态。

## 工单与客服配置

### `/admin/tickets`：工单列表

- 目标：从授权部门定位待处理问题；入口为支持导航或固定客户，返回保留状态、部门和页码。
- 桌面：页头“开启工单”，状态/部门等实际支持筛选和搜索；主表工单号、标题、客户、部门、处理人、优先级、状态、提交、更新；底部分页。
- API：`GET /admin/tickets/page`、`GET /admin/ticket-departments`；`tickets.view` + 客户/部门范围。创建入口另需 `tickets.manage`。
- 组件：搜索、部门选择、状态徽标、未分派文字、分页、合并来源提示；不把合并来源从历史创建量删除。
- 交互：标题进入详情；无范围不显示其他部门客户信息；空态不等于无权限。只读用户正常看公开内容和被授权历史，不提供可编辑假表单。
- 手机：工单号/主题/状态/更新时间优先，客户和部门折行，不能把“关闭”缩成无标签图标。

### `/admin/tickets/new`：管理员代建工单

- 目标：以真实管理员身份给指定客户建立公开问题；成功到详情，取消返回来源。
- 桌面：左侧客户/部门/服务/处理人/优先级关系表单，右侧标题/公开正文/抄送邮箱/初始邮件/附件；窄屏恢复阅读顺序。
- API：`GET /admin/tickets/create-options` 按 `kind` 获取授权选项，`POST /admin/tickets`；`tickets.manage`。固定客户入口锁归属；客户改变清空旧服务和处理人。
- 组件：异步分页 Combobox、正文 Textarea、邮件说明、文件选择、草稿与确认反馈；选择器失败单独重试，不能凭手写编号绕过校验。
- 创建：稳定key重放；服务与客户/部门需重新核验。邮件状态分别显示 queued/skipped，工单创建不依赖实际收件；抄送不自动订阅未来回复。
- 附件：创建成功后 `POST /tickets/{id}/attachments` 独立上传，10 MiB内；失败显示“工单已创建，附件待处理”。首次上传保存稳定key及原文件指纹，未知按下述附件恢复协议查询，不自动再次上传、不重建工单。
- 手机：关系→内容→附件→提交单列，附件状态可见；未知创建时冻结原请求，保留恢复按钮与已创建对象入口。

### `/admin/tickets/[id]`：对话与处理工作区

- 目标：明确区分公开回复、内部协作、转交和附件；入口为工单/客户/服务，返回原列表。
- 桌面：页头编号/标题/状态；左 2/3 时间线与回复编辑器，右 1/3 客户/服务、部门/处理人、处理动作及通知摘要。内部备注有独立背景与“仅管理员可见”。
- 页内视图：公开对话、内部备注、处理选项、附件；回复预设先插入草稿，再由管理员发送，不能点选即发送。
- API：共享 `GET /tickets/{id}`、`POST .../replies`、`PATCH /tickets/{id}`；固定后台身份使用[认证契约](api.md#共同协议)的 admin portal，不回退客户 Cookie。另有 `POST /admin/tickets/{id}/receive`、`/transfer`、`/notes` 与 `POST /admin/tickets/merge`。
- 权限：读 `tickets.view`，处理 `tickets.manage`，同时重核部门/客户；读取预设另需 `ticket_presets.view`。部门/人员候选以实际接口授权结果为准。
- 处理：接单、改分配、转交原因、合并同客户工单分别确认；合并保留来源与跳转，不给任意客户工单提供强制合并。关闭和 resolved 的含义不混用。
- 回复：公开发送前明确接收方；`POST .../replies` 使用原工单的 `version` 与原 `idempotency_key` 恢复未知，不取回复版本或改传expected_version，409保留正文。成功重新读时间线和摘要；内部备注、关闭/转交不冒充现有三种公开通知触发。
- 附件：`POST/GET/DELETE /tickets/{id}/attachments...` 使用授权接口；历史初始/回复/内部备注父关系仅按返回事实展示，内部附件不可出现在客户视图。当前上传只接file并创建根附件，不提供reply_id/note_id绑定或内部备注附件上传；不能将内部文件误传为客户可见根附件。未知上传先查原key回执，下载失败局部重试。
- 评分：只读呈现每条合格管理员公开回复及管理员初始内容的1–5星、来源/未评分；客户通过 `POST /tickets/{id}/ratings` 每对象只能首次评分，后台不代评、不改分，不对整单造总评分。
- 历史：unknown作者、客户消息、内部备注与合并来源不可新评分；历史评分不因当前处理人变化重写。统计边界见[处理人与评分](../report-restoration-contract.md#工单处理人与评分)。
- 手机：摘要→对话→编辑器，处理选项用独立折叠区，发送和内部备注按钮必须文字区分；长附件名与URL换行。

### 工单附件的待确认交互

- 首次上传前保存actor、工单、8–128字符key及文件名/MIME/大小/SHA-256；所有共享上传和恢复请求带后台portal。刷新后不保存文件字节或承诺浏览器仍持有原文件。
- 断网、5xx及明确未知错误先 `GET /tickets/{id}/attachment-upload`，key在请求头；confirmed核对原附件信息，展示“上传曾确认”并刷新附件列表，不能以列表中同名/同hash推定为本次成功。
- unconfirmed显示“已登记意图，结果待人工核验”，禁用重传/换key；同key上传会被 `attachment_upload_unconfirmed` 拒绝。404同样不证明可安全重传，先核对当前身份、工单及原key。
- 413/415等预约前确定错误可修正文件再发新意图；预约后外部Put、审计/事务或进程问题不能自动重试。confirmed不保证文件现在仍可下载，删除、归属与存储可用性继续由授权下载判断。
- 该协议已具备API但当前UI未接入，实施必须依据[上传恢复契约](api.md#工单附件上传恢复)，验收独立覆盖创建成功/附件未知、刷新恢复、撤权与文件已删。

### `/admin/ticket-departments`：部门

- 目标：管理可接收工单的部门；入口为客服设置，编辑在本页 Dialog，成功回列表。
- 桌面：部门名、启用、客户可见、排序/版本与操作表；编辑包含名称、创建时标识及当前 API 支持的布尔和排序字段，不添加旧版尚不支持的准入策略。
- API：`GET /admin/ticket-departments` 为 `tickets.view`；`POST`、`PATCH /{id}`、`DELETE /{id}` 仅超级管理员。
- 组件：状态徽标、表单 Dialog、可见性说明、删除确认；隐藏/停用对客户历史读取的影响必须在确认中说明。
- 交互：成功刷新目录；版本409保留草稿；旧无回执写入未知仅刷新核对，不承诺换key重放安全。删除被引用阻断显示后端原因。
- 手机：表单单列，客户可见与启用分开标注，不用同一个开关表达两种状态。

### `/admin/ticket-statuses`：工单状态目录

- 目标：管理状态展示定义；从客服设置进入，不把自定义显示目录当作任意业务状态机。
- 桌面：标识、标题、排序、内置、启用、操作；弹窗表单为当前 API 对应的 slug/title/sort_order/active。
- API：`GET/POST /admin/ticket-statuses`、`PATCH/DELETE .../{id}`；读 `tickets.view`，写 `tickets.manage`。
- 组件：分页表、内置锁定徽标、状态编辑弹窗；内置不可重命名或删除提示，内置标题只读，不提供绕过选项。
- 交互：按 API 版本/key提交，409保留草稿；成功刷新目录与相关选择器。未知结果只按该端点已有恢复保证处理。
- 手机：列表改为状态卡片，弹窗单列且键盘聚焦正确。

### `/admin/ticket-rules`：工单传递规则

- 目标：维护实际支持的部门/商品条件、屏蔽词和自动回复；不扩展为任意工作流编排。
- 桌面：规则编号、部门、商品、屏蔽词摘要、启用、操作；编辑分条件、屏蔽词、回复正文、启停四区。
- API：`GET/POST /admin/ticket-rules`、`PATCH/DELETE .../{id}`；`tickets.view/manage`，分页、版本及key沿端点协议。
- 组件：受限关系选择/编号说明、关键词 token 输入、Textarea、启用 Checkbox、删除确认。
- 交互：空条件的“全部”含义明确；失败保留规则草稿，409提供刷新核对，成功只刷新受影响列表。自动回复文本按文本安全渲染，不执行HTML。
- 手机：条件与关键词单列；较长回复在详情展开，不能撑宽列表。

### `/admin/ticket-presets`：预设回复

- 目标：维护客服复用文字，入口为客服设置；分类/回复编辑保留本页选择。
- 桌面：左侧分类导航，右侧预设列表；主列标题、分类、排序/启停、正文摘要、操作；编辑表单先标题/分类，再正文与实际支持的设置。
- API：`GET/POST /admin/ticket-reply-preset-categories`、`GET/POST /admin/ticket-reply-presets` 及相应 `PATCH/DELETE /{id}`；`ticket_presets.view/manage`。
- 组件：分类树或列表、搜索（仅已有API支持时）、正文编辑、预览、确认弹窗；不在客户端分页后假称全库搜索。
- 交互：分类删除影响以服务端校验为准，成功刷新两区；回复插入工单草稿不直接外发。端点无统一回执时未知操作先读取核对，不能套金融恢复承诺。
- 手机：分类和回复列表改卡片并上下排列；编辑使用单列弹窗，回复分类在表单内下拉选择，取消更改只恢复草稿，不发写入。

工单部门和预设回复目录已接公共列表与手机卡片；预设分类/回复区域分别加载和重试，编辑在模板Dialog内，完整回复以纯文本展开。部门写入仅超级管理员；预设写入沿用`ticket_presets.manage`。两个目录接口返回完整数组，本批不增加分页、搜索或回执协议。

## 通知渠道与营销

### `/admin/notifications`：统一通知工作台

- 目标：管理业务通知的路由、模板与投递；三个上层标签为统一通知中心、邮件/短信模板、邮件/短信兼容队列。
- 桌面：统一中心再分规则/模板/投递/渠道；事件选择器先限定业务事件，再显示各渠道配置。规则卡显示启用、实例和模板；投递表为事件/客户、渠道、状态、尝试、时间与脱敏结果。
- 渠道：邮件、短信、站内信、Telegram、Web Push统一展示实际能力与路由来源；旧链/新链清楚标记，不把旧工单邮件及营销活动伪装成已接全部机器人。
- API：`GET /admin/notification-center`、`GET /admin/notification-deliveries/page`；`PATCH .../rules/{id}`、`.../templates/{id}`；读取 `notifications.view`、修改 `notifications.manage`。Webhook配置另需 `settings.manage`。
- 模板/旧队列：`GET /admin/notification-templates/page`、`GET /admin/email-outbox`、`/sms-outbox`；旧队列 `/retry` 只对端点允许记录开放，不能为统一中心 unknown 造重发API。
- 组件：事件 Select、路由卡、模板变量帮助、版本冲突卡、渠道能力 Badge、投递分页表、旧队列状态说明。
- 交互：事件切换保留各自草稿，保存逐规则/模板完成；409重新加载版本并保留草稿待核对。accepted仅平台接受，unknown停止自动重发，skipped不是业务失败。
- Web Push：正文固定为通用提示，只能启停；不能输出业务变量。本人浏览器订阅、Telegram绑定与主动偏好在账户页完成，后台不能代绑或显示chat ID、endpoint、密钥。
- 手机：二级标签均可局部横滑，规则与模板单列；结果码/实例长标识换行，未授权字段不下载到客户端。
- 边界：详见[通知架构](../notification-architecture.md)及[工单通知](../ticket-notification-contract.md)；通知日志是投递记录，不等于本人的站内收件箱。

### `/admin/notifications/new`：邮件/短信兼容模板新增

- 目标：新增已支持用途的邮件/短信模板，入口为模板列表；成功返回原渠道/筛选，取消保留来源。
- 桌面：顶部渠道/用途/名称，中部邮件主题与正文或短信正文/提供方模板标识，下方变量帮助、启用和保存/取消。
- API：`POST /admin/notification-templates`；读取界面 `notifications.view`，新增 `notifications.manage`，写入按真实模板版本/key协议。
- 组件：渠道与用途 Select、Input、Textarea、变量说明、离开确认；不提供“新建任意机器人事件”字段。
- 交互：校验用途变量与必填；成功刷新模板目录；未知提交按该端点恢复，409保留输入。验证码模板与业务广播用途分离。
- 手机：单列正文区，变量帮助折叠；不能自动把现有模板正文带入营销受众发送。

### `/admin/channels`：编译渠道目录与实例配置

- 目标：为已编译实现配置实例；入口为接口设置或应用详情，允许 `category/return_to` 保留来源。
- 桌面：支付、邮件、短信、登录、机器人、浏览器推送、实名、开通分类；表列实现/实例名称、标识、能力、版本、配置状态/启用、操作。
- API：`GET /admin/channel-catalogue`、`GET/POST /admin/channel-instances`、`PUT/DELETE .../{id}`；仅超级管理员。实现缺失/工厂缺失/schema不兼容分别提示。
- 组件：元数据生成表单、能力徽标、私密字段只写输入、已配置标记、清除秘密确认、实例复制、测试结果卡。
- 交互：不展示密钥原文；留空保留与显式清除区分，复制实例不复制秘密并默认停用。配置有效不等于网络连接成功，启用不等于用户已绑定/订阅。
- 测试：邮件/短信使用已有 `/admin/smtp-settings/test`、`/admin/sms-settings/test`，明确测试接收者、费用及“已入队”；不臆造机器人通用测试 API。Telegram回调需部署HTTPS条件。
- 版本：PUT/DELETE使用实例version，409保留草稿刷新核对；没有回执保证的实例写入遇未知先读目录，不能声称无限自动重放。供应商/NOKVM去专属配置入口。
- 手机：分类可横滑、实例卡片化、秘密输入全宽；不提供运行时上传二进制或动态安装代码。

### `/admin/marketing`：营销活动与发送

- 目标：显式选择受众、保存草稿并确认发送；列表/新建/编辑/只读详情是本页状态，返回保留列表。
- 桌面：列表状态筛选+创建，列活动标题、受众模式、渠道、状态、人数、创建人、更新时间；编辑分消息内容、受众条件、人数预览、保存及发送四区。
- 表单：现有渠道仅email/sms/inbox；按客户或商品选择实际支持的状态、销售、语言、地区、验证/绑定、商品/主机状态条件，不自动把Telegram/Web Push加入营销。
- API：`GET /admin/marketing/options`、`GET /admin/marketing[/{id}]`、`POST .../audience-count`；读 `notifications.view`；`POST /admin/marketing`、`PATCH /{id}`、`POST /{id}/send` 需 `notifications.manage`。
- 组件：受众条件表单、商品多选、内容Textarea、人数预览、草稿状态徽标、发送确认Dialog、投递入口。
- 交互：改受众后人数标为过期，预览不发消息；保存不发送。发送前列活动/渠道/受众条件/人数与不可任意撤回说明，queued不显示已送达。
- 恢复：编辑/发送使用原版本和稳定key；未知保留原请求并查询活动状态，409保留草稿待核对；不能换key重发整批。成功刷新活动与发送状态。
- 手机：受众筛选分组折叠、预览人数和发送确认常可见；长正文安全显示，营销日志与事务/工单通知分开。

## `/admin/reports`：六类报表

入口为报表导航、工作台及客户/销售相关跳转；六类在同页标签切换，用 `tab` 保留视图，所有读取需 `reports.view` 及当前客户范围。具体指标、金额和期间以[报表恢复](../report-restoration-contract.md)与[统计口径](../credit-cash-reporting.md)为准。

桌面公共顺序为标题/期间查询、六标签、口径说明、指标卡、趋势、明细/分页；查询草稿不改变已展示期间，点击查询才请求。当前标签独立挂载/加载/错误/重试；人员目录或费用加载失败不遮蔽其他报表。手机标签局部滚动、指标卡单列，图有可读表格替代，无导出按钮。

### 收入：年度现金与业务消费

- 现金布局：年份、上年比较开关/图例；收入/外退/人工费用/现金净额卡；12个月趋势及月表；下方费用台账。收入来源区分网关、人工线下与兼容历史还款，模拟与待核验异常单列。
- API：`GET /admin/reports/annual-cash?year=`；费用 `GET/POST /admin/reports/expenses`、`POST /expenses/{id}/void`。费用读要求全部客户范围，写另需 `finance.manage`。
- 费用表单：发生日、类别、来源、金额、凭据及说明；撤销需原因，追加事实不修改原记录。保存绑定稳定key，未知恢复原请求，409保留草稿；成功刷新台账和年度现金。
- 口径：外部到账含充值，余额消费不能再加一次；实际外退按发生月，费用撤销重述原发生月；净额不是经营利润。无全局费用权限时费用/总支出/净额为null并显示无权限。
- 业务消费子视图：`GET /admin/reports/income?year=`，卡片全年业务消费/全年去重账单数与12月表；余额消费包含、充值排除，年度账单数不可累加月数。只读查询不生成财务事实。

### 客户：全历史余额流水排名

- 布局：明显“全历史余额流水·前十名”，不显示不适用的年月；表列排名、客户、钱包收入/支出/净额，金额名称注明余额账本口径。
- API：`GET /admin/reports/customer-ranking`；只展示有符合口径流水的客户，空数组为“暂无流水”。没有客户读取权限不提供客户详情链接。
- 交互：刷新只刷新该排行；切年不产生假筛选，保留返回来源。钱包排名不称外部现金、净销售额或利润。

### 产品：分类收入与数量

- 布局：年月+独立商品分类/产品筛选；完整筛选合计；分类组分页表，展开组内商品；新购/续费金额、服务/项目件数及订单/账单数并列。
- API：`GET /admin/reports/product-income/groups`；商品分类是 `product_categories`，不以服务导航组替代。分页total含义、汇总和展开依响应，不只汇总当前页。
- 口径：金额折后稳定分摊，数量“件”和“单”分开；跨产品单数不可直接相加，退款独立进现金，不把成交额称扣退净收入。未分组、停用和历史名称可辨。
- 交互：筛选回第一页并收起失效展开；慢请求不能覆盖新年月。展开加载失败只重试该区域，手机保留金额/件数/单数而用表格容器滚动。

### 每日运营

- 布局：年月、新客户合计；每日表列日期、新客户、新订单、已付订单、新工单、工单回复和兼容取消事实，按上海自然日补齐序列。
- API：`GET /admin/reports/new-clients?year=&month=`。无 `tickets.view` 或 `ticket_metrics_available=false`，工单字段null显示无权限，其余业务继续展示；不能渲染为0。
- 交互：空/零按真实日序列显示，接口失败仅当前分区错误；兼容取消计数不是重新开启客户退款/停用申请。手机日期/主要数量固定可读。

### 我的业绩

- 布局：当前期间/对比期间、快捷日周月/自定日期；授权人员、客户、产品、业务类型和账单号筛选；趋势与汇总；按账单分页，展开真实业务项目。
- API：`GET /admin/reports/sales/options`、`GET /admin/reports/sales/details`；选项仅授权销售，未分配单列，不拉完整员工目录代替。参数遵照接口，不根据页面文案猜字段。
- 主列：客户、产品摘要、账单、业务金额、到账时间、预计提成、历史确认及冲正；子项显示历史名称、净额/折扣和归属。完整筛选汇总与当前页明确区分。
- 口径：预计按当前规则并返回规则/时间依据，未配置用文字；历史确认按原快照，二者不相加、不称已发放。正式确认续费/升级仍不在本页产生。
- 交互：人员目录独立重试；筛选回第一页；展开不触发佣金写入。手机筛选折叠、对比标签有文字图例、账单展开保留金额和状态。

### 工单统计

- 布局：处理人与评分、每日创建/当前待处理两个子视图；默认上海月，处理人视图允许实际支持日期/处理人/排序/分页。
- API：`GET /admin/reports/tickets/handlers`、`GET /admin/reports/tickets`；还需 `tickets.view` 与当前部门范围。无权限显示明确说明，不请求假空数组。
- 主列：处理人、分配量、当前关闭量、已评消息数、总分、1–5星次数；每日表保留合并来源创建量，待处理排除来源，closed不冒充resolved。
- 口径：期间创建工单按当前处理人分组，转交后历史分配数可变；评分取期间创建的管理员公开消息及原作者，不按评分提交日。未评分、未知作者不填0星或5星。
- 交互：排序/筛选/页码写URL，分页只影响明细；点击作者不越权泄露人员资料。手机长表局部滚动，评分分布有星级文字，统计页无代评分入口。

## 实施与验收交付

开发时逐页记录 `设计已确认 / 已接线 / 浏览器已验收 / 未验证`，不能把本文或API实现状态算作UI完成。每个页面需覆盖正常、加载、全空/筛选空、错误重试、只读/撤权、409、未知写入恢复、返回恢复和320/390/768/1024/1440px布局；不适用场景标N/A并说明。

财务必须另验金额来源、重复提交与跨权限恢复；工单必须另验内部内容保密、附件未知、消息评分一次；通知必须另验accepted/unknown/skipped及旧链差异；报表必须另验null权限、期间与汇总分离。浏览器、隔离数据库和真实渠道分别记录，模拟收件不等于厂商实收。验收按[领域矩阵](../architecture/contract-verification-matrix.md)关联稳定契约与证据，机器输出放 `output/`。
