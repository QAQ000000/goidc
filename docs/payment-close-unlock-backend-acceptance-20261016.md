# 可信关单与安全解锁后端验收（2026-10-16）

## 本批结果

实现可选 `payment.CloseGateway`、管理员可信关单 API、不可变证据与迟到收款异常事实。只有适配器明确确认原支付最终关闭时才置为 `closed`；账单仍为 `unpaid`，原支付与凭据快照保留。当前仅模拟支付提供该能力，真实易支付/MPAY 没有最终关单协议，明确返回不支持，不能解除保护。

新增迁移：`150_payment_close_unlock.sql`。所有数据库测试只使用本机独立 PG18 测试实例，未应用到运行业务库。

## 已覆盖的协议与安全边界

- 浏览器会话认证、独立 `payments.close` 加 `invoices.view` 权限；既有角色不隐式扩权；请求前后复核权限、员工状态、会话和销售客户范围。
- 带版本与幂等键的预约，网络调用在事务外；同键同参重放、异参冲突，8 路并发预约至多一个活动操作。
- 回调成功优先；金额/操作号/租约/状态/版本不匹配与审计失败不解锁；原实例与凭据密文摘要绑定操作记录。
- 未付款查询、本地过期、真实易支付未支持关单、查询占用、超时或未知结果都不算关闭；未知结果不能换键重新发送。
- 关闭后迟到成功产生不可变待核验资金事实，重复事件不重复记录或入账；冻结新付款、余额/信用结算、账单变更/合并/取消、订单/流量包/充值取消和订单软删除。
- 已接纳充值可信关闭后可复用原接纳快照和预留额度再次付款，或取消释放预留；不按新政策重验，不重复预留。
- GET 状态接口返回最近 50 条操作及异常和各自总数，不返回密钥、请求幂等键或凭据摘要；认证失败同样禁止缓存。
