## 架构选择

- 先采用领域化模块单体；标准库 HTTP 路由和 pgx，业务跨表事务集中在 store 层。不要把一次重写拆成不可验证的微服务网络。
- API `/api/v1` 为新接口契约；旧 `/v1`、后台动态路由和上游 API 需要显式兼容映射后才能承诺兼容。
- 登录使用随机 256 位令牌，数据库只存哈希，HttpOnly / SameSite Cookie，登出即时撤销，每次请求检查账户状态、角色和当前业务权限。Go 不接管 HTML 页面。
- Next.js 同源代理 `/api/*` 到 Go，避免在浏览器暴露数据库配置或将会话保存在 localStorage。写请求要求自定义请求头及来源校验。
- 金额用整数分（CNY）与数据库 CHECK 约束；多币种/汇率/税费后续建立独立金额契约，不能通过浮点换算模拟。
- 购物车项目以稳定 ID 识别；版本、明确选择和幂等键必须校验，不能保留旧 `pos[]` 无有效选择时结算全部购物车的回退。
- 商品、库存、订单项目、账单及审计原子写入；外部资源与支付请求不能放在持有数据库行锁的事务内。
