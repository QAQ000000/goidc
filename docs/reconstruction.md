# 项目状态与开发入口

本项目以 Go API、Next.js/React 和 PostgreSQL 18 重构旧 PHP IDC 财务系统。
核心经营链路已实现，仍处于开发和验收阶段，不能据此停用旧 PHP 生产站。

## 当前状态

- 业务：商品/配置、购物车、订单、余额与在线支付、服务交付、续费/变更/取消、工单、文件、通知、信用及返佣。
- 后台：105 项旧版能力映射中，43 项完成、62 项部分完成。登记不等于全量浏览器或生产验收。
- 数据库：迁移按完整文件名及 checksum 管理；当前有 171 个 SQL 文件，最大编号 170，存在历史重复前缀。
- 通知：Telegram 私聊与本人站内收件箱共用 11 类订单、付款、服务和提醒事件，按事件路由及用户显式订阅范围投递，见[通知契约](notification-architecture.md)。旧付款订阅不自动扩展，邮件、短信保持原队列和模板；当前没有公网 HTTPS 地址，Telegram 真实回调与消息收发未验收。
- 发布：已有隔离候选构建、启动、切换及部分恢复证据；正式 HTTPS、真实渠道、业务快照和容量仍需验收。
- 运行状态必须现场核验；文档中的历史 schema、BUILD_ID 和 active 不能当作当前运行状态。

## 开发约束

- Go 提供 JSON API，Next.js 负责页面，PG18 是业务数据库。
- 资金使用整数分；写入维护事务、权限范围、幂等、版本冲突及审计。
- 外部写结果未知时停止自动重发，沿用待核验状态和独立复核。
- 适配器编译进 Go 二进制，数据库保存实例配置和加密密钥；不动态执行上传插件。
- 旧 PHP 与 MySQL 仅作参考。历史导入工具保留，但旧数据演练不作为所有开发批次的前置条件。
- 不开发评论、评价等社交互动。
- 只在独立测试库验证；构建不能覆盖正在运行的 Web 目录。
