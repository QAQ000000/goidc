# 易支付关单与退款人工操作手册

本站易支付适配器接入创建付款、验签通知和标准 V1 查单，没有可信的自动关单或原路退款能力。迁移150提供按适配器能力执行的可信关单流程，目前只有模拟渠道实现，不能用于解锁真实易支付单。查询失败、未付款和本地过期不能代替商户关单；外部支付成功的账单禁止退入本站余额。

## 核对资料

财务在有权限的账单详情中收集客户、账单号、付款号、金额（数据库单位为分）、原商户流水、创建/付款时间和查询历史。使用支付单对应的原商户，不能用轮换后的商户查旧单。记录操作人、复核人、工单号与脱敏凭证；密钥、签名链接、Cookie 和完整 DSN 不进入共享日志。

## 未付或过期单

1. 在原商户后台按付款号、商户流水核对金额和实际收款。标准查单可用时查询；404、超时或未知结果保持待核对状态。
2. 实际已收款时让商户重发真实签名通知，或使用本站已验证兼容的主动查单补结算。人工补单只证明人工操作，不能证明收款；禁止 SQL 改状态或构造成功通知。
3. 需要关单时，由财务使用商户明确支持的关闭操作，取得最终关闭且不能再支付的可信证据。关闭浏览器、删除记录、QR 过期或查到未付不满足该条件。
4. 商户没有可信关闭操作时，保留本站 pending/expired 支付单和账单付款限制，联系商户人工处理。本站不提供人工勾选关单的入口；即使商户人工确认关闭，也不能绕过适配器可信结果校验，禁止 SQL 改为失败/取消或删单绕过。
5. 部署包含迁移150的一致版本后，仅当账单页面按实际能力及权限显示“可信关单”时，拥有 `invoices.view` 和独立 `payments.close` 权限的员工可读取最新事实、核对金额并确认请求。渠道必须返回匹配原支付号、金额和操作号的最终关闭结果，才解除该支付的保护；历史记录保留。现有角色不会自动获得关单权限。
6. 超时、未知或回执丢失时保留原请求；刷新不会重新发送或换键。使用“以原请求核实关单结果”读取原回执，不重复调用渠道。`checking/unknown` 持续冻结，当前没有人工解除入口。已关闭后出现迟到收款，页面显示异常并继续冻结，应按原商户流水核对，不能再付款、取消或删除掩盖异常。
7. 充值原支付全部可信关闭、且无收款结算及异常时，可按原接纳快照重新付款或取消并释放预留额度。若仍有未关闭支付、未知关单或迟到收款，继续保留保护。此能力不代表当前易支付商户已支持可信关单。

尚未可信关闭的旧单仍可由迟到有效通知结算；已可信关闭的旧单出现迟到收款只记录不可变异常，不重复结算。核对期间不能改金额、更换支付方式或用余额重新付款，以免双重收款。详见[可信关单契约](payment-close-unlock-contract-20261016.md)。

## 外部支付退款

1. 核验原收款、应退金额和原因，检查发票申请、资源交付与佣金影响，取得业务批准和独立财务复核。
2. 商户后台有真实退付能力时，由财务执行原渠道人工退款。没有该能力时联系商户安排人工退付并记录资金路径；人工转账不能称作原路退款。
3. 商户显示受理/成功只作为过程证据。核验商户账务流水和付款人实际到账，再登记金额、时间、退款流水、操作人与复核人。结果未知时先核对，不盲目重试。
4. 已实现后台账单详情的“外部退款登记与复核”，须部署包含迁移143和149的一致版本后使用。支持无订单、资源、信用、升级/续费/流量/佣金等关联的普通人工账单，以及原结算直接入账的在线充值整单外部退款。原结算待补账的充值（包括后来已补入余额）暂不支持；其他业务在独立工单/财务台账跟踪，不调用余额退款抵消或 SQL 改状态。
5. 登记人选择原成功付款、资金路径，填写退款流水、实际到账时间、受控凭证引用及 SHA-256 和说明。登记不会出款或增加余额；充值登记会冻结等额可用余额，余额不足拒绝。其他具备独立复核权限的员工核实原收款与付款人到账后确认，或驳回补正；禁止自审，未知结果不确认。充值确认原子扣减余额并写负向冲正流水，驳回释放冻结；原充值和原支付保留。
6. 确认后账单 refunded，原支付仍 succeeded、原 paid_at 保留；交易流水独立展示原收入和退款支出，网关汇总展示净额。只有确认的记录计支出，重复提交/原成功通知不会再退款或入余额。退款流水绑定原商户身份去重，缺少可用历史商户快照的易支付单拒绝登记和确认，不改用当前商户配置猜测。

权限为 `external_refunds.view/create/review`，默认不授予既有员工角色。UI 配置依赖账单查看与退款查看权限；写接口只接受浏览器会话，事务内重验权限、客户范围、会话、版本和幂等键。回执未知须保留原键及原载荷核实，409须显式读取最新事实，不自动换版本。凭证引用和摘要仅为核对资料，系统不会因填写摘要就自动认定真实到账。[冲正契约](external-refund-reversal-contract-20261016.md) 的复杂订单、部分退款及自动原路退款仍待后续批次。

旧 SDK 的 POST /api.php?act=refund 只有 pid/key/trade_no/money，缺少商户退款号、幂等保证和退款结果查询，受理成功不能证明实际到账。本轮 MPAY 路由没有可信的标准关单/原路退款契约，不调用旧接口试探资金操作。

指定商户为同机 http://127.0.0.1:82（PID 1000），真实扫码付款和异步通知通过，标准查单返回 404。同机 localhost HTTP 回调不代表公网 HTTPS 可达。详见 [真实支付验收](real-payment-acceptance-20261013.md)。
