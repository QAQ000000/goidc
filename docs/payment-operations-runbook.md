# 易支付关单与退款人工操作手册

本站仅接入创建付款、验签通知和标准 V1 查单，没有可信的自动关单或原路退款能力。查询失败、未付款和本地过期不能代替商户关单；外部支付成功的账单禁止退入本站余额。

## 核对资料

财务在有权限的账单详情中收集客户、账单号、付款号、金额（数据库单位为分）、原商户流水、创建/付款时间和查询历史。使用支付单对应的原商户，不能用轮换后的商户查旧单。记录操作人、复核人、工单号与脱敏凭证；密钥、签名链接、Cookie 和完整 DSN 不进入共享日志。

## 未付或过期单

1. 在原商户后台按付款号、商户流水核对金额和实际收款。标准查单可用时查询；404、超时或未知结果保持待核对状态。
2. 实际已收款时让商户重发真实签名通知，或使用本站已验证兼容的主动查单补结算。人工补单只证明人工操作，不能证明收款；禁止 SQL 改状态或构造成功通知。
3. 需要关单时，由财务使用商户明确支持的关闭操作，取得最终关闭且不能再支付的可信证据。关闭浏览器、删除记录、QR 过期或查到未付不满足该条件。
4. 商户没有可信关闭操作时，保留本站 pending/expired 支付单和账单付款限制，联系商户人工处理。本站也暂没有登记人工关单并安全解锁的入口；即使商户确认关闭，仍需补齐可审计、防迟到通知竞争的正式流程后再解除限制，禁止 SQL 改为失败/取消或删单绕过。

迟到的有效通知仍可结算旧单。核对期间不能改金额、更换支付方式或用余额重新付款，以免双重收款。

## 外部支付退款

1. 核验原收款、应退金额和原因，检查发票申请、资源交付与佣金影响，取得业务批准和独立财务复核。
2. 商户后台有真实退付能力时，由财务执行原渠道人工退款。没有该能力时联系商户安排人工退付并记录资金路径；人工转账不能称作原路退款。
3. 商户显示受理/成功只作为过程证据。核验商户账务流水和付款人实际到账，再登记金额、时间、退款流水、操作人与复核人。结果未知时先核对，不盲目重试。
4. 本站暂没有外部退款完成登记入口。资金人工退回后，本站账单仍 paid、支付仍 succeeded；在独立工单/财务台账记录差异并跟踪正式登记功能，不通过 SQL 标记 refunded，不返还本站余额，不调用余额退款抵消。

旧 SDK 的 POST /api.php?act=refund 只有 pid/key/trade_no/money，缺少商户退款号、幂等保证和退款结果查询，受理成功不能证明实际到账。本轮 MPAY 路由没有可信的标准关单/原路退款契约，不调用旧接口试探资金操作。

指定商户为同机 http://127.0.0.1:82（PID 1000），真实扫码付款和异步通知通过，标准查单返回 404。同机 localhost HTTP 回调不代表公网 HTTPS 可达。详见 [真实支付验收](real-payment-acceptance-20261013.md)。
