## 2. 最小资源与配置契约

1. URL 由清单内静态前缀映射为 `/_next/static/<相对路径>`。资源记录至少绑定来源 manifest SHA、来源构建、原路径、URL、长度及 SHA256；生成映射和配置本身也有摘要。只接受普通文件，校验根目录及路径各级没有软链接，不跟随链接或暴露特殊文件。
2. 只生成精确 URL allowlist。同一 URL 同长度、同 SHA256 可合并，保留两个来源；同一 URL 不同字节或元数据不一致立即阻断整个新配置，不按旧/新目录优先级选一个，也不做失败后回源。实际文件缺失、与摘要不符或配置生成失败时，不激活配置。
3. 映射仅暴露已核验的静态记录；包内 manifest、源码、`.env`、密钥、服务端 JS、node_modules、cache、运行器及控制目录均不能通过 HTTP 读取。未知 URL 和目录没有文件系统兜底、目录索引、SPA fallback 或 Web/API upstream。
4. 生成配置必须对 URL、文件路径和所有插值执行适用于 Nginx 的约束或转义；不能把清单字符串原样拼进指令。拒绝控制字符、绝对相对路径混淆、空路径段、点段、反斜杠及可逃逸配置字符串的输入。
5. 请求侧同时约束原始 URI 和最终精确映射。恶意请求在 Nginx 已规范化 `$uri` 后可能失去点段信息，不能只检查 `$uri`。拒绝原始点段、编码点段、编码斜杠/反斜杠、双重编码和控制字符；合法资源名中的方括号等字符需保持一致映射。query 不参与文件选择，不能改变同一资源的返回字节。
6. 只接受 GET、HEAD；其他方法返回 405。有效 GET 返回 200 和完整封存字节；HEAD 返回相同类型、缓存策略和文件长度，响应体为空。JS 使用 `application/javascript` 或 `text/javascript`，CSS 使用 `text/css`，允许明确 charset；设置 `X-Content-Type-Options: nosniff`。禁用 gzip、gzip_static 及其他自动字节替换，客户端使用 identity 取证。
7. 静态成功响应使用明确、固定的 `Cache-Control` 策略；本轮默认 `public, max-age=300, immutable`，并以同一 URL 永不返回不同字节为前提。执行者如调整此值，必须在执行前固定进配置及报告，逐阶段精确验证，不能只检查该 header 存在。未知、非法、方法拒绝等错误响应必须包含 `Cache-Control: no-store`，不能带 immutable 或正向 max-age。304 如支持，必须核对条件请求、实体标识和缓存头，不能拿无响应体的 304 替代 GET 字节验证。
8. 本轮资源集和配置只存在于自有临时运行根目录。执行前记录空间及 inode 预算，不新增完整依赖或大构建。只读映射或独立复制必须有完整摘要核对；不能改候选文件权限、采用可写共享依赖或在常驻目录生成任何构建产物。

## 3. 真实 Nginx 与隔离边界

使用本机真实目标二进制 `/www/server/nginx/sbin/nginx`，记录实际 SHA256、`-V`、运行库检查及需要的 Lua 运行文件摘要。本次只读检查显示版本为 1.30.4，并发现 `/www/server/nginx/lib/lua/resty/core.lua`；不能据此假定独立实例必然可用，需实际 `-t`、启动和请求证明。

- 使用私有 mount 和 net namespace，验证与父进程不同、网络仅有 loopback；原候选、Nginx 和所需系统/Lua 库只读可见，只有自有配置、PID、日志、临时输出路径可写。没有业务库 socket、业务配置、宿主站点目录或外部网络入口。
- 独立指定 `-p`、`-c` 和 `-g`，所有 PID、日志、client/proxy 临时路径都落在新的独占运行根目录；禁止 include 宿主 `nginx.conf`、面板 vhost、WAF 或业务站点配置。Lua 模块如需要搜索路径，只指向核验后的最小现有库，不加载业务 Lua 初始化逻辑。
- 由普通用户运行 Nginx master/worker并绑定私有命名空间的非特权 loopback 端口；控制器记录 UID/GID、进程组、实际 exe/cmdline、master/worker PID、mount/net namespace 和监听。执行前固定运行器提交与文件摘要，不依赖可变 PATH 选择服务程序。
- 配置激活只通过专属实例完成：先检查候选配置，再在自有目录原子替换，核验 master 的 PID、进程启动身份、exe、参数及 namespace 后对该 PID 发 HUP。不得使用 `systemctl reload`、宿主 PID 文件或无明确实例归属的 `nginx -s reload`。检查返回 0 本身不代表已接管，必须观察新 worker 及真实 HTTP 响应。
- Node 只用于控制器、配置生成、请求客户端及证据核验，不作为替代 Nginx 的反向代理。若原生 Nginx 缺依赖或无法安全隔离，本轮标 BLOCKED并记录原因，不能以 Node 夹具 PASS 改写成目标代理 PASS。

## 4. 执行阶段与逐项验收

所有请求在上述私有网络空间内执行；不探测现有 3088、8088 等业务入口。持续请求使用固定旧独有 chunk URL，并逐响应比较完整 SHA256，不能只统计 200。

| 阶段 | 动作 | 必须记录的证据 |
| --- | --- | --- |
| A：前置 | 重新核对双锚点、清单、实际文件、映射、预算、Nginx 来源及隔离能力 | 来源和字节一致；旧220 / 共用58 / 并集382；任何冲突阻断激活 |
| B：旧静态集 | 启动自有 Nginx，仅提供旧220项 | 全220项 GET 200、长度和摘要一致；HEAD正确；旧独有 URL开始持续请求；新独有 URL404/no-store |
| C：并集激活 | 同一监听、同一请求 URL，激活382项配置 | 新worker实际提供并集；全382项 GET/HEAD符合约定；旧持续请求无失败、无错误字节；新独有URL由404变200并等于candidate3封存字节 |
| D：配置恢复 | 恢复自有维护响应或配置generation，静态仍保留382项；重复检查、HUP及真实请求 | 旧220项跨B/C/D始终同字节；新独有URL在C/D均200且等于封存字节；全382项再次通过GET/HEAD；记录新旧worker交接、请求开始/结束与配置接管时间 |
| E：退出 | 停止且只停止自有进程，清理自有临时资源 | master/worker/包装进程正常退出，自有监听消失；两候选前后摘要相同；常驻进程身份及宿主namespace未改变；残留仅为受控证据 |

阶段固定为 `old → union → restored`：资源数为 **220 → 382 → 382**。每个阶段设置可验证的generation响应头，记录实际header名称和值；恢复时可以切回维护响应或配置generation，但静态映射始终保留并集。**不允许因为恢复配置而裁掉新资源；即使本轮从未发送新页面，也执行这一更强规则。** 这轮恢复的是自有代理配置，不是旧Web、数据库或业务状态；后续真实页面切回同样必须保留新旧静态并集及已承诺的保留窗口。

持续请求需覆盖 HUP前、worker交接期间、接管后及恢复期间；报告记录采样频率、响应数量、错误数和摘要不匹配数。这是有界请求观察，不等于任意负载或零丢请求的普遍证明。并集和恢复完成后的全量检查应使用新连接，避免只命中正在排空的旧worker。

必须另有以下反例和协议检查，逐项标记 PASS / FAIL / 未验证，保留状态码和无敏感响应摘要：

- 原始 URI：`../`、`./`、重复分隔符、大小写编码点段、`%2f`、`%5c`、`%25`双重编码、畸形百分号、控制字符，以及静态前缀内外的 `.env`/manifest/服务端文件请求；返回明确4xx/no-store，不能变成页面200、目录内容或其他文件。客户端须用原始 HTTP request-target 或等价保留原路径方式，不能在发送前自动消除点段。
- 精确映射：未知 `.js`、合法文件路径后附加路径、尾斜杠、query变体、方括号路径的正常编码及恶意编码；合法query若接受必须同字节，不接受则固定拒绝，不能选择不同磁盘路径。
- 方法和头：GET、HEAD、POST等非允许方法；成功和错误响应的 MIME、Content-Length、Cache-Control、nosniff、压缩策略及条件请求行为。错误页不泄露本机绝对路径。
- 独立小夹具：同URL不同字节、同URL同字节合并、缺文件、摘要篡改、软链接、特殊文件、路径/配置注入。拒绝发生在新配置激活之前，并证明原活动配置仍可服务旧字节。夹具不能修改任一真实候选。
- 运行归属：master与worker的实际二进制摘要、UID/GID、PID及启动身份；私有mount/net及回环监听；激活/恢复只向自有master发信号；最后自有进程组与监听均消失。常驻服务只读取不敏感的进程身份快照，不读取环境、Cookie、DSN、业务密钥或响应。

验收报告应包含外部锚点、运行器和配置摘要、资源映射清单及摘要、各阶段时间、真实HTTP证据、负例结果、身份/隔离/退出证据、封存输入前后不变及失败清理结果。报告缺失、进程退出未证实、隔离不完整、任何旧URL错误字节或未经许可的路径可读，均不能PASS。不要输出凭据、完整请求头或不必要的宿主配置内容。

## 5. 后续完整双 Web 与公网切换前置

本轮没有证明旧页面实际打开、新页面引用新chunk、两Web的ready、upstream切流、会话连续性、SSR/API代理、worker排空、schema兼容或公网链路。

1. 一个启动声明完整、来源与产物可复核的旧完整候选，以及对应的新完整候选；不能给candidate2临时补env后把它当作已验收旧包。明确两套API/Web端口、真实API rewrite和SSR origin、公开Origin及受控配置，避免共享53088/58088的声明直接造成冲突。
2. 两套独立Web运行目录和可实测的ready探针；在切换前保存真实旧HTML及其全部资源引用，切换后保存真实新HTML，至少命中各自独有chunk并核验字节。旧页打开期间持续请求资源，直到切回后仍可用；不能使用SSR fallback充数。
3. 正式静态保留窗口、缓存TTL、磁盘预算、并集更新和垃圾回收规则；页面切回后继续支持已发出的新旧URL，同名异字节始终阻断。明确旧进程排空及请求交接，不把配置HUP成功当成业务连续性证明。

只有对应后续范围取得明确授权并完成真实请求、恢复和业务不变量核对后，才更新上层G04/G09状态。本契约只允许关闭有精确证据的静态资源保留准备子项。
