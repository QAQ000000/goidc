# 服务操作历史

服务详情新增只读操作历史。客户页面为 `/console/services/{id}`，后台页面为 `/admin/services/{id}`；两端复用同一前端面板。历史只展示服务自身的安全投影，不提供写操作、评价、评论或社交互动。

## API

| 路径 | 权限 |
| --- | --- |
| `GET /api/v1/services/{id}/activity` | 当前客户本人服务 |
| `GET /api/v1/admin/services/{id}/activity` | `services.view`，并通过当前客户范围 |

查询参数为 `limit`（默认 25，1-100）、`offset`（默认 0，最大 1,000,000）、`action`、`category` 和 `status`。分页参数超出范围或筛选值不在显式允许列表时返回 400。响应返回 `total`、`limit`、`offset`、`service_id` 和按实际发生时间倒序的 `items`。

每项包含来源、动作、分类、状态、时间、操作者类型和安全元数据。客户只看到 `你`、`管理员`、`系统`；管理员在适当情况下看到管理员显示名。元数据最多包含审计/任务编号和任务尝试次数。原始审计 payload、供应商地址、凭据、请求/结果/错误字段及加密内容永不返回。

历史由服务实体的显式允许审计动作和服务关联的 provision job 组成。排队审计与同一任务合并，避免时间线重复；未知实体类型的相同数字编号不会匹配服务。任务状态来自任务表，等待人工确认和等待核验会如实保留，不根据接受记录伪造完成事件。客户服务所有权、管理员客户范围、账户状态、会话和 API 密钥在每次请求重新检查；无权或未知服务统一返回 404。

schema077 为审计实体和时间顺序增加索引。读取持有服务行共享锁和管理员客户范围共享锁，并在等待结束后重新检查当前凭据和权限。核验记录的 `not_applied` 显示失败，`applied` 显示已核验，缺少可靠结论时仅显示已记录；核验登记本身不等于操作成功。审计中任务编号只有能确认属于该服务时才返回。

过滤分类包括生命周期、资源操作、配置变更、账务与续费、取消申请。历史覆盖初始/手动交付、生命周期、电源及 NOKVM 资源操作、核验、续费、自动续费、配置/产品/账期变更和取消申请中已存在且能确认关联服务的事件。历史接口只读，不改变服务、任务、余额、资源或审计记录。
