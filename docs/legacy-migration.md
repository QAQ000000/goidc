# 旧数据迁移

## 范围与状态

`cmd/legacy-audit` 对旧 MySQL 做只读盘点。`cmd/legacy-import` 使用只读、可重复读事务提取明确列出的字段，再向 PostgreSQL 导入核心数据。客户记录只读取旧 ThinkCMF 的单向密码哈希（不读取明文）；归档 payload 会剔除 `password` 字段。不会读取支付凭据或 API 令牌，不修改 PHP 文件或 MySQL。

目前仍是迁移演练工具。完整源库有 184 张表，当前读取 30 类核心、商品配置、服务导航、下载资料、邮件模板、客户分组/联系人及工单数据，尚不能据此切换原站点。未向 `zjmfgo_dev` 导入旧数据；管理员迁移复核页面位于 `/admin/migrations`。

## 导入约束

- 默认 `dry_run` 仅输出盘点及输入校验结果。输入校验失败会输出 `apply_validation_error` 并以非零状态退出。默认预检不连接目标 PG，因此不验证其已有归档或 ID 映射。
- `--mode apply` 检查目标 schema，再执行全批次事务；同一 source 使用数据库事务锁。失败撤回本批业务写入，并单独保留失败运行记录。
- 金额使用精确整数分，拒绝精度丢失、溢出、不支持的负值及币种。服务只支持月/季/年/一次性及对应旧别名，其他周期会明确报错，不能静默改为月付。
- 账单项跨客户归属、合成账单负总额、重复商品币种价格均拒绝整个批次；不会把不同客户的数据拼成一张账单。
- `legacy_id_map` 保存客户、商品、订单、账单、账单项、服务、订单项目、合成账单、服务导航分组及有效偏好映射。合成账单使用负旧 ID，避免与原账单 ID 冲突。
- 已归档 source 的任何记录增删改动均拒绝 apply，增量迁移需要另外设计及复核。早期工具产生的不完整归档也可能被拒绝，应使用新的隔离目标重新演练。
- 相同快照重跑复用目标 ID，不覆盖迁移后余额、姓名、账单核验状态或账单项修改。旧目标有完整、匹配归档但缺 ID 映射时，可恢复映射；无法核验的旧目标或失效映射会拒绝导入。
- 历史账单待复核时不能余额支付、创建新支付意图、成功回调结算或退款；历史服务待复核时不能续费、启用自动续费、申请/批准取消、排队资源动作或完成交付。Worker 不会自动续费待复核服务，也不会执行其资源任务。
- 导入不会创建开通任务，不会联系供应商、支付渠道或发送密码重置邮件。管理员复核不会自动开通资源；真实供应商接口仍未接入。
- 快照清单包括所有30个实体，即使为空；旧目标没有清单时必须重新隔离演练。`shd_email_templates` 使用稳定 `legacy_email_<id>` kind，不覆盖既有 `password_reset` 模板；空正文记录报告 `empty_body_disabled`。客户分组和联系人使用旧 ID 身份和源归档，重跑不覆盖现场修改；分组缺失或联系人归属无效只报告并保持业务隔离。下载资料和工单附件需受控旧上传根目录和目标负责人，详见 [旧下载资料迁移](legacy-download-files.md) 与 [旧工单迁移](legacy-tickets.md)。高级配置联动同样保留旧身份和原始字段，规则求值需单独验收。

## 服务导航迁移

schema `040_legacy_service_navigation.sql` 为分组与偏好增加迁移身份，并给偏好增加稳定内部 ID；原 user_id/group_id 主键不变。导航名称上限从 120 扩至旧表的 255 字符，升级保留原显示状态、版本、归属及初始化标记。

源 `nav_group` 名称去除首尾空白，保留排序；固定图标映射识别常见 fa/el-icon/bx 类，空图标为 box，未知类为 box 并报告 `navigation_icon_fallback`。不把源类名作为 HTML/CSS 使用，原值完整归档。商品非零 groupid 有匹配组时转换目标 ID；悬空归属保持未分组并报告，0/空值保持未分组。

源客户有任一 nav_group_user 行时保留初始化状态，包含仅剩已删除组的偏好行；该客户对未记录源分组默认隐藏。无偏好行则保留未初始化，首次访问时显示当时已有分组。有效偏好逐条转换客户和分组 ID，is_show=1 显示、0 隐藏；旧 null 隐藏并报告。缺失客户/分组的行只归档及记录异常。重复客户/组对、无效显示值、无效编号/名称/排序拒绝整个 apply，要求复核源数据。

快照必须明确包含两个导航实体，即使为空；商品 groupid 也进入摘要。旧工具归档不含新字段/实体时拒绝重跑，须新隔离目标演练，不自动向旧目标补写。相同快照重跑恢复有效 ID 映射，但不覆盖迁移后分组名称/图标/版本、商品服务归属、个人显示偏好。已归档目标被删除、映射失效、偏好归属被改或初始化丢失时拒绝重建，要求恢复或人工复核。

导入事务在源批次锁后持有排他目录锁，避免商品管理、下单或客户初始化观察到半导入导航。导航失败会回滚用户、余额流水、商品、偏好、归档和 ID 映射，单独保留失败运行记录。历史服务仍保持待复核，不因导航可访问而释放付款/资源动作限制。

数据库验收覆盖原 039 非空偏好升级与稳定 ID、源 ID 不同于目标 ID、首次/已初始化及孤儿行默认、全字段归档、255 字符和未知图标、重跑后现场修改保护/缺映射恢复、源增删改拒绝、目标删除/错归属拒绝和触发器失败回滚。真实 HTTP API 用隔离导入客户验证隐藏分组仍可分页访问、本人计数及显示保存后重跑保留；真实旧库逐条核对 3 组、12 偏好、27 商品归属。没有新增浏览器交互流程，本批 UI 仅扩大既有名称字段上限；此前导航浏览器验收继续单独记录。

## 商品配置迁移

schema `048_legacy_product_configuration.sql` 在现有配置模型上增加旧配置容器、类型/范围/单位和源身份，新增 `legacy_product_config_groups`、`legacy_product_config_links`、`product_option_prices` 和 `service_option_selections`。旧 `product_config_options` 映射为当前商品的配置组，普通旧子选项映射为组内选项；schema052 对数量组将多个旧区间子项折叠为一个数量选项，并在 `legacy_product_config_option_aliases` 保留每个旧子项到该选项的映射。原始记录进入 `legacy_source_records`，重复显示值使用旧 ID 生成稳定值，避免静默丢失。

schema `049_legacy_product_configuration_links.sql` 增加 `legacy_product_config_option_links`，把旧 `shd_product_config_options_links` 的 `sub_id`、关系类型、条件/结果引用、上游 ID 和完整原始字段保存在对应目标配置组下。最初仅归档；后续已在购物车、优惠码与结算的共享校验中实现同来源离散条件和数量区间条件。多级 `option_type=20` 使用组及选项的原始 `linkage_pid`，解析为目录中的 `parent_group_id` / `parent_option_id`；缺失/错误归属/循环引用拒绝购买。真实源本轮没有多级父引用，非空分支由隔离夹具验证，详见 [商品配置](product-configuration.md)。导入商品仍保持下架，不自动对外销售。

配置价格按子选项保存完整九种账期矩阵，现有月/季/年/一次性购物车、促销和结算逻辑在有矩阵时按当前账期取价，没有矩阵的管理员新建选项继续使用原增减价回退。商品目录、购物车编辑、后台配置页和服务详情 API 返回矩阵、旧选项类型、范围、单位和服务选择；数量/联动等旧语义先保留并标记在字段中，复杂交互仍不能自动放开销售。

## 管理员复核

`GET /api/v1/admin/migrations/runs` 列出导入批次，`GET /api/v1/admin/migrations/reviews` 按 source、entity 和 state 筛选待复核/归档/已恢复记录；limit/offset 控制分页。账单和服务详情为 `GET /api/v1/admin/migrations/reviews/{entity}/{id}`，包含当前状态、旧字段归档、SHA-256 校验、最多 100 项关联异常、恢复业务未满足项和处理记录。entity 为 `invoices` 或 `services`，id 为新系统目标 ID。

普通管理员可查看，提交复核仅接受启用的超级管理员浏览器会话，不接受 API 密钥。写接口为 `POST /api/v1/admin/migrations/reviews/{entity}/{id}`，必须携带 `Idempotency-Key`、当前 version、decision 和 evidence。服务恢复还需 state、recurring_price_cents；已有 Active/Suspended 服务需填写实际 upstream_id，Pending 服务不接受资源标识。幂等重试返回同一决定，版本冲突或不同内容复用幂等键返回 409。

- `archive` 确认保留历史记录，不修改账单支付状态、金额、服务状态或客户余额，继续保留业务操作限制。后续仍可在满足条件后提交新的恢复决定。
- `release` 重新校验归档摘要、目标 ID 映射、客户状态、归属、账期和金额。历史已付/已取消/已退款/软删除/孤儿账单仅可归档，不能通过复核直接获得退款权限。
- 未付账单必须有一致的待支付订单、支持的 host 项目、金额一致且无重复或缺失的服务关联；有抵扣或税费的账单保持隔离。订单下服务必须先复核，并且仍处于待支付状态。
- 旧 Pending 服务按核验后的首次金额、周期金额与账期恢复待支付流程；旧 Active/Suspended 服务登记实际资源标识，分别恢复 active/suspended，保留原到期日，资源交付模式固定为 manual。存在未完成资源任务的服务不能释放。
- 服务恢复时保存核验过的周期金额，并保持自动续费关闭。续费优先使用服务周期金额，其次使用订单项目周期单价，不读取可变的商品默认月价；初装费不再次计入续费。
- 复核版本与决定、处理人、凭据说明、归档摘要和结果在同一事务内保存，并写入审计。失败不会部分释放业务限制或生成开通任务。

已有资源的核验目前是超级管理员提交的人工凭据，不等于 Go 已调用供应商完成自动确认。商品配置、供应商、历史交易与税费迁移仍必须另行完成。

## 命令

连接凭据从本机环境注入，禁止把实际 DSN 放入源码、报告或命令日志。第一次 apply 应使用独立测试库，核对并演练后再讨论业务库切换。

```bash
# 已安全设置 LEGACY_MYSQL_DSN 和旧站 database.authcode 后，仅做源数据预检
export LEGACY_CMF_AUTHCODE='<旧站 app/config/database.php 的 authcode>'
go run ./cmd/legacy-import

# DATABASE_URL 必须指向本次演练的独立 PG 库
go run ./cmd/migrate
go run ./cmd/legacy-import --mode apply --source zjmf-manger-decoded
```

`LEGACY_CMF_AUTHCODE` 只用于验证旧的 `###md5(md5(authcode+password))` 哈希。导入器将
格式有效的哈希以 `legacy_cmf$` 临时前缀存入 `users.password_hash`；客户首次登录
成功后立即生成 bcrypt、清除前缀并关闭 `password_reset_required`。旧哈希不会写入
`legacy_source_records`，也不会回写旧 MySQL。未设置 authcode、哈希缺失或格式无效
时，客户继续使用随机不可知密码并要求验证码重置。
