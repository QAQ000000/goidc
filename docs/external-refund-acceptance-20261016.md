# 外部退款第一增量验收（2026-10-16）

承接[核心替代目标](core-replacement-goal-20261016.md)第二阶段。本批支持普通人工账单整单外部退款的到账登记、独立复核、驳回补正和财务追溯；支付异常阶段及整个替代目标仍未完成。

## 已交付边界

迁移143增加退款事实、操作幂等及数据库约束。只接受无订单、资源、信用、续费、升级、流量、佣金关联及有效发票申请的普通人工账单。所有金额为整数分，必须对应一笔原成功付款的全额。

登记不会执行退款或增加余额。独立员工核实真实到账后确认，才原子写入退款事实、账单 refunded 和审计；原支付 succeeded、原收款流水和 paid_at 保留。不同通知事件重放原成功回调也不再次入账。交易流水及客户历史分别保留原收入和退款支出，现金汇总显示收入、退款、净额；既有收入报表保留原毛收入。

仅有效浏览器会话可写入，事务内重验当前会话、员工权限和客户范围，包括幂等重放。查看、登记、复核分别使用 `external_refunds.view/create/review`，不隐式授予普通角色；禁止申请人自审。API key 不能绕过此流程。具体接口见[HTTP 验收](external-refund-http-acceptance-20261016.md)。

商户退款流水按历史加密支付快照中的规范 API 地址与 PID 去重，跨支付类型和复制实例生效，缺失或不可用快照不能用当前配置猜测。不同域名实际指向同商户的映射仍未解决。驳回不要求继续满足出款资格，避免登记后出现发票申请时卡死；驳回历史不可改，但允许原退款流水以新幂等键补正。pending/confirmed 继续有商户、账单和支付唯一保护。

核心实现与审查提交包含 `ea0d26a`、`500a03c`、`a724158`、`bb22064`、`606c5d6`、`851d99a`、`c0149c4`、`0d58117`，以及最终驳回补正修复 `6c60bfd`。子任务独立分支提交后由主代理审查集成。详细资金约束及专项测试见[store 验收](external-refund-store-acceptance-20261016.md)。
