# PHP 替换准备度与路线图

更新时间：2026-10-09

这份文档把“能编译、隔离测试通过”和“可以替换旧 PHP 生产站点”分开。当前项目仍处于重构阶段，不能切换旧站点，也没有声称生产等价。

## 当前基线

- 旧系统静态清单：`docs/generated/legacy-inventory.json`，1352 条路由调用、184 张表。
- 当前 Go 路由：由 `scripts/route-coverage.mjs` 从 `internal/httpapi/server.go` 生成覆盖索引；方法和路径完全相同时只记为候选，不代表行为兼容。
- 覆盖索引：运行 `node scripts/route-coverage.mjs` 生成到 `output/audit/route-coverage.json`（不跟踪）；封存基线见 [历史审计](archive/README.md)。每条记录仍需核对处理器行为、认证/权限、状态机和 Next 页面契约。
- 验收边界：隔离 PG18、浏览器和 worker 回归只证明对应批次；真实支付、真实上游和正式切换仍需独立证据。
- 运行边界：Go 仅提供 API，Next.js 负责页面；登录/注册/找回密码使用一次性验证码，图形验证码仍可按站点设置启用；不开发评论、评价和其他社交互动。

## P1：核心运营闭环

- 实名、OAuth 和联系人独立登录：短信通知已定义供应商接口、凭据保管、失败/重试和隐私审计，但真实短信供应商仍需沙箱验收。
- 发票与税务：保留当前发票申请和文件模型；接入真实税务服务前不得把 PDF/XML 文件检查写成税务开具成功。
- 计划任务、通知投递和邮件：验证码及渠道实例投递已接通；服务到期 7 天/1 天提醒、未支付订单提醒、逾期账单催缴、支付成功、服务开通和服务暂停邮件/SMS 已加入幂等 outbox，worker 会按 24 小时宽限期为逾期服务入队暂停任务；邮件/SMS 共用指数退避、dead_letter 和管理员人工重试。旧 ThinkCMF 客户哈希可在配置 `LEGACY_CMF_AUTHCODE` 后首次登录升级为 bcrypt，归档不含旧 `password` 字段；真实客户密码、邮件和 SMS 收发仍未验收。
- 插件、返佣、提现：推广返利第一阶段已实现基础模型、验证码注册归因和余额/易支付结算事务内冻结佣金，支持客户概览、链接管理及后台账户/归因查询；规则和账单快照、幂等、权限与并发回滚已有隔离测试。冻结解锁、退款冲正、阶梯代理规则、客户/后台页面、提现和真实支付链路仍待后续批次。设计基线见 [推介返利与分销代理系统设计](affiliate-agent-design.md)，已实现契约见[推广返利基础](affiliate-core.md)。

## P2：非阻断外围能力

- 备份升级的自动化编排、更多历史数据迁移、别名路由和低频后台页面。
- 其他上游系统适配器：复用 `internal/supplier` 的注册表和标准模型，每个适配器单独提供协议、凭据、限流、回放和真实沙箱证据。

## 批次完成定义

每个领域完成前必须同时具备：

1. API、页面和权限契约已记录，包含成功、空、错误、冲突、撤权和移动端状态。
2. 隔离 PG18 测试通过，涉及并发或 worker 的批次追加 race 和恢复测试。
3. 浏览器流程覆盖真实 Next 代理；没有浏览器或真实外部凭据的部分标为“未验证”，不得写成 PASS。
4. 发布前保留迁移、二进制、环境和数据库恢复材料；新增敏感数据后只能做一致性回滚。
5. 文档更新当前 schema、BUILD_ID、服务健康检查和明确的未完成边界。

## 当前执行顺序

1. 生成并逐模块审查覆盖索引，先锁定高价值客户、订单、账单、服务和供应商路径。
2. 建立真实集成前置条件清单，取得测试商户、魔方财务账户、NOKVM 资源以及短信/实名/税务沙箱凭据后再做联调。
3. 先完成真实供应商/NOKVM/支付验收，再做兼容映射和切换演练；没有这些证据不进入生产替换评审。
4. 所有 Go 命令优先使用 `scripts/go.sh`，用 `scripts/check-go-toolchain.sh` 检查版本和 GOROOT，避免本地 Go 与 `/usr/local/btgo` 混用。
