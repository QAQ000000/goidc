# 未知关单独立核验：后端验收记录

日期：2026-10-17。实施契约以 `payment-exception-resolution-contract-20261016.md` 为准。本记录只描述后端实现及隔离数据库证据，浏览器与统一异常工作流验收由主项目记录。

## 实现范围

- 迁移 151 使用追加且不可修改的申请、结果、决策三张表；原关单 `unknown` 和过租约 `checking` 均不改写。原关单员工、核验申请人不能复核自己的操作，超级管理员也不例外。
- 新权限 `payments.close_verify`、`payments.close_review` 同时要求 `invoices.view`。预留请求、保存网络结果和复核分别重新校验员工、角色、会话和客户范围。
- 状态查询仅接受原凭据快照及严格匹配的原操作号、支付号、金额。适配器请求发生在持行锁的事务外。核验不重新发送 Close，不根据本地过期、未付款或管理员输入伪造关闭。
- 确认关闭时，支付终态、账单版本、独立决策及审计同事务提交。确认可信付款时复用正常支付回调结算事务，保留原通知、余额、佣金及开通处理。
- 查询与复核分别具备幂等键。同 key 重放只读取已存事实，不重复调用渠道。原关单重放投影追加的解决回执，但不修改旧事实。
- 复核响应与重放均返回数据库原 `review_note`，便于浏览器核对提交内容。

## 未结算 provider_paid 保护

渠道 Close 返回 `succeeded` 只代表渠道报告付款，本地尚未完成结算。新记录保持 `unknown/provider_paid`，继续阻止再次 Close、余额付款等冲突动作；必须通过可信回调、查单或独立核验结算。

旧实现可能已经保存 `succeeded/provider_paid`，但原支付仍 `pending/expired`。迁移 151 的统一 `payment_close_operation_unresolved` 将这类记录视为待解决，保留原行不改，允许原凭据只读核验。终态 `already_paid`、已真正成功的支付及可信关闭不受此兼容分支影响。所有资金与界面保护共享同一谓词。

## 明确边界

- 易支付/MPAY仍不声明可信 Close 或 LookupClose 能力，返回不支持并继续保护。
- Mock 的可信关闭记录来自已实际执行的本地 Close，绑定 secret、操作号、支付号和金额，受互斥锁保护且最多保留 4096 项。进程重启或缓存缺失返回 unknown，不默认 closed。这是测试适配器，不是生产商户证明。
- 本批没有真实支付商户核验验收，没有部署数据库迁移，没有以本记录替代四尺寸浏览器、全量集成或生产切换验收。

## 只读核验网络中断后的恢复补充

真实 transport error 可以留下无结果的不可变申请。租约有效时，同 key 重放仍只读返回 checking/202；租约过期且始终无结果时，仅只读核验 POST 的同 key 重放返回 `409 close_verification_expired`。它没有把 Close 变成成功或失败，也不生成复核决策。

本人核验回执及本人 GET 列表记录提供 `request_key_sha256`（请求幂等键 UTF-8 字节的 SHA256 小写十六进制摘要）；其他员工不返回该字段。此摘要用于浏览器精确核对原只读请求，绝不是商户凭据摘要。浏览器必须显式重读并核对申请人、摘要、账单、支付、原操作、金额、原版本、过期租约及空结果后，才能归档本地只读等待项。之后新 key 可以重新查询，原申请和原业务冻结不变。此恢复规则不适用于 Close 或复核写操作。

专项覆盖同 key 过期确定错误、列表精确恢复字段、跨员工摘要隐藏、迟到结果拒绝、无结果不可 confirm/reject、原事实仍空、新 key 可查询、再次 Close 和余额付款继续受阻。恢复专项竞态测试结果在本次提交完成前复核。
