# 原生文章分类、标签与排序

迁移 `074_content_taxonomy.sql` 在 schema 073 后新增文章排序、文章和分类多对多关联、标签及文章标签关联。迁移将原有 `content_articles.category_id` 回填到关联表；该字段继续表示主分类，旧 API 只提交 `category_id` 时仍生成单分类关联。没有从旧 PHP 读取或导入数据。本范围不包含评论、文章评价互动、富文本或图片。

## 编辑模型

文章完整保存接受原字段及 `category_ids`、`tag_ids`、`sort_order`。`category_ids` 最多 30 个、不能重复、均为正整数；显式提交时 `category_id` 必须属于数组，未指定主分类时首个分类成为主分类。旧请求省略 `category_ids` 时，新建文章按 `category_id` 建立单分类关联；更新文章时保留原附加分类，主分类按 `category_id` 调整。旧请求省略 `tag_ids` 或 `sort_order` 时保留现有标签或排序。显式空数组表示清空关联，空分类数组须同时传空主分类。`tag_ids` 最多 30 个，不能重复、均为正整数。分类和标签必须存在且与文章类型相同；缺失返回 404，重复或跨类型返回 409。排序整数范围为 0–1000000，新建默认为 0；公开和后台文章列表按排序升序，再按发布时间或更新时间倒序、ID 倒序。排序和关联同文章版本一起原子保存。

新闻和知识库标签各自独立。后台 `GET/POST /api/v1/admin/content-tags`、`PUT/DELETE /api/v1/admin/content-tags/{id}` 复用 `content.view` / `content.manage` 权限。标签字段为 `content_type/name/slug/sort_order/active/expected_version`；名称最多 120 字符，标识遵循文章标识规则。同类型标识唯一。管理列表含版本和所有关联文章数，草稿、归档、未来发布和受限知识库也计入后台数。标签类型不可修改；版本冲突返回 409。有关联文章时不能删除标签，即使标签隐藏。分类的后台关联计数和删除保护同样涵盖主分类与附加分类中的全部文章。

文章、分类和标签写入共用 `contentTx` 的管理锁、内容锁、等待后权限复查。标签保存/删除以及文章关联修改均在同一事务记录审计；审计失败时全部回滚。仅 `content.manage` 且同时具备 `content.view` 的有效管理员可写，只读管理员可查看。管理端支持文章主分类与附加分类选择、标签多选、排序和按分类/标签筛选；标签有独立维护视图。

## 公开可见性

隐藏规则为：文章任一关联分类被隐藏时，整篇文章从公开列表、详情、筛选结果及总数中移除；主分类隐藏也会移除。已发布文章不能保存到隐藏分类。分类后来变为隐藏时，原关联保留，重新显示后文章按其状态、发布时间与访问范围重新出现。隐藏标签仍保留后台关联，但公开文章不显示该标签，公开标签筛选也不会匹配它。

公开 `GET /api/v1/news` 与 `/knowledgebase` 增加 `tag_id` 筛选；`category_id` 匹配主分类或任一附加分类，`0` 表示真正未分类。列表和详情新增 `categories`、`tags`、`sort_order`，其中分类/标签仅来自该访问者实际可读的文章。`GET /api/v1/content-tags?content_type=news|knowledge` 只返回至少关联一篇当前访问者可读文章的启用标签，`article_count` 也仅统计可读文章。公开分类列表只返回至少关联一篇可读文章的启用分类。草稿、归档、未来发布、隐藏分类及权限不足的知识库文章都不贡献公开标签、分类和计数。所有公开查询复用 `publicArticleWhere`，包含发布时间、状态、知识库访问等级及任一隐藏关联分类判定；SEO 代理应复用同一谓词。

详情页显示所有可见分类和启用标签；列表提供分类与标签筛选。公开文章不会返回后台状态、访问等级、作者和版本。评论和文章评价接口未增加。
