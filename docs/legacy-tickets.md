# 旧工单迁移

迁移045覆盖旧 `shd_ticket`、`shd_ticket_reply`、`shd_ticket_note`、`shd_ticket_department`、`shd_ticket_status` 以及工单附件。Go 只读取显式列，迁移事务写入 PostgreSQL，旧 PHP/MySQL 不修改。

旧工单对应目标 `tickets`；旧部门对应 `ticket_departments`；回复和内部备注分别对应 `ticket_replies`、`ticket_notes`。旧状态标题保存在 `legacy_status_label`，原状态映射为：1 开放、2/5 待处理、3 开放、4 关闭。旧优先级 `medium` 映射为 `normal`。旧 `tid` 保存在 `legacy_ticket_no`，目标 `ticket_no` 使用 source 哈希和旧 ID 的稳定值，避免重复旧工单号造成冲突。合并链验证同一客户、无环，并将回复、备注和附件挂到规范工单；合并记录仍显示为关闭。

旧管理员不存在于客户快照中。导入会为每个明确出现的旧管理员创建禁用、无权限、要求重置密码的历史作者账户，使用独立的 `source:staff` 归档身份。它们可以显示为历史回复/附件作者，但不能登录、接单或访问后台。`--file-author-id` 必须是目标启用超级管理员，用于新写入审计和无法还原的旧操作人。

## 部门和可见性

部门名称支持旧表的255字符；隐藏部门导入为 `active=false` 且 `customer_visible=false`。客户列表、详情、回复、工单附件读取和删除都会即时复核部门可见性；管理员仍按实时部门授权处理历史工单。旧 `only_client_open`、产品订单、实名认证和上游关联策略不静默放宽，当前遇到这些策略会拒绝整批并要求先设计兼容契约。

## 附件

旧工单、回复和备注中的逗号分隔文件名会展开成稳定的 `ticket_attachments` 源记录。文件仅从配置的 `public/upload/common/ticket` 目录读取，拒绝根目录、common 或 ticket 子目录符号链接、文件符号链接、越界名、FIFO、非普通文件、空文件和超过10 MiB的文件。文件名优先使用 `^` 后显示名；MIME和危险扩展名共用上传白名单，HTML、脚本、SVG 和可执行扩展拒绝。附件保存 SHA-256、MIME、大小、内容、原作者与 reply/note 父关系；内部备注附件只能管理员读取，客户不能在详情或直接下载接口看到。

导入先读取并记录每个附件指纹，apply 时再次读取和核对；源字节改变会拒绝。源快照、实际文件、目标对象、ID映射、归档、附件和审计一起回滚，失败运行单独保留。删除附件、部门隐藏、客户回复、关闭工单等现场修改在重跑时保留；删除源对应目标或附件、失效映射和源记录变更均拒绝，不恢复已删除授权或内容。

## 验证

隔离夹具覆盖重复旧号、合并链、服务归属、历史作者禁用、正文/回复/备注附件、内部附件保密、客户/管理员下载、部门隐藏、后续回复和关闭重跑、非法状态/归属/联系人/附件路径、字节变化、目标删除及整批回滚。真实旧库只读演练读取到2工单、2回复、0备注和3个附件，隔离 PG18 导入和重跑映射303条；3个附件字节、MIME、SHA、名称和时间逐项核对。

网页生产构建、lint 和 typecheck 通过。隔离 Next.js 预览使用真实导入 API：客户工单列表/详情显示原工单号和导入状态，4个客户可见附件实际展示；客户没有内部备注或内部附件，页面宽度1280无横向溢出。当前 fixture 浏览器环境不使用开发数据库，测试 API 与 Next 预览均已停止，测试 schema 已清理。

迁移仍不覆盖旧工单邮件入单、上游转发、访客工单、联系人身份、自动回复和旧插件通知。完整切换和旧 API 路由兼容仍未完成。
